The preview connects to the host running the code

After an agent changes a web app on another machine, the developer still needs to see what actually runs. VS Code 1.145 lets the integrated browser in the Agents window load pages through the remote agent host. The agent starts its development server, the user opens the page and checks behavior, and feedback returns to the task. This provides something more concrete to inspect than a completion message or terminal output. The feature is a preview behind the remote-browser proxy setting; remote canvases require their additional setting. It improves visibility and navigation, without automatically establishing that the app passes browser tests or meets its design requirements.

Group another opinion without merging permissions

Nested chats can now select an agent harness different from the parent conversation, allowing another agent to review a plan within the same session grouping. Each chat keeps its own model, permissions and history; changing one does not reconfigure the others. A new nested chat starts with blank context, so a person still needs to supply the plan or files to review. Grouping is not automatic knowledge sharing. More subtly, separate conversations do not isolate code changes. Chats using the same folder can modify the same files. Parallel implementation experiments therefore need an explicit separate worktree before their results are compared and merged.

Local recurring work gets an explicit cron schedule

Local automations gain five-field cron schedules for patterns beyond the presets, such as two runs each weekday. The form validates the expression and describes the resulting schedule. Users can select a custom agent from the workspace, while disabled automations are grouped away from active work. Review should include the time zone, model, permissions and an actual first run, not just valid syntax. Documentation says local schedules depend on an awake machine and an available agent process; quitting the application does not imply continued execution. Missed occurrences are not guaranteed to replay individually. Cloud automations do not support this cron option, so the two execution arrangements should remain distinct.

Reduce switching while keeping execution location visible

These changes suit development that alternates between inspecting an app and revising it: run remotely, observe in the current window, then choose another agent or a recurring task when useful. Remote access itself does not copy the workspace or move an existing local session; files and tools remain on the original machine, which must stay reachable. A practical comparison would use the same interface change and measure locating the running page, diagnosing a failure and correcting it, while checking host, worktree and permission confusion. Agreement between models is not independent validation. Downloads cover Windows, macOS and Linux; model access, organization rules and usage charges still depend on the account. No hands-on comparison was performed here.
