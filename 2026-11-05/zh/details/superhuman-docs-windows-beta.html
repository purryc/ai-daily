把文档从浏览器标签中取出来

Superhuman Docs把文档、表格、公式和按钮放在共同工作区，AI可以协助构建和修改这些内容。Windows测试版改变的是进入和持续使用这个工作区的方式：打开多个文档、固定常用标签、从最近文件和全局搜索继续工作，评论与提及进入系统通知。对于整天在项目计划与追踪表之间切换的人，这减少了在网页标签里寻找工作的步骤。它没有改变任务本身，也没有证据表明模型推理转到本机；“桌面应用”应理解为新的客户端入口，不能据此推断离线AI或更强的数据保密承诺。

先申请，再核对自己的入口

11月2日的官方帖子要求填写申请表，并说明会分批放行。因此它是可申请测试，不是已经向每个Windows账户全面开放。旧桌面帮助页仍写Windows尚未来临，内容主要说明七月发布的Mac版；本期依据日期明确的新公告描述Windows测试状态，而不把旧帮助页中的所有细节直接套用。采用前要核对当前账户是否获得访问，以及从聊天或邮件打开文档链接是否回到预期窗口。入口不一致会制造新的查找和账号切换负担，抵消把工作从浏览器分离的便利。

已有AI能力和客户端增量分开

Docs AI的帮助说明已有草拟内容、建立和更新表格、整理数据与处理评论的聊天入口；这不是Windows测试版当天才出现的能力。原有AI列和AI块也继续存在。对团队来说，可以把自然语言需求转成可协作的文档结构，再人工检查字段、公式和生成内容，而无需另把聊天答案搬回表格。测试版发布没有说明这些动作在Windows上的完成率或速度。旧文档还注明AI测试期有不同账户额度和公平使用条件，不能把桌面程序的可申请状态写成AI无限免费。

[S41]

插件习惯可能比独立窗口更重要

公告下实际读取的五条回复里，一名使用Mac客户端的人说自己离不开公式编辑器插件，并质疑浏览器已经能完成同类工作；这是个人经验，不是Windows功能测试。另有读者询问离线与Linux支持，所读回复没有给出承诺。这些问题提示了更具体的选择条件：如果团队主要需要固定文档和及时看到评论，桌面入口可能合适；如果重要工作依赖浏览器扩展或断网编辑，就要先核对支持。可用一项真实文档任务对照原浏览器操作，记录遗漏通知、链接错开和必须返回网页的步骤，再决定是否常驻。
