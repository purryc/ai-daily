Atlassian AMP 把 Agent 的身份、上下文、权限和审计接入团队工作流；OpenAI Decisions API 把下一步判断拆成可调用的 predicate、choice 与 score；femtoAI 则开放 SPU 与压缩工具，试图把本地语音和传感推向更小设备。Microsoft 的本地 AI 活动尚未开始，Torch It 仍是全球弱信号。

  1. 01Atlassian AMP2026-10-06 · developer surface产品价值在于把 Agent 的工作从个人窗口搬回团队共同查看的空间。人类同事可以看到谁触发了 Agent、它访问了什么、改了哪些内容、由谁负责；本地运行的 coding agent 也不再是 Jira 之外的黑盒。对设计、产品和工程团队，交付物、评论、选择和验收条件可以成为 Agent 的上下文，而不是靠复制粘贴重新解释。
  2. 02OpenAI Decisions API2026-10-06 · developer surface这条 API 把许多产品里的‘分类后决定下一步’从长文本生成链里抽出来：图片审核可以输出是否符合规则，路由器可以从固定工具集合选一个动作，工作流可以把输入打分后决定升级、拒绝或交给人工。对 HCI，重要变化是模型判断成为可观察的系统状态，而不是藏在一段自然语言解释里。
  3. 03femtoAI 开放 SPU 开发者社区2026-10-07 · startup signal这条产品信号的重点是把‘端侧 AI 太大、太热、太耗电’转成开发者可以试的工具链。评估套件让产品团队先用目标模型、语音和传感任务评估内存与功耗，再决定是否把 SPU 放进耳机、眼镜、家居或机器人。它不保证产品自动拥有更好的识别率，也不等于一块评估板已经变成可量产的终端。
  4. 04Microsoft Windows / Surface 活动2026-10-07 · weak/unverified本条 scan 的产品信号不是‘微软发布了什么’，而是本地 AI PC 的验收窗口已经被公开预告：应观察模型在哪里运行、离线时能做什么、GPU/NPU/云端如何切换，以及开发者如何知道自己的数据和成本边界。没有现场或官方会后资料前，不记录价格、发售、规格、演示结果或 Windows 新功能。
  5. 05Torch It / Ericsson2026-10-07 · weak/unverified它提供一个具体但尚未闭环的产品方向：把图表和视觉信息转成可听的解释，而不仅是 OCR 读字。对用户，真正关键是读错时能否追问、重复、定位原文、降低信息密度，以及在教室、办公室和街道等噪声环境中不打断用户。当前没有证据证明这些交互已经存在。
