Radar starts cluster investigations from a symptom and puts the verdict beside evidence

Describe the problem before locating the resource

Previously an investigation required a resource kind and name, asking the engineer to know where to look before the investigation began. A request can now contain only a question, or include a namespace, resource and timing clues. Slow checkout can therefore be investigated before a particular Deployment or Pod has been identified. The request uses the same investigation engine and Findings result rather than creating a separate chat mode. Home and search entry points can pass the typed question into that workflow. Radar supplies cluster context for the agent to examine; the description starts the inquiry but does not itself establish a cause.

Sign-in and capacity failures have a next action

The consent surface now checks the local sign-in state of Claude Code or Codex. A definite signed-out result displays the relevant command and a recheck action; an unknown result leaves the existing flow available. Cursor and OpenCode are not covered by this check. Another change handles a fourth request when three investigations are already running. The panel lists active runs in start order, with actions to open or stop one. When capacity becomes available, the original request can continue with its question and target preserved. These changes address the practical obstacles before a useful run, without representing an improvement in the underlying model’s reasoning.

The first visible answer retains its uncertainty

The previous completion card merely announced that an assessment was ready, requiring the reader to open Findings to learn the answer. The assessment label was also more prominent than the verdict itself. The verdict sentence now leads both the result view and the card ending a turn. Its state remains visible: established, suspected, undetermined, healthy or conflicting with captured evidence. If a fix has since been applied or newer reads have overtaken the assessment, the older status is labeled accordingly. Readers can judge whether they have enough information before opening the evidence, without a clearer headline turning an uncertain diagnosis into an established fault.

[S97]

A chart citation must identify the captured observation

The release also corrects a mismatch between a chart identified by Deployment and a citation naming its single Pod. A citation is placed only when the captured chart covers the relevant target Pod; a multi-Pod aggregate cannot stand in for evidence about one member. Ambiguous references retain an explanation. This keeps both findings and ruled-out hypotheses connected to inspectable observations. Execution configuration still matters: Radar’s safeguarded mode can constrain Claude Code and Codex, while the user’s normal agent configuration may retain other tools. Information returned to an AI agent reaches that agent and its model provider. Applying a repair needs approval, and ordinary cluster-management actions have their own permissions.
