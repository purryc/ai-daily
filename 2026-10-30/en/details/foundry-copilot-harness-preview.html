Package the procedure, not another orchestration loop

A team asking an agent to gather evidence, analyze files and deliver a result often first builds context handling, tool coordination and execution machinery. Foundry’s public preview provides that managed loop while developers supply a model, instructions, reusable skills and connected tools. A skill can bundle procedures, scripts and supporting material instead of repeating the entire method in every user request. The option suits teams that want to concentrate engineering effort on their business procedure. It does not decide what a good deliverable is. If the procedure lacks clear inputs, expected artifacts and acceptance conditions, selecting a managed harness leaves those product decisions unresolved.

Select the runtime when creating the agent

In the new Foundry experience, a developer selects the Copilot harness while creating a text agent, configures the model and tools, then saves and tests the active version in a new conversation. Applications continue to call the Responses endpoint. The preview does not support changing the harness after agent creation, so this is an architectural choice to evaluate early, not a switch to assume can be toggled later. Workspaces are separated by conversation, and important outputs belong in durable storage. A product that reuses material across tasks must explain which files are temporary working material and which have become saved artifacts that a person can reliably retrieve again.

Recovery needs application-owned progress

The same announcement calls long-running resilience for hosted agents generally available. That is a separate path from the Copilot harness preview; the two should not be assigned one maturity label. The linked resilience guide still carries a preview title and an earlier update date, so the applicable capability status needs confirmation for procurement. It describes reentry into a handler after process loss, with the application preserving progress and preventing repeated side effects. Conversation history and replayed output are not a complete workflow checkpoint. If work already created a report elsewhere, recovery should first establish whether that report exists. This division of responsibility shapes whether continuing work is understandable to the user.

Separate runtime cost from model cost

The announcement schedules consumption billing from December 1. Harness runtime use is free before then, while model inference and separately billed tools or connected services remain chargeable. A pilot budget must therefore follow a complete task rather than treating the runtime offer as a free agent stack. Hosted agents remain an alternative when a team needs its own framework, middleware or process behavior. Compare the approaches by what engineers actually maintain: managed execution removes some runtime code but constrains supported models, regions and environment settings; owning execution logic adds maintenance responsibility. These services were not deployed for this report, and no long-task success rate was measured. Configuration effort, recoverable artifacts and cost boundaries are the immediate evaluation questions.
