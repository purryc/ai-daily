Keeping the task inside the team project

Intrascope was already a multi-model team workspace. Its October 29 Product Hunt presentation groups version 2.0 around agentic chat, connected apps, Skills, automatic routing and a redesigned interface. A person places the question, files and client context inside the relevant project instead of repeatedly pasting the same brief into separate chat products. The website also describes exports to PDF, DOCX and presentations, allowing a result to continue through the team’s existing document workflow. The advertised model and connector totals describe vendor coverage rather than verified access for every account. They do not establish that every model can perform every connected action with the same reliability or feature completeness.

Model access and app access are different decisions

Setup starts with a workspace, invited members and project assignments, followed by the vendors and models administrators want to enable. The new MCP connections let enabled models read or act in tools such as Gmail, Drive and Notion, with company-level allow or block choices for each connector. These decisions have different meanings: authorizing a model to answer does not grant every business-system permission, and allowing a connector does not establish a fresh confirmation before each write. Public material does not specify universal per-action approval, cancellation of active operations or a complete permission mapping. Teams still need to identify which tasks read reference material and which can change an external record.

Reusable context needs an owner

Manifests hold tone, goals, product knowledge and response rules, attached to projects. Skills add a slash-command route for recurring tasks. That arrangement keeps organizational background and a reusable procedure available beyond one person’s conversation history. The administrator surface manages users, projects, limits and billing, while the team chat is where people perform the work. Centralization does not itself make the content current. An outdated product description or an old client requirement can be repeated more consistently once it becomes shared guidance. A project owner therefore still needs to decide who maintains the instructions, which files belong to that client and when the shared context should be revised.

One workspace bill is not unlimited inference

Intrascope supports personal provider keys, managed balance or both in one workspace. BYOK consumption is billed directly by the model provider; managed consumption draws down a prepaid balance and stops when it runs out. The workspace subscription and model use are separate costs, with per-model limits and reporting by user and project. The newer homepage also lists monthly team and workspace budgets, without specifying detailed behavior for concurrent tasks crossing a limit. Official pages currently disagree on some plan prices and seat allowances, so a single quoted price would be misleading. Whether the arrangement saves money depends on workload, model selection and rework, rather than the number of subscriptions represented in one interface.
