Research can stay in its existing Drive home

Designers often read research in Drive before copying a summary or image into a prototype conversation. Figma’s October 30 release adds a Google Drive connector so its agent can use that context while working on the canvas and create new Drive files for decisions or assets. Connectors also expand to all plans, including Starter. This changes the route from source material into design; it does not make every Figma AI capability free. The announcement gives a day without a timezone, so this record conservatively treats it as a recent supplement. A useful request still identifies the document and relevant version. A fluent generated summary can omit conditions or exceptions present in the research.

Read, write and disconnect are separate controls

Each person authenticates the external service through Add context. When a tool is needed, the agent exposes the proposed call and asks to run it; permissions can be set per tool, and external-write tools begin disabled. Google Drive is unavailable with the Governance+ add-on. All-plan availability also leaves seat, file-edit and external-service permissions in place. Administrators can block connectors, but data already incorporated into a Figma file remains. These distinctions matter in practice: connecting does not establish continuous live synchronization, and a changed source requires another read. Disconnecting likewise does not undo content already generated and saved. A team should distinguish permission to retrieve information from permission to distribute it elsewhere.

Turn a node workflow into a tool colleagues can run

The same-day Weave change lets Organization and Enterprise teams publish their own tools into Figma’s Tools area alongside official and community tools. An author connects an Output node in Weave, chooses which input attributes remain exposed, and publishes through Share tool. Colleagues can select canvas content, enter a prompt or choose settings without reconstructing the node graph each time. The underlying workflow can still be opened for inspection and revision, and tool updates create versions. Sharing a tool is distinct from sharing the editable workflow. This packaging suits repeated style-transfer or background operations, but the author still needs clear inputs so colleagues understand which parameters they can change and which have been fixed.

Internal distribution still has execution requirements

The help page requires edit access to the file. Running Weave tools in Figma is available on Professional, Organization and Enterprise, while internal publication has the narrower organization-level requirement. Only image or vector outputs run on the canvas; a publishable video or 3D workflow does not become canvas-executable. Runs consume Figma AI credits, and Weave remains a separate product for workflow editing. Administrators can disable community and organization tools without disabling tools built by Figma. For a team, the benefit is less repeated configuration and external transfer. Quality control still surrounds publication: clear inputs, an acceptable result and a way back to the original image help colleagues use the workflow correctly.
