Write a digit on the floor

DrawPad turns input into a twenty-eight-by-twenty-eight floor. Holding the fire button while walking lights the tiles beneath the player, creating a handwritten digit. Pressing READ runs the network and lights the winning number on a seven-segment display. In the scripted example, Python supplies the keystrokes, but the game still computes the classification. A poorly formed digit can be misclassified. The author explicitly separates agreement with a reference calculation from a correct answer. The published animation also speeds up the waiting portion, so its viewing pace is not a latency measurement. Input, computation and output remain visible within the same game scene.

Numbers become actors and mechanisms

The compiler creates extra player copies and moves them through conveyors and mechanisms. An activation can be represented by a number of these copies. Crossing weighted floor lines changes a later light level or height; stair-step gates implement activation functions. Ceilings controlled by another value determine how many copies pass, supporting multiplication and attention. Closing a route also makes a neuron intervention visible. The scene therefore participates in computation, rather than merely displaying an ordinary model’s answer over a DOOM image. Python reads the resulting values and compares them with an integer implementation. The engine’s numerical ranges and timing behavior still constrain which networks can be compiled and executed.

The update repairs an incorrect pass verdict

The dated increment is version 0.7.1 on October 28; the project’s first public release was October 20. Its static extractor could previously report equality for maps that actually computed incorrectly in the game. Missing trigger flags, moved teleport destinations and changed reset-script tags were among the missed changes. The update reads those elements, mover speeds and readout pages and applies the plane-range contract to the recovered network. Geometry and timing outside its coverage are explicitly identified as unchecked. Default generated builds do not change in this patch. What changes is the evidence developers receive when deciding whether a map faithfully represents the source network.

Equality has a defined scope

The runtime check compares exposed intermediate values for an actual input with the integer reference, using zero tolerance. Static extraction instead reads a network back from the map file and compares its structure with the source. These checks answer different questions: one exact run does not establish correctness for every input, and matching structure does not prove that an engine executes the map as intended. Random-network and map-mutation tests help expose blind spots in the checker itself. These remain the author’s published methods and results, not independently rerun findings. For interactive teaching or exploring computational representations, the project offers manipulable material; as an everyday classifier, it adds game-engine and build-environment overhead.
