An unreadable page is not an unchanged page

Phone control depends on readable interface content to identify controls and assess what happened. Version 1.0.5 changes a misleading failure interpretation: Android’s sensitive-view policy may filter password, payment or verification pages. Instead of treating empty content as a game or custom-drawn interface, or claiming that the screen did not change, the client explains the possible restriction and directs a handoff. It stops blind taps and swipes in that state. This preserves the meaning of a lost observation channel. An unfinished goal is not evidence that an invisible part of the interface can safely be treated as an ordinary page and navigated by guesswork.

Submission and verification are distinct states

After an action, if neither side provides comparable content, the new version reports that submission occurred but verification is unavailable. It no longer equates that state with no change or reaching the end of a list. Keyboard visibility and window-inset changes also count as interface changes, and screenshots carry a system timestamp. Separately, an options card can permit a freeform answer rather than forcing one of its presets. Card JSON missing its special fence can still render natively, with a short summary used for copying or sharing. Both changes turn raw output into a comprehensible state or a usable next input, reducing ambiguity about what the agent received or observed.

Remote connections expose the route they used

Version 1.0.4 from the preceding day makes DSH Remote choose a connection path automatically: local network or peer-to-peer first, then TURN and finally relay, subject to host and server support. A route label reveals the actual path, connection time, measured round-trip latency and fallback reason. Reconnecting clears old measurements rather than presenting the previous network’s values as current. Conversations, workspaces and plugins belong to their respective hosts, and switching disconnects the previous host. Remote access supports continuing desktop work, but currently accepts only image attachments and differs from local operation in embedded web mode, plugin management and log export. A similar chat surface does not imply identical capabilities.

A local engine does not imply a local model

At first launch, users can install Ubuntu, Node.js and the DSH environment on the handset or connect to an existing computer without installing the local engine. The author says root and a separate Termux installation are unnecessary and supplies an APK for Android 8 or later. Phone control is limited to the local engine in normal mode and requires permissions; the nonintrusive mode additionally requires Android 14 or later and Shizuku or self-connected ADB. Model requests still go to the chosen provider, potentially including task-relevant screen text or images. Anonymous usage statistics are enabled by default and can be disabled. The AGPL-3.0 project is unofficial; environment setup and provider configuration remain user responsibilities.
