From a remote terminal to actionable cards

Collie is a self-hosted phone PWA for developers supervising terminal agents such as Claude Code, Pi and Codex. Instead of connecting through mobile SSH and operating awkward key combinations, the user finds a session needing input and responds through a text field, question card or key panel. Herdr is the primary multiplexer target; tmux and zellij remain experimental. The default setup uses a shared Tailscale network and device pairing. MIT licensing does not remove hosting, networking or underlying model costs. The product changes how a person returns to an agent’s task, rather than making the agent’s actions inherently safer or more autonomous.

Released fixes address concrete screen differences

Stable version 1.23.2 was published at 21:18:33 UTC on October 21. Its documented fixes include Claude questions without question marks, particular pi extension-defined input boxes and follow-up choices from notices. These are small visual distinctions with direct consequences for the core mobile task: a changed border indentation, footer or question wording can prevent the bridge from recognizing where it may type. A stale typed-but-unsent card can now be dismissed when the terminal has already moved on. These are maintainer release claims, not results independently reproduced here on the corresponding phone and agent versions.

Sending text and answering a survey are different actions

A contributor’s field report describes blocked sends while controlling multiple sessions from Android. Claude’s transcript-sharing survey used letter choices that a reader expecting numeric choices did not understand. The release exposes those letters as notice options and requires manual handling when a message’s first line is itself an answer key. That matters because typing a message line by line could otherwise answer a different question. This is one operator’s report, not a population failure rate. Our interaction interpretation is that confirmation must identify its target: the same character can be ordinary message text or consent to a survey, depending on terminal state.

Unresolved cases reveal the cost of recovery

Another report describes a multiline pi draft being read as a menu: Send leaves text without pressing Enter, Submit is refused again, and the user switches to Screen to press Enter manually. Pull request 555 remained open when collected. Its proposal distinguishes soft-wrapped text from option lists but retains a conservative refusal for short lines with explicit newlines; suspected duplicated text was not confirmed. Other input fixes in the same day’s release must not be presented as resolution of this case. Waiting, text already typed and text actually submitted are different states. Showing one generic queued or retry label can encourage repeated actions without helping the user recover.

Acceptance should cover handoffs after a version change

A useful comparison includes continuing with mobile SSH, waiting to return to a computer and using Collie’s cards, measuring the steps needed for one approval or revision. Harmless sessions can cover empty input, existing drafts, surveys, unknown versions and terminal redraws while recording false refusals, wrong targets and recovery time. This is an evaluation proposal, not a completed test. The project describes single-user remote terminal access; pairing should not be mistaken for a multitenant authorization system. Release notes also disclose an embedded Bun TLS fix not yet included in this build. If agent updates repeatedly force a return to the desktop to repair recognition, compatibility work can consume the mobile convenience.
