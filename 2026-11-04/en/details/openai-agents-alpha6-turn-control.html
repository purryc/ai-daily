OpenAI's SDK gives each turn a handle for queueing, steering and recovery

Each submission owns a result

An application opens a Session and receives a Turn when it submits work. Waiting through get_result follows that captured root, including accepted steering. A busy Session can queue a new request or steer the active one. This distinguishes a correction to ongoing work from a separate task. A chat interface should preserve that distinction rather than displaying queued text as if it were already executing. The documented handle keeps its result stable after later independent submissions. That gives application code a concrete object to associate with the original request, instead of reading a single global result that can change when more work arrives.

Observation is different from completion

An event stream is useful for text and tool progress, but the documentation gives it bounded retention: a slow observer can encounter EventGap, and text deltas can differ from the eventual answer. Completion should therefore come from the result and canonical history. Stopping a reader is not the same as stopping work, cancelling the root does not guarantee independent child work stops, and a root result does not prove that child work is finished. The exposed distinctions are useful only when the interface uses them well. A stop control should have a comprehensible scope: current work, the whole conversation or descendants. An indefinite spinner cannot communicate those choices or confirm their effects.

Tool checks have different roles before and after execution

Python tools declare inputs with annotations, and policies can allow, deny or replace arguments before execution, then inspect results afterward. Replacement arguments are validated again, with separate views of original and effective values. This gives application rules a defined place at the tool boundary, such as a permitted quantity range. An after-policy cannot reverse effects already produced by the function. Conditions intended to prevent an operation belong before dispatch; output formatting and result inspection belong afterward. A later error is not evidence that nothing happened. The release adds these controls, but their correctness still depends on the application's own policy and tool implementation.

Storage choices define recovery boundaries

LocalStorage reopens a conversation using its profile directory and identifier, while portable SessionState checkpoints serve a different restoration path. LocalStorage cannot export those portable checkpoints. Saved history does not supply current credentials, permissions, workspace files or live processes. The alpha.6 release lists wheels for Linux x86_64, Apple Silicon and Windows x64, using standard CPython 3.10–3.14; Linux requires glibc 2.39 or newer. A checked installation document still contains stale text saying preview wheels are not yet public, so the versioned release is the availability authority. This preview changes APIs, and installing the existing PyPI package does not provide the same implementation.
