Dictate into an app and recover failed insertion

Umless starts with a held hotkey and processes the utterance after release. Its configuration separates automatic pasting from copying to the clipboard, allowing different delivery behavior for the current application. The November 1 first public Windows release adds an installer, recorded custom shortcuts and a clear microphone-open error. Failed pastes remain in history for manual recovery. That last detail addresses a small but costly interruption: a finished transcription is not useful if the intended field never receives it. Distinct listening, processing and insertion states help locate the failure without dictating everything again. These behaviors come from release documentation, not a completed test in this report.

The polished text is only one output

Most polishing workflows make the disfluency disappear from the final text. Umless retains the verbatim transcript and highlights fillers, repetition, self-correction and other edits in history. Reports then cite original sentences when proposing improvements. Scene settings let a chat retain conversational language while a document receives stronger restructuring. Keeping both versions gives the user something concrete to inspect when a rewrite changes meaning. It also gives coaching a traceable reference instead of only a score. The additional record is a product cost as well as a benefit. Someone who wants immediate dictation without a lasting speaking archive should inspect recording controls and retention settings before accumulating history.

Local scoring can inherit polishing errors

The project assigns fluency and concision to rules, leaving logic and clarity to a language model. Its metric specification makes a consequential distinction: when polished text exists, a filler must also lie in a deleted character span before it counts. Without that comparison, narrower interjection rules apply. The specification also acknowledges false repetition detections for ordinary reduplicated Chinese words when no polished version exists. Local calculation therefore does not make a score objective. An upstream recognition omission or an inappropriate rewrite can change the measurement. Inspect the highlighted sentence first, then compare similar speaking tasks. A falling count may reflect a different editing model rather than a changed habit.

[S33]

Choose recognition and polishing separately

Recognition defaults to local SenseVoice, while polishing can use local Ollama or a user-selected cloud endpoint. The privacy description states that switching to a cloud model sends transcripts and, for daily diagnosis, the previous day’s records to that provider. Audio is not retained by default, and text history uses a local database. Pausing records, excluded applications, export and clearing provide separate controls; uninstalling does not remove stored history. The Windows code’s MIT license does not cover external inference charges. Android has separate licensing and beta status. An offline setup consequently requires checking both recognition and polishing, rather than assuming that local microphone processing defines the whole data path.
