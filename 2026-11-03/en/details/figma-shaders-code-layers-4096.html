Describe the effect and its controls

The Figma agent can generate shader fills that create patterns and gradients, or shader effects that alter an existing layer. The documentation advises explicitly requesting a shader and naming desired controls such as intensity, colors or spacing. An ordinary request for a gradient may instead produce an image fill. That distinction affects iteration: a fixed image may require regeneration, while an exposed control lets a designer vary one effect repeatedly. The result still needs inspection on different layers. A detailed prompt establishes the intended behavior, not evidence that the generated implementation follows it in every situation.

See the effect inside a running layout

The new increment combines rendering and export up to a 4096-pixel maximum with shader support when designs become code layers. Select the design, build the code layer and press Play to observe it in a running layout. A hover animation shown in isolation says little about the button carrying it. Putting it beside text, boundaries and neighboring controls makes contrast and focus problems easier to spot. The higher export resolution can preserve detail, but the announcement supplies no guarantee about frame rate, power use or performance in a complex page. Those remain questions for the intended device and composition.

General availability still has runtime conditions

The release makes shaders generally available while specifying Chrome 157 and a staged rollout for this code-layer path. The help article additionally requires the HTML-in-Canvas setting and excludes the Figma desktop app and other Chromium browsers. Seeing a design file is therefore not the same as being able to play its effects in every collaborator’s environment. Shader generation and editing use AI credits; applying and playing shaders do not. Separately, generating and editing code layers is free on paid plans through November 4. Other agent tasks remain chargeable, so that temporary allowance should not be described as an entirely free workflow.

Reuse needs version ownership

Shaders can be saved as styles and shared in team libraries, and creators can inspect and restore version history. Shared updates have a different boundary for consumers: the management documentation says installed users receive the latest shader, with rollback requiring its author to republish an earlier version. A team can compare important pages on copies before changing a shared effect, avoiding a small parameter adjustment that unexpectedly alters many files. Handwritten effects and existing shaders remain alternatives. Generation makes experimentation more accessible, while readability, runtime requirements and version compatibility remain ongoing design responsibilities. No shader was generated or performance-tested for this report.
