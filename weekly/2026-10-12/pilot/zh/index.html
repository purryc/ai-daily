社媒不是只生成文案

AgentScope Java：功能、成本与实际用途
出问题的操作链
开发者在同一轮派出两个 agent_spawn(agent_id="researcher")，由streamEvents() 接回思考、文本和工具事件。2.0.x 的 source 都是同一个parentSession/researcher，因此前端按 source 分组时，两项任务的片段混在一起。报告者暂时用提示词禁止同名并行，并让界面降级显示“无法拆分”；这等于牺牲并行能力来保住可读性。
读完讨论才得到的修正
当前 main 已有 execution，其中 sessionId、turnId、runId 能标识子任务；报告者随后复现并确认，并行同名任务也能区分。UI 应按 execution身份分组，START/END 边界事件则另用 sessionId 与 replyId 配对。2.0.x 没有这个字段，配套维护分支 PR 提议保留 childSessionId；嵌套转发必须保住最内层身份，不能每经过一层就覆盖。
另一个可落地的排障点
另一条讨论把上下文压缩和长期记忆拆开：main 的 compaction 管本次请求摘要，memory 管会话外的保存与整合。模型不返回窗口大小时，token 触发阈值会回退到160k；若真实窗口更小，摘要就可能来不及。实际接入时先核对模型窗口和 triggerTokens，而不是以为接上长期记忆就解决请求超长。对产品界面，任务实例、版本与预算应是可见状态，而不只是后台日志。
入口与成熟度
Java SDK/开发者集成议题；main 与2.0.x不能混写。130k溢出为用户报告，回复者未复现；维护PR不等于已发布修复。

TIPER + agent-risk：功能、成本与实际用途
TIPER：难度来自互动，不是把任务改坏
TIPER 先让代理与模拟用户完成任务，再从失败轨迹中修改持续性的用户行为，并筛掉破坏原任务事实或可解性的候选。论文报告12个GPT-5.4测试设置的avg@3下降5.8–33.7个百分点。它更适合用于发现客服、订票或协作编码里“信息给得少、节奏不同”暴露的弱点，而不是把一个平均分直接当上线结论。
agent-risk：先判断旧记录够不够用
这个项目提供 Python 包 ai-agent-risk。输入每步分数、是否造成伤害、成本和最终失败标记，replay_stop 将记录分为照旧运行或被新阈值停止；继续走出旧日志的分支则需保存状态后的重跑或风险界限。certify_replay 给出伤害上界。与把全部任务从头再跑一遍相比，它试图只重跑证据不足的分支；但换模型也可能令旧轨迹全部失去可复用性。
入口与成熟度
TIPER论文公开，所链GitHub仓库本次读到为空，不能称代码已可运行。agent-risk仓库有Python≥3.9快速入门、代码与复现实验入口；本刊未安装或复现。
