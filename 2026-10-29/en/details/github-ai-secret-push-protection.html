Credentials outside the pattern list

A service key with a recognizable prefix is relatively straightforward to match. An internal password, temporary credential or value without a standard shape is harder to classify. GitHub’s public preview adds AI detection to push protection, using surrounding code to assess how a value is used. A developer sees a blocked push and a location, then makes the correction in the local workspace. The additional check happens before material enters the repository. It is not a new password manager and does not replace designing the application to read credentials from appropriate configuration or secret storage.

A location is the start of the repair

Push protection concerns content about to enter the repository. Removing a line from the current file may be insufficient if an earlier commit in the pending push still contains it. The affected commits need correction before another push. This leaves two distinct jobs: changing the application so it no longer relies on a hard-coded value, and removing the residual value from commit history. If a credential was exposed elsewhere, the owning system still determines revocation or rotation. A blocked push cannot prove that it was never disclosed. A path and line number make investigation possible without completing those external tasks.

Handling disagreement through the configured process

Contextual classification may catch values that fixed patterns miss, while also mistaking an example string or other data for a secret. Teams need enough context to investigate the finding rather than only an unexplained AI warning. Existing bypass and delegated-approval arrangements still apply. A coding agent encountering a block should involve an authorized person instead of finding another route merely to finish a push. Organizations configure bypass eligibility and approval differently, so the preview should not be described as imposing one universal review workflow. Its false-positive rate, latency and behavior on complex commits have not been independently measured here.

Eligibility and consumption are separate

This is an off-by-default public preview for eligible organizations with GitHub Secret Protection or GitHub Advanced Security and the required AI scanning and push-protection settings. The new pre-push AI checks consume credits; post-push AI scanning has a different billing treatment. They should not be combined into a claim of a universally free upgrade. Adoption depends on the existing repair process: which real credentials cause rework, who investigates disputed findings and where approvals wait. Catching a value earlier can avoid repository cleanup, but unclear findings may still concentrate investigation work among a few security maintainers. A team can keep the responsible reviewer and approval route close to the failure message. That reduces searching for help after a block and avoids treating an urgent release as an automatic reason to disregard the finding.
