Choosing effort instead of a model

Developers move between a small test correction and a problem spanning several files, with different amounts of reasoning needed. Fusion presents Standard, High and Max effort choices, then selects models and an execution pattern for the request and context. The October 28 announcement combines earlier automatic selection and Hydra Fusion in a generally available entry point. A user still needs to describe the intended change, constraints and acceptance criteria. Effort is not a replacement for project context. For a team, this can remove a recurring model-selection decision while retaining a reason to inspect which models actually ran when similar jobs have different costs or delays.

Drafts, reviews and files

The documentation distinguishes a single-model response, sequential drafting and revision, and review involving multiple models. Standard primarily uses one model; higher effort can combine calls. This is separate from launching independent subagents. The interface exposes the models in use without presenting every intermediate draft as the final answer. File state deserves particular attention: discarding an intermediate answer does not undo edits it may already have made. Review therefore belongs on the workspace diff, tests and proposed commit, not only the final explanation. Individual context limits also remain; orchestration does not automatically create one larger context window.

Local routing still has a cloud boundary

The accompanying experiment can send eligible work to a local model. The managed WinML path uses MAI Code 1.1 Flash; the CLI also supports specified manually configured compatible servers and models. Setup differs across the app, CLI and VS Code, and adding a BYOK provider does not automatically make it eligible for Fusion routing. Routing decisions can still depend on the cloud, so a local inference step is not an offline guarantee. Downloads, available memory and contention with builds remain practical considerations, particularly on a laptop already running an editor, test suite and other applications.

[S30]

Budget follows the calls actually made

Fusion adds no separate orchestration fee, but combined calls consume credits at the models’ normal rates. The paid-plan introductory discount has an end date. Administrators must also enable relevant models and features; an option visible to one developer does not establish organization-wide authorization. A useful comparison follows the same class of change through retries and final review. A cheaper first draft can create more rework, while greater effort may avoid repeated explanations. Vendor benchmark results do not supply a reliable budget or quality promise for an arbitrary repository. Teams still need an acceptable final change, not merely a lower price for the first response. When review models disagree, the developer still has to connect each suggestion to a real defect. More participating models do not create an automatic rule that the majority is correct, especially when they share the same misleading context.
