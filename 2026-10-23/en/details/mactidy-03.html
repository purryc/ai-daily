Turning disk usage into a question of provenance

MacTidy addresses a recognisable kind of Mac clutter: applications, settings and old development tools carried through several computer migrations. Its initial scan builds a catalogue rather than immediately changing files. The interface groups system items, apps, development environments, terminal material, personal files and unidentified leftovers into shelves. The supplied screenshot also displays a timeline of inferred computer eras. Our reading is that this changes the question from “Which directory is largest?” to “Which part of my working life left this here?” That can be more useful to a long-term owner than a headline about reclaimable space. It gives an unfamiliar folder some context before the owner decides whether it still matters.

Dates and usage records are clues

The eras are not invented by a language model. The documentation describes using migration traces in the Keychains directory to divide the timeline, then assigning an item according to its earliest file. Owners can rename an era after the computer they remember. Usage is inferred from Spotlight access information, directory modification dates and command history. A practical starting point is therefore the filter for material apparently unused since arrival. The limitation follows directly from the task: an archive, old certificate or dormant project can remain valuable despite little recent activity. In our assessment, the timeline should prompt recognition rather than decide importance. Editable era names help connect technical timestamps to the owner’s own account of their machines.

AI fills recognition gaps; cold storage supplies a middle choice

The built-in knowledge base identifies familiar applications, SDK remnants and version managers. Optional AI handles names it does not recognise, using a compatible endpoint or local Ollama. The developer describes sending filtered metadata rather than file contents, including name, path, type, size and date. AI is consequently an explanatory aid, not a prerequisite for every scan. The action side offers a useful middle ground: freezing moves an item into dedicated storage while recording where it came from, so it can be returned. For an old toolchain whose relevance is uncertain, that matches the owner’s hesitation better than immediate disposal. Moving something can still temporarily break software that depends on it; reversible storage is not the same as making dependencies disappear.

An early utility for people willing to inspect their storage

The 0.3 release is labelled the first public version. It targets Apple silicon Macs running macOS 14 or later and is available under the MIT licence. The distinction between scanning and acting is important: scanning is read-only, while freezing or moving to Trash changes locations. Restoration also has a boundary once Trash is emptied. The developer notes that the app is not yet Apple notarized and that fuller cataloguing can require Full Disk Access. We have inspected the supplied interface image, not installed or tested the program. Our product judgment is that this suits someone prepared to understand old directories one by one. Its potential benefit is a clearer keep-or-set-aside decision, rather than treating every trace of a previous computer as disposable waste.
