A persistent computer extends the single-use sandbox

ACE is infrastructure behind an agent, not a new assistant consumers can download today. Google's motivating example is an agent that analyzes a spreadsheet, installs libraries, and saves a chart on Monday, then retains its scripts and results for a follow-up on Tuesday. The orchestration harness remains outside the sandbox and decides what to invoke; the sandbox executes code, commands, and browser actions. ACE supplies a microVM with its own kernel and root-level control, combining isolation with a persistent workspace. The October 22 event is disclosure of the service and governance expansion. Google explicitly targets preview in the coming months, so internal use for Gemini does not establish customer availability or production general availability today.

Keep state without reserving the same machine

The efficiency mechanism follows an agent's rhythm. After a tool call finishes and no background work remains, the runtime reports idleness and the host checkpoints and suspends the environment. A later call restores it. Pre-warmed images and copy-on-write memory let environments share unchanged operating-system and program pages while allocating private changes separately. Durable user workspaces are distinguished from disposable scratch data and shared read-only toolchains. These distinctions affect experience: preserving files is not identical to retaining live processes, and a memory snapshot does not roll back an external service. Google's claim of no active compute for idle sessions is not a published total-price guarantee; storage, other services, and contractual restoration performance remain unspecified.

Credentials stay outside; policy still governs actions

The technical account separates untrusted execution from long-lived service credentials. Sandboxes lack a normal external network interface; requests traverse mediation proxies and Agent Gateway, which checks user delegation, agent identity, node identity, and policy before inserting backend credentials. The same account describes short-lived session-scoped workload identity, so the precise claim is that durable service secrets remain outside the sandbox, not that identity material never exists. This reduces direct secret theft without automatically preventing a mistaken action through an allowed channel. Cross-cloud and endpoint governance are described as coming to preview, with token and routing features targeted for this quarter. Those roadmap states should not be merged with already documented identity and gateway capabilities.

Substrate is an existing self-managed foundation

The announcement presents Substrate alongside ACE, but its linked GKE availability post dates to September 15. Substrate maps a larger set of stateful actors onto a smaller worker pool, snapshots memory and filesystem state when idle, and runs on standard Kubernetes with microVM or gVisor options. Its public repository is Apache2 licensed, remains pre-1.0, and explicitly provides no backward-compatibility guarantee. The earlier GKE post permits non-production workloads while production support requires an allowlist. This is an existing self-managed runtime choice, not evidence that ACE itself is open source. No account, cluster, or deployment was created in this review. Consumers generally encounter its consequences as restoration delay and continuity rather than as infrastructure controls.

Keep performance figures within their test context

The October 22 announcement cites Substrate validation with 200,000 agents, 500 activations per second, sub-500ms suspend/resume, and up to tenfold density. The current repository states higher throughput and lower latency figures. Without matching versions, configurations, and workload conditions, those numbers cannot be combined into one test or transferred directly to the future ACE customer service. My product judgment is that the announcement gives waiting agents a more appropriate resource lifecycle and places access enforcement outside model reasoning. The valuable user outcome is returning to work that can continue. These remain vendor architecture and performance claims; continuity still depends on process, file, external-connection, and product-level restoration contracts that are not proven for every task by the announcement.
