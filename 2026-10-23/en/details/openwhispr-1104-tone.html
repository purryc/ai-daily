Dictation that adapts to the destination

OpenWhispr is a desktop dictation, meeting-transcription and notes application. Its established interaction is a global shortcut: speak, then receive text at the current cursor. Version 1.10.4 adds a writing preference after recognition rather than introducing a new speech model. Personal messages, work messages, email and other applications can each receive a chosen tone. Personal messages offer Formal, Casual and Very Casual; the other categories offer Formal, Casual and Excited. A user can therefore dictate an informal message and a formal email without repeating a style instruction every time. The release became public on October 22 at 08:21:23 UTC, while the repository changelog is dated October 21. The release publication is the event here; the earlier preparation date is not another launch.

Classification starts with speech, under an explicit switch

Tone & Style is disabled by default. Users enable it in Settings and save a choice for each group. The implementation describes classification at dictation start, using the application identity, window title and browser host. Titles and hosts remain in the main process and outside logs; the interface receives the category. Cloud cleanup receives tone and category, while local or bring-your-own-provider cleanup appends matching instructions. This is a narrower context transfer than sending a whole page, but local speech recognition alone does not make the complete writing chain offline. An older Windows helper only identifies the executable, potentially classifying a browser as Other. Other also includes documents, IDEs and terminals. Editorially, destination categories save repeated setup but cannot reliably express every relationship inside one app; an explicit requested tone must remain authoritative.

Preserving speech when the later step fails

The release also addresses failures between speech capture and insertion. Previously, an error after transcription, such as a selected-text edit, could leave an empty history entry. The new path retains the transcript and exposes it through the failure indicator. A chosen local, self-hosted or enterprise cleanup model is also supposed to remain in use when speech recognition comes from a cloud or streaming provider. Another fix preserves self-hosted model choices across restarts instead of reverting to a cloud default. On Linux, voice-assistant answers can reach the caret, but automatic insertion into Wayland apps on niri, sway and Hyprland now requires wl-clipboard. Without it, the transcript remains available for retry. The practical gain is recoverable work when a later stage breaks, not a demonstrated improvement in recognition accuracy. These are release claims, not our cross-platform test results.

Notes reconnect speakers, summaries and calendar context

The notes workflow gains a calendar link from the note header. Users can search the previous three days of events, attach participants, open a joining link or remove the association. AI Summary now uses the detailed-note structure, while existing summaries and customized templates remain unchanged. More consequentially, in-person speakers should no longer all reach the model under the user's name. Continuing a recording in the same note no longer reuses earlier session speaker identifiers, and stopping a local meeting waits for the final audio chunk still being transcribed. These changes move the product toward knowing whose statement entered a summary and whether its ending was retained. They do not establish correct speaker identity: a polished summary can still carry forward a wrong attribution from the underlying recording or separation stage.

Open code with separate cost and processing choices

Version 1.10.4 has public source, an MIT license and downloadable macOS, Windows and Linux artifacts. It is more than a UI proposal. Building from source requires Node.js 24 or later; the desktop stack includes Electron, React, whisper.cpp and sherpa-onnx. The pricing page lists unlimited local dictation as free, with the free cloud tier offering 2,000 words weekly and five meeting hours monthly. Pro is displayed at $80 billed annually, equivalent to $6.67 per month rather than a monthly-billing quote. Bringing an API key has a different cost structure from running a local model. My assessment is that the app suits people who want model choice alongside dictation across applications; the useful outcome is fewer revisions in their actual messages. The illustration is a contributor's screenshot of the implemented settings components in a test harness with stubbed data, not proof of model quality or a real user's account.
