The new event is the tracing skill, within existing Coworker

Adobe's October release notes assign Trace Journey Profile an availability date of October 22. The collection was edited on October 23, which is not a replacement launch date. Business performance analysis and hygiene analysis carry earlier dates, while journey creation from the right rail remains in the forthcoming section. The concrete delta is a tracing capability inside an existing assistant. Adobe describes continuous delivery, so the date should not be interpreted as proof of simultaneous deployment to every organization. This review checked public documentation rather than signing into a customer environment to establish account-specific access.

Move from branch distribution to one person's execution

Trace queries journey step events at three levels: node entry and stop counts with branch shares; profiles that errored during a requested interval; and an individual path identified by profile ID or email. The last includes timestamps, values evaluated at condition nodes, and exit details. An operator investigating an unexpected loyalty branch can therefore ask about the particular evaluation instead of relying solely on population summaries. These are execution records, not experimental evidence that the diagnosis is complete. The documentation supplies no independent accuracy result, event-completeness guarantee, or measured reduction in investigation time.

Bind the question to the right operational object

The chat's organization and sandbox determine reachable data, skills, and tools. Operators can switch that context through the account menu and use an entity mention to identify a particular journey. Journey Optimizer currently has the full-page immersive entry point; its in-product experience remains forthcoming in the interface availability table. Responses can expose tool activity, artifacts, and a summary, with transcript controls revealing more detail. My interface judgment is that explicit object selection matters more here than merely extending a prompt: similarly named journeys in different environments can imply entirely different investigations. The documentation does not prove that entity mentions eliminate targeting mistakes.

[S108]

Generic interface controls do not expand the skill's scope

Trace supports published journeys and excludes draft-only and B2B flows. It is read-only, with no list export or journey editing; aggregate fallout, anomalies, and custom-action trends belong to Journey Analyze. The general chat's Plan mode waits for approval before work, but it cannot turn tracing into editing. Likewise, generic CSV artifact controls do not override the skill-specific export restriction. My product reading is that diagnosis and remediation remain separate user intentions. A suggested follow-up at the end of an answer should be understood as a possible next task, rather than evidence that a business configuration was already changed.

Execution provenance is the meaningful product change

The meaningful interaction change is whether a question can be tied to a specific time, node, and evaluated branch value. Consider a customer reporting a missing message: an operator could examine whether the path reached the message node, encountered an error, or exited earlier before deciding what to investigate next. That is an illustrative workflow inference, not an Adobe trial result. Opening a message or choosing not to purchase requires different evidence. The next step should match the cause: journey design for a branching condition, delivery records for a missing message, or actual customer feedback for intent. Keeping those questions separate makes the conversational diagnosis useful without turning a technical explanation into a complete account of customer behavior.
