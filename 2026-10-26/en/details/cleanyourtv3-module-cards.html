Separate applications become owner-approved cards

CleanYourTV began as a coding-agent-assisted cleanup of a family television. Its October 25 version-three release expands optional utilities from eleven to twenty, adding nine including home controls, ad-blocking status, named sources and nighttime volume limits. Each add-on is a separate Android application with its own installation and permissions; the core launcher does not depend on them. When a declared module card is found, the owner chooses whether to show it. A changed label or signing identity requires a new choice. Other version-three options include a single app row, lunar dates and returning Home at power-on. New options default off, so upgrading alone does not impose a different layout.

Remote gestures control lights while locks remain read-only

The Smart Home module takes a Home Assistant address and token, then groups scenes, lights, switches, climate devices and household status. OK runs a scene or toggles a light; Left and Right adjust brightness in ten-percent steps or a thermostat by half a degree. Locks are visible but cannot be opened. It displays up to eighty supported entities, refreshes while open and offers no entity picker yet. The tagged documentation makes an important distinction: the interface ran on a MOKA R8G television, but the author’s Home Assistant server was unavailable, so requests went to a stand-in server. Its screenshot shows genuine application UI with demonstration data, not a verified household integration.

Named inputs and blocking controls have narrower validation

Sources tries to replace port numbers with names reported through HDMI-CEC, putting connected inputs first and handing playback to the television’s input application. Both ends need CEC enabled, and reported connection status can include standby devices or even an empty port. The author’s television test had no CEC device attached, leaving device-name handling covered by program tests. Ad Blocking instead reads an existing Pi-hole or AdGuard Home server and offers a five-minute pause or immediate resume. It does not create a blocker. The real-TV demonstration used a stand-in Pi-hole 6, with no real Pi-hole or AdGuard validation. These are useful remote surfaces whose integration claims remain limited.

Device failures sharpen the cleanup lists

The release also incorporates more concrete device feedback. A TCL G10 owner lost the remote microphone button after cleanup despite a working Assistant stack. Restoring the Google TV remote service recovered the button; rapid reboots had confused diagnosis by reverting package state. Version three preserves that dependency. A separate Sankey report found that prose said Live TV was kept while an uncommented list entry still disabled it. That reporter did not own the same model, so this is a configuration inconsistency rather than a fresh reproduction. The corrected lists and input-handler protections address specific dependencies. Source builds and model checks remain necessary; agent-assisted configuration is not television runtime AI.
