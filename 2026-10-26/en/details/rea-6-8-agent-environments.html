Record a workflow before giving it to an agent

A developer who wants to exercise an agent against a repeatable application task often needs to maintain a test service and its simulated responses. REA 6.8 offers a capture-based starting point. Its environment-build command accepts a HAR file or Evidence JSON produced by browser-scenario capture, inspects the recording, derives a tool manifest and initial state, and writes a directory that agent-env can run. The build itself reads a file and writes a folder; it neither launches a browser nor contacts the recorded application. Browser recording is a separate preceding step. Input formats are explicit, so an arbitrary JSON file is not accepted merely because it resembles a HAR.

Reads use state; writes need recorded confirmation

The default server answers read tools from the state observed in the recording, with filters, search, sorting and pagination. That lets an agent ask related questions without receiving one fixed response for every request. A create, update or delete needs evidence for its modeled effect, such as reading a newly created item and its collection afterward. Missing observations, missing confirmation, contradictions or unmodeled side effects can withhold the corresponding write tool. A coverage report names withheld operations and suggests what to record next. This gives developers a specific missing read to capture, rather than treating a successful HTTP response as proof that the simulation is complete.

Choose replay or a changing local state

A replay-only option keeps stateless replay available when a caller does not want the default derived state. A dry run performs build checks and reports planned files without writing a bundle; a real export requires an absent or empty destination. Developers can also compare an environment against fresh application probe captures. These are different controls: replay selection changes how the local environment responds, while comparison checks its relationship to new observations. Writes served by the built environment change its own state rather than resending requests to production. Recording a browser scenario is different: real write requests made during recording can change the application instance being captured.

The bundle carries bodies as well as behavior

REA is MIT licensed and can be used through MCP or its CLI. This release requires supported Node 22, 24 or 26 versions, and its installer does not upgrade the runtime. Bundles include complete capture evidence and response bodies. Standard authentication headers are excluded, but custom credential headers, query tokens and sensitive response values can remain; a name-based warning is not a completed redaction review. The practical trade is less manually written simulation code in exchange for careful recording, confirmation reads and export inspection. Suitability depends on whether the important objects and side effects were observed. The release does not establish that an arbitrary application becomes a faithful replica automatically.
