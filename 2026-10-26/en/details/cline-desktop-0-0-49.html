Open a turn’s changes from its completion summary

After an agent says it has finished, reviewing its work can still require finding files and determining which changes belong to the latest turn. Cline Desktop 0.0.49 adds a Changes button to the session header, showing line counts and opening file-by-file diffs for either the last turn or the whole session. A completion summary also lists modified files and opens the pane scoped to that turn. A neighboring project tree carries Git status letters and session-change markers. Files open in read-only tabs, with a File/Diff switch for agent-edited files. These controls connect the completion message to concrete code without making the review result automatic.

Keep commands, pull requests and model details nearby

The new terminal panel sits at the bottom of the window and can be toggled by keyboard, keeping command output near the conversation. Pull-request status moves into a header menu containing its title, merge state and checks, with failures first. Actions include opening GitHub, creating a pull request, copying the branch name and refreshing. Local Models settings collect Ollama and LM Studio setup guidance, model details and storage information; a composer chip shows memory used by the loaded model. These changes consolidate inspection and management surfaces rather than adding model intelligence. The project-files panel also works with local and SSH environments, so remote work retains the same path from a session to its changed files.

Another client reconnects the run already in progress

The accompanying SDK and CLI releases repair cross-app handoff for a task that is already running. Previously, starting that session could replace its runtime while the original run continued unreachable and wrote into a stale snapshot. The updated SDK reattaches to the live session and rejects a new start carrying a prompt while that run is active. The Hub tracks clients that register session capabilities and routes requests to the first still connected; if none remains, it fails promptly instead of waiting indefinitely. Desktop startup failures now offer Retry and Export diagnostics, and settings expose Hub status and restart. This fixes ownership and feedback, not a general guarantee that interrupted tool actions can be retried.

A fuller interface still needs human review

Desktop remains a beta, with macOS, Windows and Linux packages, and the repository uses Apache-2.0. Cloud providers, a user’s own API account and local models have different costs and runtime requirements; open-source client code does not make inference free. The new viewer is read-only, so editing still uses the agent or another editor. Architecturally, a desktop backend connects to the shared Hub and receives approval updates as events. Closing one client does not mean that the shared Hub used by other clients has exited. The release improves visibility into changes and failures, while code judgment, tests and external-action approval remain human responsibilities.
