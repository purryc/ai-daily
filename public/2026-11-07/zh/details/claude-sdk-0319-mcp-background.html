Claude Agent SDK 0.3.319 · 开发工具更新／官方发布与代码

Claude SDK把MCP任务放到后台，结果仍须追踪

长工具调用有了单独的任务身份

开发者用Claude Agent SDK把读代码、改文件和执行命令接进自己的应用。0.3.319增加的是MCP任务后台执行：启用CLAUDE_AUTO_BACKGROUND_TASKS，并采用流式输入，返回任务以mcp_task标识。前台界面因此可以表示还有工作在继续，而不是把一次工具等待伪装成完整回答。应用仍需保存任务和会话的对应关系，展示运行、失败与完成的区别；发布说明没有证明所有MCP服务都会自动支持这种模式，也没有给出统一的恢复时限。

预热不再冒充真正开始的会话

同一版还调整OpenTelemetry会话计数。预先启动、最终却没有被领取的进程不再增加会话数量；真正领取成功时才计一次。对运营仪表盘来说，这会影响每会话成本、失败比例或使用量的分母。团队应把升级前后的统计口径记下来，避免把计数修正误读成用户活动下降。这里减少的是测量噪音，并不是模型调用已经变便宜，或者每个任务都能更快完成；这两类结论仍要从真实账单与任务记录得到。

清理动作需要明确失败

会话维护也有较具体的修补。从项目目录之外的转录文件恢复，再执行清理时，丢失写入消息现在指向正确会话。删除会话若不能完全清除目录，会以ENOTEMPTY拒绝，而不留下看似成功的调用。结束为错误结果的运行只保留标准错误行，不再与正常退出时的写入丢失消息混在一起。产品需要据此解释哪些记录仍在、哪些结果未持久化，不能只把错误代码藏进后台日志。

接入范围先于并发承诺

后台MCP路径明确不包含Bedrock、Vertex和Foundry，不能把一个云平台的验证结果推广到所有客户环境。仓库说明SDK受Anthropic商业服务条款约束，并非因为代码页面公开就可当作宽松开源组件；模型、外部工具及托管资源也仍有各自条件。适合的小规模试用是一项耗时工具任务：前台继续收消息，再断线重连，检查任务身份、最终文件和错误是否一致。后台任务增多后，排队和账单也要一起核对。
