Keep the agent identity while changing its runtime

Paperclip puts several agents inside one task and budget interface. The November 6 stable release makes its native Runner the default for qualified new Claude, Codex, OpenCode and Pi agents, and gives existing Claude and Codex agents an upgrade action. The action includes pending edits and requests conversion while retaining supported model, account and instruction settings. Incompatible fields produce an error and leave saved configuration on the old runtime. Merely opening settings or saving an unrelated change does not upgrade the agent. That explicit transition lets teams move one working agent at a time rather than discover a runtime switch after a routine settings edit.

A fresh session can coexist with retained history

Conversion starts fresh sessions while keeping earlier runs available. Retaining history does not mean partially completed model execution transfers unchanged. The implementation report describes local macOS tests with API credentials, while SSH, sandbox targets and subscription credentials were outside that particular exercise. Linux defaults require glibc 2.39 or newer, and supported processor architectures vary across harnesses. Operators should check the target system, connection type and custom settings before comparing actual output files before and after conversion. The author's checks are useful evidence of scope, not a guarantee for every deployment combination. A migration plan should also preserve enough information to explain why an unsupported field was rejected.

Repository skills keep a per-run version

New projects can import attached GitHub repositories as skill sources and check their selected branches for updates; existing projects can adopt their repositories explicitly. Runs pin the skill versions they start with, automatic updates can be paused, and a missing branch can be repaired. This reduces manual copying of skill files while creating a review responsibility. A newly imported script can change tool behavior, so an updateable source is not automatically a trusted source. Administrators should retain the relevant commit and installation scope, then confirm that an in-progress task keeps its starting instructions when the repository changes. This is a configuration lifecycle improvement, not proof of safer generated work.

The upgrade also removes an old experiment

This stable release promotes work from an earlier beta series; its entire commit count should not be described as features first invented that day. It removes the Pipelines experiment's boards, stage configuration, review queues and related commands while preserving database tables and records. Cases and Routines remain. Teams using the old controls still face a workflow change despite retained data. The repository is MIT licensed, with external models, connections and hosts carrying separate costs, and some new providers remain experimental. A useful acceptance check follows an existing job through rejected settings, reopening and historical record access, rather than stopping when the new button becomes visible.
