Record with people before mounting on a robot

A demonstrator holds one YUBI gripper in each hand and performs a physical task while wrist images and tool motion are recorded. The robot later carries matching tools and cameras, reducing the viewpoint mismatch between demonstration and execution. A task instruction and two partial views condition end-effector actions, which a controller translates for the arm. This releases a robot from each recording session, but does not make collection free. A useful collection plan still needs different object placements, handovers and difficult cases. Teams should inspect whether demonstrations represent the situations the deployed system will actually encounter, rather than counting recording hours alone.

Connecting partial views through a longer task

With only wrist views, a single image may not distinguish opening a case from closing it. The system uses stage prediction, recent-motion memory and streaming action generation to connect longer procedures. A demonstration in which sorting bins move illustrates adaptation to changed positions, not universal recovery from disturbances. For adoption, separate object identification, stage selection and physical execution errors. Record where a person must intervene and whether resumption preserves the intended task. This makes failures actionable: a smooth clip alone cannot tell an operator whether to reposition an object, repeat a demonstration or correct the controller when a different run stops.

Keep partial completion visible in the evaluation

The paper evaluates ten tasks on a Franka at a site absent from collection, with fifteen trials per task. Its 78% average, compared with 27% for the strongest baseline, permits partial completion. It therefore cannot be converted into a count of completely successful runs. An unseen site also does not mean an arbitrary household. A deployment trial should separately report full completion, intervention and object damage, then vary containers, illumination and dimensions. Capacity estimates for purchasing or scheduling need usable completed outcomes. A partially sorted tray may contribute to a research score while still leaving an employee substantial inspection and finishing work.

Separate code, weights and data availability

The November 6 announcement makes code and model resources the new release event; the post-training repository is readable, while dataset publication remains prospective. Code uses Apache 2.0 and weights have separate Gemma terms. Installation also requires a matching Linux, Python, CUDA and dataset setup. The reported training time uses eight H200 GPUs rather than a laptop. Before expanding collection, budget one bounded task from recording through data conversion, calibration, training and on-site debugging. Compare total staff and equipment time with the existing demonstration process. Savings in robot occupancy are useful only if they outweigh the additional integration and validation work.
