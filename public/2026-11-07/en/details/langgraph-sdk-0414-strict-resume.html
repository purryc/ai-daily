A second answer should not silently disappear

A paused agent task may be visible on a phone, a desktop and a colleague's browser at the same time. After one person answers, another can still click Continue on an old screen. Without an explicit failure, that second interaction can look as though an approval succeeded. LangGraph SDK 0.4.14 lets Python callers request strict resumption: answering an interrupt that is no longer waiting fails with UnknownInterruptError and preserves the thread. The mechanism addresses stale interaction state. It does not decide whether the answer is sensible, establish which person may approve, or replace the application's own identity and permission controls.

The parameter must reach a compatible server

The keyword-only parameter is available on runs.create, stream and wait in both synchronous and asynchronous clients. It is sent only when explicitly set and only for runs attached to a thread. Stateless overloads leave it out, and a server without support ignores the field. Updating the client package is therefore insufficient to promise strict behavior. The backend capability, request shape and error handling must agree. A reproducible check opens the same interrupt twice, completes it in the first view, and submits the stale identifier from the second. The expected result is an understandable rejection with no unintended advance of the thread.

Typed tool events are not a new execution engine

StreamMode also gains tools and lifecycle. Tool events cover start, intermediate activity, completion and error; lifecycle events describe a subgraph starting and ending with the identifier of the tool call that launched it. The implementation explicitly calls this a typing change with no runtime change. Crons share the type, yet the server returns 422 if a cron requests either mode. An option appearing in autocomplete consequently does not mean every endpoint accepts it. Applications can use the existing events to explain progress, but should not market the type addition as a new execution engine or assume that it supplies complete provenance.

Give the reviewer a way to recover

The LangGraph repository uses MIT licensing, while hosting, model calls and managed services retain separate costs. For review products, the most useful result of strict resumption is an explanation of current state: which request was already handled, where work now stands, and whether the reviewer needs fresh evidence. Blindly retrying the old request merely repeats the failure. A pilot should include duplicate clicks, wrong identifiers, delayed networks and an older server, checking both unintended advancement and legitimate answers that become stuck. We did not execute those tests. The public implementation establishes the mechanism and its compatibility boundary, not a measured reduction in approval mistakes.
