Long tool calls acquire a task identity

Developers use Claude Agent SDK to put code reading, file changes and command execution inside their own applications. Version 0.3.319 adds background MCP tasks when the application enables CLAUDE_AUTO_BACKGROUND_TASKS and supplies streaming input. The task is identified as mcp_task. That gives an interface a concrete reason to display continuing work after the immediate exchange, instead of treating a tool wait as a finished answer. The host application still needs a mapping between task and session and distinct running, failed and completed states. The announcement does not establish that every MCP service automatically supports this mode or provide a universal recovery deadline.

Prewarming is separated from an actual session

The same release changes OpenTelemetry session counting. A process started by prewarm no longer counts if no session ever claims it; a successful claim adds the count once. This matters when dashboards divide spend or failures by the number of sessions. Teams comparing periods should record the measurement change rather than interpret a smaller denominator as a sudden drop in customer activity. It is a correction to instrumentation, not evidence that inference became cheaper or tasks became faster. Those conclusions require actual usage bills and completed-task records. A useful rollout separates process starts, claimed sessions and finished jobs so that operational capacity is not confused with customer work.

Cleanup needs an explicit failure result

Session maintenance receives several concrete fixes. When a session is resumed from a transcript outside the projects directory and then cleared, the lost-write message now names the correct transcript session. deleteSession rejects with ENOTEMPTY if it cannot fully remove the directory. A run ending in an error result produces the stderr line rather than the lost-write notification reserved for a normal CLI exit. For an application, these distinctions affect whether it tells a person that records were removed or output was saved. A visible cleanup failure should leave a recoverable state and an explanation; burying the code in a server log would waste the more precise signal.

Check supported deployment paths before promising concurrency

Background MCP support explicitly excludes Bedrock, Vertex and Foundry. A successful integration on another route therefore cannot establish coverage for customers on those platforms. The repository says Anthropic commercial terms govern the SDK; a public repository is not itself a permissive open-source license. Model access, tools and hosting also retain their own conditions. A focused pilot can launch a slow tool operation, continue receiving foreground input, disconnect and reconnect, then compare task identity, final files and errors. As background work accumulates, queue length and spend should be checked together. The practical question is whether users recover useful results without losing track of work.
