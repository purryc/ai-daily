See the individual jobs inside shared discussion

A team creates a Space by selecting a project, a name, who can see it and an optional goal, then posts requests, bugs or ideas. The coordinating agent starts threads for separate pieces of work, represented by live cards in the shared chat. A person can open a card to inspect the result and continue editing. Comments between people are not read by the agent until someone mentions @amp. That distinction leaves room to discuss a proposal without converting every sentence into an instruction. When the team does assign work, the resulting thread supplies a concrete place to inspect responsibility, progress and output.

Send the selected element with the feedback

A second November 6 update puts feedback on the website itself. An administrator enables the widget, adds its script and allows the site's origin. A person with project access selects an element and writes a requested change, accumulating comments across pages of that site. After sending and authorizing the account, Amp creates a thread carrying the selected element and page address. The agent works on a repository copy in an Orb, not the live site, and does not see the live site's private data. This reduces manual location descriptions, while leaving the reviewer responsible for checking whether the change fits the actual page state.

A hidden button is not access control

The widget starts hidden, but a query parameter or keyboard shortcut can reveal it; its script still loads for visitors. Hiding the button therefore is not an identity boundary. Sending requires permission to start threads in a workspace project, personal projects are excluded, and allowed origins are entered manually. Each send creates a new thread rather than appending to an existing one. Teams that only need internal review can place the script on staging. Turning the widget off removes its associated application; enabling it again creates a new identifier and requires replacing the script. Those maintenance steps belong in the adoption plan.

Count review work alongside delegated work

The Space activity chart separates shipped, archived and open threads. Research with no code to land can be archived without manufacturing a commit. That chart helps inspect backlog, but a shipped count alone cannot establish that a requirement was met. Hobby has no monthly fee, while hosted Orbs and external model access retain charges or subscription limits. A useful trial asks two teammates to annotate different parts of a page, then checks task creation, conflicting edits and time spent locating review material. If coordination becomes easier but duplicate threads multiply, the team still needs ownership of merging and archiving work.
