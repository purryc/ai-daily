The checkpoint restores a session, not a machine

GitHub Agentic Workflows 1.2.1 can save an agent session into a workflow artifact so a later run can recover conversational and tool history. This can reduce repeated explanation of work already attempted. The November 9 weekly article discusses the capability, but the original prerelease was published on November 6 at 20:14:55 UTC; it belongs in a seven-day retrospective. Durable continuation is experimental and opt-in. It is not a general backup of workspace changes, and it does not freeze credentials or current instructions inside historical state. A subsequent execution still receives its current model, tool and policy configuration, which can differ from the earlier run.

A parent run makes continuation traceable

The documented selection rules distinguish an explicitly supplied parent, the last successful run of the same workflow on the same branch, and a preceding attempt when rerunning a job. Continuation therefore has a lineage to inspect rather than an arbitrary old conversation. Artifact retention defaults to seven days, with configurable retention bounded by organizational policy. Missing explicit parents and invalid artifacts should surface as errors instead of silently looking like a fresh successful task. For ongoing issue processing or review, developers should retain that lineage beside the task identifier and output. Similar requests on two branches otherwise remain easy for a human reviewer to confuse.

Stored history remains untrusted input

Pinned documentation warns that session artifacts can contain substantial task and tool-output history. Secret cleanup is heuristic, rather than a guarantee that every piece of personal information or encoded credential will be detected. Anyone able to read an artifact may consequently be able to read its retained content. Guidance treating restored history as untrusted is not deterministic isolation against prompt injection. Integrity validation checks the checkpoint contract; it does not establish that a website quoted inside a tool response is trustworthy. Adoption should therefore include artifact access, retention and input-source review. Separate threat detection starts afresh rather than relying on the restored session as a security verdict.

[S77]

External actions still need duplicate protection

Engines do not all restore state identically: some use native session identifiers, while others rely on recovered files and continuation instructions. A canceled run or lost runner may fail to upload the newest checkpoint. The feature neither dispatches a replacement job automatically nor guarantees that a tool’s external side effect happens only once. A cautious adoption test would first use a task without external writes, inspect its recovered lineage, and then add stable operation identifiers and result checks for actions that must write elsewhere. No installation or runtime test was performed here. Persistence can reduce repeated task explanation, but it also creates retained data and failure branches that someone must manage.
