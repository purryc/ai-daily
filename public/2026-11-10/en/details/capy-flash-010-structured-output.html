Make the answer satisfy the interface contract

When a local model feeds a form, classifier or extraction pipeline, the next step usually needs fields rather than prose resembling JSON. capy-flash 0.10.0 lets a request specify JSON Schema, GBNF grammar, a regular expression or a fixed choice list. XGrammar’s CPU core computes a legal-token mask before each decoding round, constraining sampling and checking MTP drafts. Unconstrained requests in the same batch keep their previous path; constrained DFlash2 requests decode without drafts. The interface contract is applied during generation, reducing one class of punctuation and field repair afterward. It still cannot establish that an extracted value is true or that a classification is appropriate.

Compatible protocols still have explicit limits

The server exposes Chat Completions, Responses and Anthropic Messages shapes, with format settings placed in response_format, text.format and output_config.format respectively. All three support streaming. Strict objects close undeclared keys by default, which differs from literal JSON Schema’s open-object behavior; intentionally open fields must be stated. The documentation also lists unsupported keywords, so protocol compatibility should not be treated as complete equivalence with a provider’s API. Required or named-function tool_choice and strict tools still fail, and constraints cannot be combined with active tools or custom stop strings. Moving an existing client therefore requires checking its actual request shape, not simply replacing the server address.

Complex formats consume shared resources too

The release bounds constraint size, nesting, member count, compilation time, concurrent compilations, matcher CPU time and memory. A busy compilation queue can return 429, while an exceeded request budget reports its own error. Those limits aim to prevent one expensive grammar from delaying neighboring work. The default five-second compilation timer starts only after a compilation slot is obtained, distinguishing waiting for capacity from a complex format. A stream can already have sent HTTP 200 when matching later fails; it then ends with a protocol error event and the partial content is incomplete. A client needs a successful ending before consuming the result, rather than equating an accepted connection or partial JSON with a completed extraction.

Local hardware and concurrency retain their tradeoffs

The project targets specified Qwen3.8 models on one or two 16 GB sm_120 GPUs. Flash-Next experts that do not fit in VRAM use host memory and CPU computation, with substantially different memory needs across model packages. Version 0.9.0 already introduced optional active KV in RAM and concurrency support; those are context for this update. Version 0.10.0 raises the default pending timeout from thirty seconds to ten minutes, reducing premature rejection of simultaneous long prompts while potentially extending waits. The maintainer reports 360 constrained generations passing an independent schema validator on two RTX 5070 Ti cards. That is a configuration-specific author result, not our replication. Adoption should examine semantic fields, successful endings, queue delays and error handling together.
