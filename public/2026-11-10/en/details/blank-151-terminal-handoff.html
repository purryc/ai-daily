Continue the same task across desktop and terminal

blank is an open-source agent workspace combining model connections, file editing, tool approvals and result previews. Version 1.5.0 added a full-screen terminal interface on November 8; version 1.5.1 then corrected requests to custom model endpoints. The terminal offers a scrollable transcript, multiline composer, command picker and inline approvals while sharing configuration and sessions with the desktop app. A person can begin work in the app and resume that session in a terminal instead of copying a prompt and rebuilding its context. These are released interface and compatibility changes. A recent Reddit self-promotion is a discovery source, not evidence that the whole product first launched that day or has broad adoption.

Approval and recovery remain visible in the terminal

The terminal lets users select sessions, resume history, change models and expand tool output. Approval distinguishes a one-time allowance, a persistent allowance and denial; unrecognized input leaves the action waiting. A plain mode remains available for non-interactive input and output, so scripts do not have to adopt the full-screen interface. On the desktop, file cards deliver generated artifacts, while Paper switches between preview and code with different viewport widths. That puts inspecting files closer to inspecting generated pages. An approval prompt establishes permission for an action, however, not correctness of the resulting code. Users still need to inspect the working directory, changes and intended artifacts rather than treating a completion message as acceptance.

Custom endpoints should not receive guessed parameters

The concrete 1.5.1 fix stops sending a guessed reasoning-effort setting to custom OpenAI-compatible endpoints. Provider errors now show which request fields were sent. For someone connecting a local inference server or a different provider, that is more diagnostic than a generic failure: it helps separate an unsupported parameter from a problem with the task. Local runtimes must actually be running, while cloud calls go to the selected provider. Keeping session files on the device therefore does not make every inference offline, and the free MIT-licensed software does not include external model usage. The same release contains a network-proxy policy design document; a proposed networking layer should not be advertised as implemented behavior.

Separate worktrees prevent collisions, not review work

Existing team settings can dispatch read-only specialists or isolate write-capable subtasks in separate git worktrees. Runs with changes retain a branch and changed-file summary. That addresses concurrent writes to the same directory; it does not resolve conflicting requirements or prove the merged result correct. Generated HTML and SVG are previewed through an isolated Paper protocol, which the developer says prevents access to application data. We did not install the app or audit that boundary. A practical first comparison is whether a small task resumed between desktop and terminal preserves its model, directory and approval state. That exposes handoff errors more clearly than enabling every tool at once. Interface imagery does not establish that every platform installer and model connection has been tested.
