Recover a screen—and remove its derived summary

TimeScroll is for a Mac user who remembers seeing a chart or sentence but cannot remember which app contained it. It keeps searchable screen history, so the person can browse a date or describe the remembered content. Version 2.3.0, published on November 9, addresses a specific consequence of generating summaries from that history: deleting a time range now removes it from existing and future summaries too. Deleting within the first three hours of a day also removes the previous day’s summary. The design treats summaries as derived records that must follow deletion. It does not establish improved model accuracy or recall information already shared elsewhere.

Capture controls determine what can later be searched

The update excludes common password managers by default and adds an optional private-browser-window exclusion. The latter requires Accessibility permission and the developer explicitly says detection is imperfect. Audio has a separate boundary: a private window can still be heard in the recording when system-audio capture is enabled. Hiding its image therefore does not stop its sound. Three new Shortcuts actions start capture, stop it and report whether it is running without opening the main window. A user can build a battery-sensitive recording routine around those controls. The release also reduces Accessibility-tree activity in Chrome and Electron during Direct capture; no independent battery measurement was performed here.

Read text directly, then retrieve by meaning

After Screen Recording permission is granted, Direct mode obtains text through macOS Accessibility; OCR is available for apps that do not expose suitable text. Search can be narrowed by app and date, with matches located on the corresponding snapshot. Meaning-based retrieval uses local MobileCLIP2 image embeddings or an embedding model in a local Ollama installation. Ollama can also summarize a selected period. These are existing capabilities, not all new in 2.3.0. The free, open-source app supports Apple silicon and Intel Macs running macOS 14 or later. Compared with manual screenshots, it removes the need to predict what will be worth saving, while adding an ongoing retention and storage decision. In a community discussion, a user asked about missing Accessibility text; the maintainer said there was no automatic OCR fallback. The two modes should not be described as seamless coverage.

Local storage and external assistant access are different choices

The privacy policy says snapshots, extracted text, indexes and transcripts live in a chosen local folder. Update checks can be disabled, and enabling relevant AI features initiates model downloads. The optional encrypted vault is still marked beta. MCP is off by default; enabling it lets a connected assistant search the history, and the returned information is then governed by that assistant’s privacy policy. Local storage should therefore not be described as a promise that every connected workflow stays local. Before relying on deletion, a useful check is to summarize a harmless interval, delete it, and inspect both search and summary results while separately checking audio settings. That check was not performed for this article.
