Let the process decide which tools appear

An airline agent may understand which booking a customer wants changed without having confirmation for that specific change. Concordat lets developers describe process states through Python classes and methods: verification can precede proposing a refund, and a pending approval can request a human decision. The tools offered to the model change with the state; an attempted illegal call is rejected before its method body executes. The product team must therefore make the business process explicit rather than only revise a prompt. This suits tasks with clear prerequisites, such as showing an application before submitting it. The library does not decide which prerequisites are appropriate for the business.

Keep the approver separate from the model

A human step is decided by an approver function supplied by the application. The model can request that decision but cannot supply it itself. Budgets are also divided during delegation so parent and child cannot spend the same allowance twice. For interaction design, waiting for a person should be an explicit state showing the target, parameters and expected result, not an isolated confirmation button. The application still needs to define whether changed circumstances invalidate an earlier approval. The library enforces the protocol that was written; it cannot supply missing business rules. A broad execution tool could also conceal actions with different consequences inside a single apparently permitted call.

A keyword is not complete consent

The paper adds customer pressure to skip confirmation in simulated airline tasks and reports eliminating unconfirmed writes under its chosen rule. However, the experimental gate treats a message containing yes, yep or yeah as confirmation; the author explicitly notes that it would accept yes followed by an objection to the specific target. This is not a complete consent interpreter or a general safety demonstration for real support work. A practical approval should refer to a concrete action description and the parameter version actually shown. After a user changes one item, the application must know whether the previous approval remains valid. Correct final state and authorized execution are separate facts worth preserving.

A small kernel still needs operational integration

The repository is labeled pre-alpha, uses Apache-2.0 and provides Anthropic and OpenAI runners. Obtaining the code without a license fee does not remove model or maintenance costs. Integrators still need to handle remote timeouts, duplicate submissions and partial completion: a successful external operation whose response is lost can be repeated accidentally. Durable sessions are future work in the paper, so pending approvals should not be assumed to survive a process restart automatically. A pilot can begin with a bounded, inspectable task and record blocked out-of-order actions, normal completions and reasons for human transfer. Other application entry points must follow the same business rules if the protocol diagram is to describe the real execution boundary.
