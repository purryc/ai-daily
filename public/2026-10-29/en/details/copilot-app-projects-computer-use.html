One goal across several sessions

A feature often involves more than code: design material, discussion, test failures and later communication all need attention. Projects groups those materials and sessions around one goal, including projects without a repository. After adding context, a user can inspect tasks grouped by whether they need input, remain open, are working or are done. A session exposes plans, changes and pull requests, with a way to steer subsequent work. This reduces the need to reconstruct responsibility from a long chat list. A done status remains a task state, however; readiness to release depends on the associated artifact and review.

Desktop interaction when a connector is absent

Computer use reads accessibility information and, when needed, screenshots before clicking or typing. It addresses local applications without a suitable API or connector; macOS also requires Accessibility and Screen Recording permission. It is off by default, but tool permissions determine subsequent prompts. Once a persistent allowance is granted, it would be misleading to say every action receives a fresh approval. A user can stop the operation or press Escape. Removing a saved allowance affects future use rather than automatically ending an active session, so withdrawing permission and stopping current work are distinct actions.

Security fixes remain local first

The security extension brings existing alerts and review of current changes into the app. Users can filter findings, request an explanation or ask for a fix. A fix changes local files without committing or pushing them automatically. Linked pull requests help reveal work already underway, while a stale-review indicator warns when code has changed since review. Reading alerts and asking for AI explanations, fixes or reviews have different billing consequences; model-assisted actions consume credits. Access to private-repository findings also depends on Code Security eligibility and permissions, so installing the extension does not grant access to all security information.

Keep handoff state visible

Projects is useful when several related artifacts must be followed at once, but gathering context does not remove differences between tools. Window position, dynamic controls and focus can affect desktop actions; a structured API is usually easier to constrain when one is available. Security work likewise needs inspection of the actual diff rather than reliance on a repaired-status message. A team can use the overview to find material and waiting tasks while keeping code review, external actions and desktop permissions in explicit controls. At handoff, the person should be able to tell whether to clarify a request, inspect a file or stop something still running. A project may contain one task waiting for a person and another still running. During handoff, completing one artifact should not be confused with ending all related work or resolving every pending dependency in the project.

Memory crosses sessions; checked-in guidance still gets a pull request

The accompanying GitHub intelligence release makes Memory generally available on paid plans, carrying preferences and repository conventions across clients; personal memories can be viewed and deleted. Dreaming is a separate opt-in preview that curates personal and repository memories and proposes changes to checked-in skills or instruction files as pull requests. These are different operations: memories can be added, updated or removed, while repository files enter review. Dream runs also consume AI credits. A requirement valid for one conversation may not belong in permanent guidance, so the team needs to distinguish current instructions from accumulated memory. Cross-repository search can bring in related implementations without removing access controls.

Closing the editor differs from shutting down the host

VS Code’s Agent Host separates a session from an individual editor window and extends work through remote SSH or tunnels. Closing the local window still requires the remote machine and Agent Host to remain running. That differs from a cloud session on GitHub infrastructure, which does not depend on a personal laptop staying on. Phone controls can operate an agent on the development machine without moving execution onto the phone. When switching clients, users need to know where the task is running, which host must remain online and how to resume after disconnection. Parallel model comparison and Judge recommendations remain a preview rather than proof that a chosen change passes project tests.

Visual assets saved into the workspace

The image feature lets a Copilot conversation call a dedicated GPT Image 2.5 Flare tool, preview the result and save it into the workspace. It removes the separate generate-download-import step for a visual asset. This public preview has specific paid-plan eligibility, and image tokens are billed separately from the chat model. A visible AI watermark is optional and off by default. Once generated, the file still needs checks for dimensions, wording and intended use; it is not evidence of a real product interface.
