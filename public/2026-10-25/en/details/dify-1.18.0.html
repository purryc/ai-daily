Choose the next destination while completing the task

A workflow that first asks an agent to handle a message and then adds a classifier to decide whether to answer or escalate carries another layer of parsing and mapping. Output Routes places those conditions on the Agent v2 node. The editor defines at least two routes, writes their selection criteria and connects the destinations. The agent completes its work and selects a route in one call. A read-only switch output exposes that choice, and the canvas highlights the branch actually taken. The builder still owns the criteria: two valid route names do not establish that a model understands an ambiguous complaint or missing information.

A package moves supported resources together

Handing a workflow to another team can leave skills and attachments behind when only its configuration travels. The new .ifpkg format includes application configuration and supported associated resources. Inline agents, skills and files in Workflow and Chatflow apps are recreated in the destination workspace, with references remapped. Explicit YAML export remains, and file or URL imports accept both formats. Import reports missing resources; a versioned manifest, digests and bounded archive validation describe what the package contains. This reduces separate copying and reconnection work. It does not establish that every external plugin, account permission or service is available in the receiving environment.

Open a tool invocation to inspect its internal steps

A nested workflow can otherwise look like an opaque tool call. Run history now opens a particular Workflow Tool invocation and shows the child’s individual steps, with pause, resume, stop and file outputs coordinated across the graphs. The source graph is captured before execution, so republishing a tool does not silently change an already-running invocation. Inspecting its details still requires access to the source application. The release notes qualify nested usage and step totals, particularly after pause or stop, and distinguish console drilldown from external trace export. Diagnosing a failed handoff therefore benefits from the specific invocation rather than relying solely on an aggregate count.

Streaming, knowledge spaces and upgrades have separate conditions

Plain Agent v2 nodes can stream generated text, while structured output, routed output and nodes using default-value error handling remain buffered. Agent Knowledge Base adds file, source and retrieval management as an optional beta requiring a separate service and database; cloud availability was still described as forthcoming. Upgrading also involves the API, workers, Agent Backend and runtime images together. Older runtimes cannot read newly saved snapshots, and historical agent-specific human forms cannot resume, although shared Workflow Human Input nodes remain supported. For existing deployments, these compatibility conditions determine what happens to paused work and deserve attention alongside the more convenient editing and packaging features. The receiving workspace still needs its own dependency and access checks.
