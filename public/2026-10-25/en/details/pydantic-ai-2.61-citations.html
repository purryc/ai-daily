Pydantic AI 2.61.0 · Developer-tool update

Pydantic AI attaches citations to answer spans and preserves them through the UI

One structure connects answer text with its sources

A question-answering product using several models encounters citations as URLs, file identifiers, whole-block references or character positions, each in a different provider format. Version 2.61.0 maps recognized references into TextPart.citations, containing sources and an optional anchor in the answer text, while retaining provider-specific details separately. Applications can offer a consistent interaction for inspecting what supports a sentence without implementing a different frontend parser for every provider. The change organizes and transports evidence. It does not establish that a cited page supports the claim, or allow an uncited sentence to inherit the authority of nearby links. Source quality still requires separate judgment.

Unreliable positions do not become false highlights

An anchor is retained only when it can be reconciled with the text. Out-of-range positions and mismatched spans are not turned into guessed highlights. Gemini offsets across several parts are checked against the joined text, with a unique segment-text match available as a fallback. Raw provider data remains available for investigation. An application can consequently distinguish a known source without an exact location from a source attached to a specific span. Streaming introduces another distinction: some providers deliver citations at the end of a part, while Google and OpenAI Chat may wait until the response ends. A typing answer can therefore precede its complete source list.

Which citations survive the frontend round trip

The Vercel adapter emits a source entry for each cited web page and stores full citation metadata on text parts. When the frontend returns conversation history, those fields can be reconstructed. Joining consecutive text parts also shifts anchors by the preceding text length instead of keeping only the first part’s citations. Document sources are not automatically listed as web sources because providers may omit stable media types or titles, although their metadata remains. Invalid client-returned citations are discarded individually rather than failing the entire request. The AG-UI adapter still does not send citations to its frontend. Developers must therefore check their actual adapter path rather than assuming identical behavior everywhere.

Citation behavior cannot be applied indiscriminately to tool arguments

Citations attach to text, not to a structured object returned through tool arguments. Anthropic document-citation markup can enter non-text fields, so the request option is disabled for structured output, and a forced tool with documents or Web Fetch can raise an error before submission. Model-selected tools retain a documented markup-contamination risk. History replay also sends only supported citations back to their originating provider; some document references revert to plain text. The adoption benefit is easier preservation of a source chain, with display, caching, history and tool arguments still requiring distinct checks. After inspecting a source, users should be able to return to the associated sentence rather than lose its place in a detached list.
