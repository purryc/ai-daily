Different actions receive different permissions

A file inspection often needs reading without editing or deletion. Agent Zero 2.15 represents that distinction directly in the agent configuration. Twelve bundled tools with multiple actions can be controlled operation by operation, including reading versus writing files and listing versus deleting scheduled tasks. This gives an administrator a smaller action set for an assistant that checks information. The practical benefit is an inspectable setup decision: a person can see which operation is enabled before starting work. It does not establish that the model understands an ambiguous request correctly. The task still needs to distinguish examining a file from changing it.

Defaults and explicit overrides remain distinct

The editor separates an explicit On or Off choice from Default, which inherits the relevant default. That matters when a configuration evolves: a category default can cover later defaulted entries, while a deliberate override retains its meaning. The documentation describes deterministic configuration editing, with the actual override changes available for review before saving. Global and project scope remain separate decisions. For a team, reviewing scope alongside the action is useful because a permissive experiment should not silently become the setting for unrelated work. Save & Test starts a fresh chat, making a new configuration easier to check without treating old conversation state as a clean test.

[S48]

A text permission is not a filesystem boundary

The documentation explicitly says these permissions govern tool calls rather than creating a filesystem sandbox. A terminal that remains available may still alter a file whose text-editor Write action is disabled. Reviewing the whole capability set is therefore more informative than inspecting one greyed-out action. Hiding a skill also does not remove material already present in conversation history. A useful local evaluation would give the agent a read-only inspection job and observe the tools it actually requests. This is a check of whether the configuration matches its owner’s intention, not evidence that a visual toggle has created isolation across every execution path.

[S48]

The upgrade also changes tools and recovery details

Other changes make several bundled capabilities into plugins and consolidate the separate memory operations into a single action-based tool. Existing custom integrations should therefore be checked against the changed interface before an upgrade. The release also addresses duplicate sends, first-chat creation races and upload-failure cleanup. These details matter when a person cannot tell whether a request was accepted and is tempted to send it again. Channel-setting changes require explicit administrator status, separate from permission to send the bot a message. Deployment still needs Docker and an available model service. No upgrade, billing measurement or complete plugin-combination test was performed for this article; the described behavior remains maintainer documentation.
