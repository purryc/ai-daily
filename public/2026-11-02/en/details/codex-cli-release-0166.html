Selecting the relevant part of a long transcript

In a long coding session, a developer may need one error message, a rejected approach or the explanation of a particular step. Version 0.166 adds keyboard selection across words, lines and pages, with integrated search and configurable shortcuts. Consistent Markdown rendering also extends across asynchronous questions, choices and replies. These are practical reading controls for material that already exists. They can reduce repeated scrolling or another request to reproduce an earlier answer. They do not establish complete model memory. A copied explanation should still be interpreted alongside the code state and task that produced it, especially after several later edits.

Continuing after a queued message

The new queue --resume option can bring an unloaded thread back after a message is queued. For someone juggling tasks, the useful outcome is that the next request reconnects to the intended work rather than sitting apart from it. Related fixes retain acknowledged permission settings through resume or fork, restore image attachments with recovered composer text and bring descendant threads back when their parent is unarchived. These changes address specific continuity failures. Before continuing, a person still benefits from checking the thread, attachments and active workspace. Preserving a previous permission setting is not a reason to interpret it as approval for unrelated new operations.

Separating connection trouble from task trouble

A focused doctor --network-only command checks configuration, connectivity and WebSocket behavior. That provides a more specific starting point when a terminal appears stuck and the developer does not know whether work began. The release also fixes some reconnection and thread startup or shutdown races, and improves explanations when an action is blocked. None of this provides a recovery guarantee for every network environment. If an operation’s outcome is uncertain, inspecting files and execution state before sending the same instruction again can prevent duplicate work. The diagnostic command helps investigate connectivity; it does not prove that an interrupted business or coding operation left no effects.

Keeping release timing and access costs separate

The original GitHub timestamp places this release on October 29, rather than the October 31 date of a later roundup, so it is included as a seven-day retrospective. The CLI repository uses the Apache2.0 license, but running the client locally does not make model inference free or entirely offline. The README describes signing in through an eligible ChatGPT plan or configuring an API key. The accompanying image is a general terminal example referenced by that version’s README; it does not demonstrate the new selection or queue controls. An upgrade evaluation should examine time spent recovering context, attachments and connectivity, rather than treating an expanded model catalog as an outcome by itself.
