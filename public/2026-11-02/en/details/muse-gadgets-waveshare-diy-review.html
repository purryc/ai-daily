Start with a readable answer

The Verge’s Sean Hollister published an October 31 development-board build that added conversation history and spoken answers. The new evidence is a personal modification, not a retail-pendant review. On a tiny screen, whether an answer remains readable affects whether the owner must take out a phone anyway. A simple task provides a useful design starting point: hold to ask, recognize when recording ends, see processing status, read the reply and retrieve it later. Each step needs distinguishable feedback. An appealing character can accompany those actions, but it cannot replace them. This is a practical interaction problem that a programmable gadget makes unusually visible to its owner.

Hardware handles input and output

Waveshare documents avatars, Muse images, touch controls and push-to-talk through onboard microphones and a speaker, with phone-app pairing and an SDK token. The official device table identifies a 1.75-inch 466-by 466 AMOLED touch display,32 MB flash and 8 MB PSRAM for this board. It is development hardware connecting input and output to a service. Being pocket-sized does not establish that it runs a large model locally. Check the full model identifier when choosing parts: a similar case or display size does not guarantee the same display driver, audio hardware or firmware configuration. A reliable shopping list must connect each physical component to an actually supported board profile.

Editable firmware needs a recovery path

Muse Gadgets provides ESP32 and Linux SDKs and identifies its device code and firmware as Apache 2.0 licensed. Builders can connect displays, buttons, sensors and other homemade interfaces to the service. These are extension points rather than proof that every home-control function arrives ready to use. For a personal project, preserve the original firmware and a recoverable version, add one action at a time and verify that controls still stop or return from it. A coding assistant can lower the difficulty of beginning the implementation. The owner still needs to understand how errors appear, what survives a restart and which version can restore a working device.

[S36]

Give the extra device one clear job

Compared with a phone, an extra pendant also adds charging, pairing and maintenance. Choosing one useful action matters more than counting features. Begin with something easy to complete at hand, such as leaving an answer visible for later, and observe whether that actually avoids unlocking the phone. Home-device controls need their own confirmation and failure feedback; a conversational reply alone is not evidence that an external action occurred. The interface should also distinguish a network problem from waiting on the service. We did not audit the author’s code, measure battery life or establish long-term stability. Programmability makes the experiment interesting, while dependable everyday use remains a separate property to test.
