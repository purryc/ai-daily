Removing a bridge from deployment

Embedding a coding agent requires more than choosing a model. Developers must decide where its loop runs, how tools execute and which process receives credentials. The October 29 fx adapter change uses libfx in the host application for the harness and model requests. Built-in filesystem and command tools operate through the sandbox. This removes an internal executable installation, bridge process and exposed port from the setup. The change simplifies the deployment relationship; it does not eliminate the sandbox or make the model understand application permissions automatically. A team can evaluate it by checking which previously maintained connection steps are actually removed from its own deployment.

The boundary depends on the call

Model credentials remain on the host rather than being forwarded to the command environment. The documentation also places HTTP or SSE MCP connections on the host and excludes command-based stdio servers. Describing the entire agent as living inside the sandbox would therefore hide an important distinction. Host networking supports model and configured MCP calls, while the sandbox need not make model requests itself. For an application team, a useful integration review lists the path of each capability, especially external connections and custom tools. The documented boundary around built-in file operations should not be casually extended to every tool an application may attach.

Tool selection and steering need visible state

The adapter adds built-in tool filtering alongside mid-turn instructions, structured output and image tool results. Its permission modes distinguish reading, editing and shell execution approval. Those choices can support separate inspection and repair entry points in a product. The application still has to present whether the agent is waiting for a person, running or finished. Sending a new instruction mid-turn is not equivalent to undoing an earlier file change. A usable interface should clarify whether the instruction changes subsequent work or calls for a separate corrective task. This is an integration design consideration, not a recovery guarantee supplied by the new steering capability.

Recovery needs retained state and the sandbox

Resuming in a new host process requires more than retaining conversation text. The documentation calls for reattaching the sandbox, supplying saved lifecycle state and using credentials compatible with the original provider. Credentials themselves are excluded from persisted lifecycle state, and manual compaction remains unsupported. The harness packages are explicitly experimental, with potential breaking changes. An evaluation could stop a controlled task, reconnect it and inspect both the resumed conversation and actual files. No such execution was performed here. Host, model and sandbox costs were also not measured, so fewer setup components should not be reported as a demonstrated reduction in total operating cost.
