Ask about the work already on screen

When an unfamiliar error appears, a conventional chat requires a screenshot, an upload and an explanation of the current task. AirJelly now accepts a request to inspect the screen from the conversation, including multiple displays. Its side chat also accepts input while a reply is underway, with a choice to queue the message or send it immediately. The former preserves the current conversational sequence; the latter offers a way to correct direction sooner. The release is dated October 30 without a clock, so it is conservatively treated as a seven-day supplement. A subsequently observed November 2 version lacks evidence of availability before this issue’s cutoff and is excluded from this update.

[S09]

Suggested questions now commit sooner

The preceding release placed a suggested question into the composer for editing. Version 2.0.16 sends it immediately on click. That saves a confirmation for frequent follow-ups, but changes the control from editable suggestion to committed request. A reader may want to inspect a proposed question before actually asking it. Clear button behavior matters more as the assistant gains richer context. During interruptions, the interface also needs to distinguish a received correction from work already performed under the previous instruction. The release notes do not establish comprehensive rollback for every running action. Conversation steering therefore should not be described as a guarantee that arbitrary operations can be reversed.

[S09]

Pausing capture does not erase history

Context can include visible work, accessibility signals and connected applications, reducing repeated explanation while collecting more than a single typed question. The help documentation describes a double press of Option to pause screen capture, alongside app exclusions. The privacy page separates encrypted local screenshot storage from remote understanding: relevant images and text are sent according to the feature used. Secure-input protection depends on the application reporting a protected field through accessibility interfaces. That is a conditional mechanism, not proof that every sensitive passage will be excluded. Pausing before a private task, removing existing history and recalling an already transmitted request are different operations that users should not confuse.

[S10] [S11]

Keep useful reminders without constant interruption

Suggestions can be revisited under Work → Proactive, allowing people to defer attention rather than respond whenever a hint appears. General settings let them disable gentle nudges or choose other modes. This matters for a personal utility because useful context often accumulates during focused work, when interruptions are costly. Account documentation says longer context, screenshots and tool steps can consume more credits; current billing is inspected inside the application. Moving to a new device also does not automatically transfer all local history. A practical starting point is one repeatedly forgotten follow-up, checking whether reminders are accurate enough to keep. Neither unverified pricing nor assumed time savings should become a promised return.
