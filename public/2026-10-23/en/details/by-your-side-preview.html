Reading and acting share the existing browser

By Your Side is a developer-preview assistant that lives beside the page in Chrome. Its author’s public introduction describes reading, clicking and filling within the existing browser session, with results presented as interactive cards. A straightforward use is reading an unfamiliar article: instead of copying the whole text into another chat and carrying the explanation back, the reader can ask about the passage where the difficulty appears. The supplied demo image keeps Wikipedia in the main window and places an explanation card alongside it. Our interpretation is that the appeal lies in preserving the spatial relationship between question, source and answer. That fits the moment when a reader encounters an unfamiliar concept halfway through a page.

Translation, questions and changed instructions can continue in place

The usage guide connects several small reading actions: ask about selected text, replace page text with a translation, switch back to bilingual or original display, and drag material into the input before sending it. It also describes changing requirements while a task is running. In a comparison task, for example, revising a budget could preserve the information already collected instead of forcing a completely fresh request. That potential benefit is our inference from the interaction, not a measured productivity result. Material types still matter. The guide excludes text inside images, PDFs and cross-origin frames from whole-page translation. Reading some PDF content and translating an entire PDF in place are different capabilities and should not be conflated.

Taking over preserves a task, then rereads the page

When the user wants to intervene, the documented takeover action stops the assistant. Handing control back makes it reread the edited page before continuing the same task. Edge indicators are meant to show whether the assistant is working here or in another tab. This is useful for someone who wants to delegate repetitive clicks but personally handle an ambiguous choice. Routine clicks and filling are not individually confirmed. Submission rules are less settled: the README, usage guide and current-status page describe them differently, so a blanket promise about every sending path would be premature. Payment remains explicitly manual. Our judgment is that alternating control is the central interaction; its value depends on understanding the user’s changes at the handover.

An inspectable early tool with a setup cost

Access still involves building the source, loading the extension and connecting a model service. Public source does not make model usage free. The README names Chromium browsers and multiple desktop systems, but says full testing has covered macOS with Chrome; Safari and Firefox are unsupported. Page content and task screenshots can go to the connected model provider, so using the existing browser does not imply local inference. Canvas and cross-origin frames also remain limitations. For a technically comfortable browser user, this is an inspectable and adjustable assistant worth understanding. For someone expecting a finished install-and-go utility, the setup cost is substantial. We inspected documentation and an authentic screenshot, without installing the extension or measuring cross-site task success.
