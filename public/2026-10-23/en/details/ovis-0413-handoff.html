A phone window onto the session still running on the PC

Ovis is an individually maintained browser and phone client for herdr. Version 0.4.13 was published on October 22 at 11:59:39 UTC. It renames herdr web ui while retaining existing installations, settings and update channels. Its audience already runs agents such as Claude Code or Codex on a computer: the phone reads the same native conversation as chat and opens the real terminal for interfaces that cannot become cards. Herdr continues to own the sessions; the phone does not create a separate cloud copy. It therefore suits an individual who wants to inspect and steer work away from the desk, while the host PC remains necessary. Compared with a remote desktop, it exposes sessions, questions and workspaces as touch-friendly objects, with different support across agents.

Making the handoff from chat to terminal visible

The clearest interaction change is the handoff for terminal commands. A command such as /config or /usage, which chat cannot fully represent, opens a terminal overlay in the current browser after acceptance. The reading position remains, with controls to return to chat or keep the terminal open. Busy commands remain queued; an explicit Send now triggers the transition, and refused sends retain their drafts. Ordinary commands show whether they were accepted, are waiting for an answer, completed, require the terminal or have no observed result. A changed screen is only an unconfirmed preview. This matters when deciding whether to send again: the agent may have entered a settings menu rather than finished. The interface offers a specific next action instead of collapsing different situations into a generic busy state.

Resuming, rewinding and starting work have different boundaries

Earlier sessions reads the histories each agent stores on the PC, showing recent entries with title, initial prompt and time. Resuming opens a new tab, unless another pane already has that session, in which case Ovis selects it. Rewind in terminal opens the terminal and suggests the agent's native rewind command; it does not perform the rewind and preserves the draft. A new workspace can specify model, reasoning effort and an initial message, but some agents receive that message only after becoming ready. If the originating page disconnects or leaves, it stays pending for a person to send or discard. A server restart drops pending messages held only in memory. For a phone user who frequently switches apps, session creation and actual message delivery are therefore distinct states.

[S93]

A question card must still correspond to the current question

Supported approvals and questions become cards that are checked against the current terminal before submission. Version 0.4.13 labels a card potentially stale when screen reads keep failing, and refuses an answer if the subsequent read finds a changed question. Some newer OpenCode questions use the native background service; older versions and other prompts retain generic cards or the terminal. The release also fixes two Codex panes in one folder showing the wrong conversation and shares read completion status across browsers. My assessment is that this reduces opportunities to answer the wrong session, especially on a phone where multiple terminals are hard to inspect together. The release is not evidence that every agent format parses correctly. Uncertain session identity and unsupported transcripts still fall back to the terminal.

Self-hosted access still requires a host and configuration

The code and MIT license are public. Version 0.4.13 is an installable plugin release with no separate binary assets on that release page; remote-PC bridge bundles use their own remote versioning. Linux and macOS require herdr 0.9 or later, Bun 1.4 or later and Node 18 or later. Windows x64 does not need WSL, but its terminal currently uses a fixed-grid screen mirror with typing. Phone installation is a PWA and requires a network route to the host. Session files stay on the agent's PC and are served to connected browsers; agent model connections remain separately configured. Anonymous usage counts start enabled and can be disabled in About; voice and push features may contact external services. A free license does not remove host uptime, model bills or maintenance. Its strongest fit is someone already using herdr.
