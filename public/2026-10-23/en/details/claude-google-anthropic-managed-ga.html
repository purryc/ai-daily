A new platform route, rather than another model launch

On October 22, Anthropic announced general availability of Claude Models on Google Cloud under Anthropic management; its release notes also confirm Opus 5.5 fast mode on that route. Developers already using Google Cloud can retain its credentials, invoice and commitment drawdown while accessing Anthropic-operated APIs. The announcement lists hosted agents, files, code execution, citations and caching. Customer quotations are vendor case studies, not independent measurements. This is neither a consumer Claude chat subscription nor a rename of the existing Google-operated route. Prior Antigravity model-choice coverage is a different event. A date-only announcement is conservatively treated as supplementary.

One cloud bill can hide two different API surfaces

The comparison guide distinguishes routes by SDK and URL. AnthropicGoogleCloud calls claude.googleapis.com with project and workspace in the path, followed by a native Claude endpoint. Model selection stays in the request body, API version in a header, and streaming in a request parameter. AnthropicVertex instead uses Agent Platform prediction endpoints, with the model in the URL and version in the body. Both accept Google credentials and produce Google billing, but use separate permissions, rate-limit management and organization structures. Editorially, teams built around native Claude requests may avoid adaptation work; changing a brand label alone does not migrate an application.

Project permissions span workspaces; organizations do not convert in place

Setup creates a new Anthropic organization for the Google project; existing API or Enterprise organizations cannot convert in place, and their stored resources or ZDR arrangements do not carry over. Project roles span every workspace, so separate access requires separate projects. The IAM reference says Viewer can download files and read complete session histories but cannot send messages or count tokens. User adds workspace mutations; Admin adds organization permissions. Workspace IDs therefore locate resources rather than independently isolating team membership. Gradual migration is possible, but a successful activation does not mean existing assets and configuration have moved.

Broader capability still has explicit exceptions

Same-day feature availability does not erase documented exclusions: API keys, MCP tunnels, self-hosted memory stores and prebuilt self-hosted workers are unsupported, while restricted betas need access for the new organization. The Google-operated alternative excludes Files API, server-side code execution, web fetch, advisor, Agent Skills, MCP connector and Managed Agents, among others. Existing managed sessions and scheduled deployments also keep running after their creator's IAM access is revoked; stopping them is a separate action. These are documented capabilities and control semantics, not task-success measurements. No API call, paid activation or permission change was performed for this report.

Geography and data processor are separate choices

Anthropic is the new route's data processor, and some supporting services operate outside Google Cloud. Its URL location remains global; US-only inference uses inference_geo set to us in each request. The Google-managed alternative offers global, US/EU multi-region and regional endpoints under Google's data handling. Its regional availability is model-dependent: single-region endpoints serve Sonnet 4.6 and earlier models, while newer models use global or multi-region. Teams with location constraints therefore compare model availability, processing operator and geographic scope together. Paying through Google does not make these routes equivalent. The documentation does not justify broader compliance guarantees.

Fast mode buys output speed, not a task-time guarantee

Opus 5.5 opts in through speed set to fast without a beta header. Anthropic claims up to 2.5 times output-token throughput, explicitly distinct from time to first token; it does not promise equivalent acceleration of tool calls or complete tasks. Pricing is $8 per million input tokens and $40 per million output tokens, with caching and residency modifiers still applicable. Fast mode has separate limits and returns 429 with retry-after when capacity is exhausted. Evaluation-tier organizations need an eligible tier. Interactive writing or debugging may benefit more than asynchronous work, but that remains a workload-dependent value judgment without independent latency testing.
