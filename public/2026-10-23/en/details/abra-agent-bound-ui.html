Turn displayed content into an input surface

ABRA addresses an asymmetry in agent conversations: outputs can already be tables, graphs, or documents, while modifying them often requires describing the screen again in language. Its prototype places a shared canvas beside chat, with graph, table, text, and read-only display views. A person can edit a cell or connect graph nodes directly. The distinctive contribution is not another button but reusable actions whose meanings depend on the task. Connecting two nodes could express a project dependency in one context and a social relationship in another. The system stores these task meanings separately so they can be inspected by humans and by another agent. This makes the displayed representation part of the communication channel.

Separate gesture, action, and consequence

Views define elements and available actions. An agent binds those elements to task objects, enables actions, and publishes what each one means. Changes depending only on view state, such as selection or sorting, can run locally. Changes requiring task reasoning become consequences for the agent that owns the canvas. Another agent can read these meanings and invoke the published action rather than privately modifying the owner's data. The tool interface supports creating, reading, updating, and acting on canvases. This separates interface reuse from domain interpretation. However, publishing a semantic contract does not itself authorize an operation or guarantee the result matches user intent; making that contract understandable remains a distinct interaction-design responsibility.

A cell edit can express a broader convention

The tournament demonstration links player tables, a tournament graph, a gallery, and notes. When the user abbreviates Forward to FW in a cell, the agent treats it as a convention and proposes applying it across the column. An edge that violates tournament structure can be rejected by the owner agent. This demonstrates richer intent interpretation than a literal spreadsheet edit, while revealing a possible surprise: does changing one cell mean changing only that cell or proposing a column-wide rule? Shared referents can preserve identity across views, but the paper does not show that users naturally understand these consequences. My editorial inference is that displaying the affected objects beside an action may be more useful than expecting people to read abstract semantic descriptions.

Executable actions are not yet demonstrated user value

Evaluation separates canvas creation, owner-side consequence resolution, and cross-agent invocation, using 45, 33, and 33 cases respectively. Each case runs three times per model across four models, with only one response turn. Element binding reached 100%, while specification and meaning-following varied: some outputs misplaced configuration, and others merely repeated an action name instead of explaining its task effect. Cross-view referent coordination was also inconsistent. The authors explicitly have not evaluated human comprehension or improvement over chat. The readable GitHub repository identifies a BSD three-clause license, but the prototype was not installed. This is a promising interaction substrate for developers, with structural execution results that cannot yet be translated into faster or less error-prone everyday use.
