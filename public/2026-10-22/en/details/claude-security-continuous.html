Turn a scan into a lifecycle

The October 21 update concerns continuous work around findings, rather than the first appearance of Claude Security. It connects a baseline scan, subsequent code changes, issue state and team knowledge inside a project, reducing repeated scan initiation and comparison with old reports. Related repositories can share a project, which is relevant when a client and backend rely on each other’s checks. Anthropic says fixes are tracked against changed code and findings reopen when the issue returns. These are stated lifecycle capabilities, not independently verified coverage of every vulnerability. The job for a security team is closing an evidenced problem, rather than accumulating a longer alert list.

Concrete setup and handoffs

An administrator enables the feature, configures project-creation roles and grants repository access. A user creates a project from Security, selects repositories, branches and folder scope, and supplies architecture or deployment context. Findings present locations, evidence, reasoning and proposed repairs; Fix opens Claude Code, or the user copies a prompt into another setup. Authorized members edit the threat model in Knowledge so analysis can consider reachable attack paths. Folder scope is not an absolute data-isolation promise: the tutorial says broader code, including excluded folders, may still provide context. That distinction matters when deciding which repositories a project should be allowed to read.

[S03]

Fixed and dismissed are different states

The help page states that scans are stochastic and follow-up work has no fixed timetable. A fixed finding can reopen when detected again, whereas a dismissed finding does not reappear in later scans. A dismissal therefore needs an intelligible reason rather than an undifferentiated close button. Migration also has operational consequences: findings are copied into a new project and the original is archived, but members, webhooks, excluded directories, scan history and schedules do not carry over; GitHub Enterprise projects cannot migrate. Review owners, alert delivery and scan scope before and after migration. Otherwise a newer automation path could silently discard controls the team previously depended on.

[S02]

Judge adoption by closure cost

API, MCP and webhook connections can return findings to existing ticketing and development systems, with personal tokens limited by their owner’s permissions. This may reduce copying without establishing that status remains consistent across every connected tool. The service remains an Enterprise public beta, requires suitable seats and usage setup, and charges direct token costs for scans and project work. Promotional credits have eligibility, timing and new-project conditions and should not substitute for a long-term quote. Against static analysis, manual threat modeling and an existing repair queue, measure actionable findings, false-positive review minutes, regressions after fixes and migration omissions. More findings without faster verified closure would not establish a net operational gain.
