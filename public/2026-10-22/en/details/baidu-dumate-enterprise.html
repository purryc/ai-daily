The update and the job

The October 21 Hangzhou event adds computer and phone interface operation, a tender suite, task boards and an Agent security center to Baidu's enterprise offering. The enterprise edition and collaboration themselves are not new launches. A reporter at the event describes interaction with legacy systems that lack APIs, while the tender suite extracts requirements, reviews documents and identifies risks. Employees need an actual deliverable across files and systems; IT and purchasing teams need those actions to fit identity, budget and accountability processes. No tender or production task was executed for this issue. Event examples remain vendor and customer claims. Because the precise announcement time is unverified, this is conservatively a three-day supplement rather than an invented exact-time launch.

From accounts to execution

The existing onboarding documentation makes adoption concrete. An administrator uses a Baidu Intelligent Cloud account to establish an enterprise domain, configure authentication, create members and assign seats and resource allowances. Employees use separate enterprise member accounts; an account without a seat cannot sign into the client. A new task lets the user select an accessible local folder, attachments, default permissions, model and execution location. Cloud execution can continue while the computer is offline, whereas local execution uses the machine's files and environment. Previously, employees opened documents, copied information and operated tools individually. The proposed sequence first configures the scope of execution. It may reduce transfer work, while administration of skills, identity and quotas remains necessary.

Interruption is a state change

The task sidebar separates progress, files and invoked capabilities, exposing step status, intermediate outputs, tools and skills. One consequential interaction rule is easy to miss: sending an additional request during execution automatically ends the current task and starts a new one. That is not a parallel discussion that leaves the running work untouched. Branching from a response preserves earlier conversation and links back to the source task, but the documentation does not promise atomic reversal of changes in external systems. Scheduled work has controls for timing, model, permissions and local or cloud execution, with review of generated settings before confirmation and a history of runs. Acceptance should examine what finished before interruption and whether restarting repeats a submission.

Evaluate the complete delivery

At collection, the public enterprise page displayed a first-purchase promotion of CNY 132 per seat per month against a stated CNY 189 price. Additional resources cost CNY 10 per thousand points; a joint DuMate and Comate seat was CNY 138 monthly and excluded resources. The page was observed after the cutoff, checkout was not tested, and these amounts do not price every private deployment. Reusing deliverables, skills and knowledge is a hypothesis for reducing repeated explanation. Templates, existing RPA and native business-system automation remain alternatives. A representative recurring document task should measure completed delivery, review minutes, resource consumption and interruption repair. Faster interface operation fails the value test if people repeat every check or a changed request causes duplicate writes. Lower total delivery cost with traceable responsibility would support expansion.
