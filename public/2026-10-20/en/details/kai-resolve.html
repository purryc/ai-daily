Task and workflow change

Kai Resolve targets failures that first-line knowledge answers cannot explain, such as notifications missing for some users. Instead of support collecting fragments and sending engineering a vague report to reproduce, an investigation agent examines the ticket, recording, logs, account evidence and permitted code before answering or escalating. Official October19 documentation explains its handoff to Kai Code, while an October17 article explains triggers. These are recent workflow records, not proof of the product's first launch. [G1][G2][G3] PM inference: value should be measured by how many follow-up questions an engineer avoids. More code context alone cannot establish the customer's actual failure when a session recording or relevant logs are missing.

Control, uncertainty and human handoff

The investigation reads code without writing it and attaches file evidence. Decision cards can ask the team a bounded question and resume after an answer. Inconclusive should remain unknown, not become no issue. A proposed fix requires separate approval before a Kai Code session produces a PR for engineering review. [G2][G3] The October17 help also explains that enabled triggers may route an initial request for a person through Resolve once; another request after takeover goes to the team. [G1] PM inference: this handoff detail can determine adoption. Measure both investigation value and added wait for a human, so fewer escalations do not merely mean another barrier for someone explicitly asking for help.

Adoption cost and alternatives

Adoption depends on Gleap ticket workflows, SDK-captured evidence and deliberately connected repositories or data sources. Project-level triggers do not cover every channel in the same way; starting an investigation manually from any ticket is not universal automatic takeover. [G1][G3] Plan information is historically uncertain: an earlier marketing reading said Pro while help said Team; the live marketing page now says Team, but that cannot reconstruct the original cutoff's contract. No tier or price is promised here. PM inference: compare a knowledge agent with human escalation, a support engineer using logs and replay tools, and Resolve investigation on the same ticket. Where reproduction templates already work, extra investigation may add delay; the opportunity is a handoff that routinely loses cross-system evidence.

Falsifiable opportunity and visual evidence

PM inference: the falsifiable opportunity is an escalation an engineer can act on immediately. Use twenty historical issues with known outcomes, including expected behavior, missing evidence and permissions errors. Hide the final answers and compare diagnosis accuracy, unsupported bug confirmations, missing information and total resolution time. Check whether a rejected proposal preserves the investigation and whether customer follow-up waits for a release confirmation after merge. Fewer support messages do not count as success if they cause an incorrect fix. The help article provides an original UI image showing the handoff, Resolve identity and AI label. It establishes interface form, not customer-resolution success. Marketing filenames and test messages are not our execution logs; no repository was connected and no investigation started.
