Task and output

robot-data-diff compares local directories or Hugging Face dataset revisions, reporting episode additions, removals, statistical changes, task distribution and schema drift. An HTML report can carry a checkpoint label. It runs on CPUs with Python 3.10+ and Apache-2.0 licensing. Package 0.1.0 reached PyPI on October 13; this issue’s 24-hour event is the October 19, 21:38:27Z code observation, not a first release. [RDD1][RDD2][RDD3]

Reading the example and its blind spots

The actual HTML example reports 206 to 201 episodes: one added, six removed and five changed. Both inputs are labeled v3.0; the folder name pusht_v2 is a modified copy, not v2.1 validation. README limits v2.1 evidence to a synthetic fixture. The code fingerprint summarizes length, tasks, action extrema and means, idle ratio and spike count. A time-reversed sequence can therefore share a fingerprint, as can changes outside the summary. That is an inference from code, not a reported test. [RDD1]

Product analysis: use differences to direct investigation

PM analysis: the clearest user is someone whose policy deteriorated after retraining and who needs to know which recording to inspect first. An episode-level report narrows the investigation more usefully than file timestamps. However, no reported difference should not approve a dataset, and a reported difference does not establish the cause of a regression. I would attach the report to immutable dataset revisions and a checkpoint while holding the training configuration constant, then investigate code, sampling and labeling changes separately. A product should label unchanged as matching summary statistics and offer a path to inspect raw trajectories and frames. Missing statistics should appear as unknown rather than zero change. This is a proposal for the surrounding review workflow, not a claim that the CLI already supplies causal diagnosis or an experiment-tracking platform.

Alternatives and acceptance criteria

Alternatives include a custom Parquet comparison script, byte-level file hashes and a fuller quality validator. They answer different questions: semantic change, exact content change and rule compliance. A useful acceptance set would contain known edits such as deleting an episode, scaling actions, changing indices, reversing time, replacing only camera images, editing a task label and changing a trajectory while preserving its mean. Measure coverage, false alarms, misses, cold-cache download cost and report time. The adoption metric should be time until an engineer finds the first relevant difference, not the number of generated tables. Remote mode retrieves metadata and Parquet while excluding video, so initial transfer still scales with dataset size. If a regression arises from video-only edits, the investigation needs a corresponding image check. The tool can remain useful while its responsibility stays limited to directing that investigation.
