User and change

Exa 3.0 targets developers embedding retrieval inside assistants and operational applications. The release introduces the cheaper Lite search type and general availability of Dynamic Highlights. Published launch prices are four dollars per thousand Lite requests and seven dollars for Auto. Broader data coverage includes products, places and dynamic information. A useful product task is answering a location-specific opening-hours question with a source, rather than optimizing an abstract notion of smarter search. The announcement has an October 19 date only, so it is treated as a three-day lookback with an uncertain strict 24-hour boundary. Reported benchmark leadership and token savings remain vendor claims, not reproduced measurements. [exa-3-1]

From API request to user answer

The official getting-started examples submit a query through search, request highlights, and read each result’s title, URL and relevant passages. Those results then become evidence for the answering model. There are separate responsibilities for composing a query, selecting the right result, generating an answer and exposing supporting evidence. PM inference: a fluent sentence is not sufficient proof that retrieval succeeded, especially when businesses share names or sit near one another. An application should distinguish an unresolved location, sufficient evidence, conflicting evidence and no useful result. These are proposed interface states for the consuming product, not claims that Exa ships a complete consumer-facing resolution flow. [exa-3-3]

[S23]

What the cheaper mode gives up

The current API reference explicitly says Lite serves cached content and does not fetch live. It accepts only the documented parameter subset and rejects other parameters. Domain and publication-date filters are available, but a publication filter does not establish that underlying information was refreshed recently. Lite should therefore not be positioned as a cheap guarantee of live facts. PM inference: cached material can be adequate for stable background questions, while a temporary closure, sold-out item or live score may require fresher evidence or a visible uncertainty state. The reference also exposes authentication, billing and rate-limit error responses. No key was created and no paid request was made in this research. [exa-3-2]

[S22]

Alternative and validation

The immediate alternatives are keeping the existing Auto path or sending the user to the business’s own authoritative page. Applications that already have a reliable domain-specific feed need not add general retrieval to every question. PM hypothesis: route stable queries to Lite and escalate uncertain or time-sensitive ones; this is a proposed policy, not a demonstrated product benefit. Evaluate the same timestamped question set for correct-source selection, stale-answer rate, escalation rate, total latency and cost per ultimately correct answer. Manually inspect whether compressed highlights omit exceptions that change the answer. If cheap requests create more retries and correction work, the lower unit price does not justify migration.
