A native preview around an existing connector

Floot already offered an MCP connection in September. Its October 29 Product Hunt appearance instead emphasizes a native ChatGPT app: enable Floot in the sidebar or conversation tools, describe the application, watch an embedded live preview and obtain a published link. Floot provides the database, sign-in and hosting, while the chosen chat assistant supplies the reasoning. The date identifies this public presentation, not the first release of every full-stack feature. For someone tired of copying generated code between tools, requests and visual feedback are closer together. A complete-looking page still does not establish that registration, saved records and error handling work through the entire intended user journey.

Pointing to the thing that needs changing

The setup guide uses the ChatGPT app directory, followed by sign-in on Floot’s own site and activation through the tools menu or @Floot. It says actions request permission by default, and recommends an allow-all setting to reduce interruptions during a long build. That convenience should not be described as preserving a fresh confirmation before every publish or data operation. In the project view, selecting an element maps it to a source file and line; drawing an annotation saves screenshot context for the assistant’s next context check. It does not immediately execute the edit. An updating indicator identifies a lagging preview. The user still supplies the desired change and checks the actual flow on phone and desktop layouts.

Publishing separates code, not the database

Floot’s publishing documentation contains a consequential boundary: code changes remain in preview until the Publish button or an assistant request deploys them, but the preview and live application use the same database. Changes to rows or table structure take effect immediately. Deleting a record while testing a preview therefore cannot be assumed to affect only a test environment. Before exercising sign-in, forms and backend actions, the builder needs to identify whether the data is disposable and which table an operation changes. A code rollback should likewise not be treated as a promise to restore data. The integrated platform removes infrastructure setup while leaving application and database state on different version boundaries.

[S73]

No inference credits does not mean unlimited building

The promise that the chat subscription handles AI reasoning sits alongside a separate build meter. Reads, code writes, type checks, SQL and publishing count as tool actions; failed or cancelled calls do not. Those allowances differ from model tokens and application hosting consumption. Preview sharing has its own boundary as well: a token-bearing link permits interaction without Floot sign-in, normally expires after seven days and cannot be individually revoked early. Interaction access is not code-editing access, but it still matters when an application handles real business information. Builders should choose the sharing and data arrangement before inviting outside testers. The shorter path to a working draft does not establish the reliability of every generated application.
