Coucou 0.5.5 · Open source · release

Coucou keeps concurrent agents’ questions separate and reuses a Claude plan

One editor can contain several separate jobs

Two terminal windows or two VS Code windows can host unrelated jobs, so the application name alone cannot identify the one waiting for help. Coucou 0.5.5 retains grouping by tool while keeping each session’s title, steps and completion state. A session asking for permission or an answer temporarily receives a separate place, with its card and phone record attached to that session. It folds back after an answer, denial or timeout. Overflow is shown as an additional waiting count, with older requests kept visible. A completed task also gets its own result rather than disappearing behind a sibling that is still running.

Identical questions still need different destinations

The question queue allows multiple sessions to wait without a later question automatically sending the earlier one back to its terminal. Additional phone questions receive separate records, and replies are matched to those record identifiers rather than just the words of the question. Two jobs asking the same thing therefore require separate answers. The contributor notes that the existing iPhone application can display and answer the records, although some subtitles show raw identifiers until a newer phone build supplies friendly names. Permission prompts also retain their previous priority over question cards. These details matter when a compact notification surface stands in for several terminals.

[S52]

An existing subscription supplies the chat

Version 0.5.5 adds a specific routing rule for chat. If no Anthropic API key is saved, the GitHub build can call the already signed-in Claude Code and use the existing Claude plan; saving a key restores the API route. Release notes say each invocation excludes user settings, hooks and MCP servers and does not save a session. Ordinary chat may search the web. A dropped file instead goes alone into a separate folder for a reading path without web access. This removes a second API-key setup for that chat surface, while leaving the account’s own usage constraints and the App Store build’s key requirement in place.

[S50]

Remote jobs depend on a working relay

Remote support connects hooks on a Linux server to the desktop application through SSH, using a configurable socket and recognizing VS Code Remote events. The contributor documents both leftover sockets after a disconnect and a connection that appears present but never responds. Relay health therefore affects whether a request reaches the person at all; contributor timing reports are not guarantees for other networks. Coucou’s code is MIT-licensed, while its name, character and sounds have separate ownership. The current official demo illustrates the overall interface. This report stays with the dated 0.5.5 release and does not import October 30 main-branch features whose availability before the cutoff was not established.
