Transcribe speech before selecting passages

VClip separates cutting a long video into transcription, passage selection and export. Users choose a local interview, lesson or recorded stream. FFmpeg extracts audio, and speech recognition runs in a separate process so the editing interface can remain responsive. Silero voice activity detection first identifies speech segments, then SenseVoice or Paraformer converts them to text. Timestamped subtitles are divided into blocks and sent to an OpenAI-compatible endpoint. The model returns candidate titles, summaries, start and end times, scores and reasons. The maker’s illustrated interview of roughly ten minutes produces seven candidates; that is a demonstration, not a promised yield for every recording. Editors can read the reason and revisit the corresponding footage before keeping a passage.

Candidate boundaries still need visual review

Returned times must remain inside the relevant subtitle block. The application checks ordering, duration and fields before accepting a candidate. Without a model endpoint, or when an answer is empty or cannot be parsed, a rule engine combines subtitles using semantic boundaries, pauses and text length. This avoids an empty list but does not guarantee compelling clips. Separate subtitle and clip tracks let users move a passage, drag its edges, jump to a timecode or make frame-level adjustments. Hover thumbnails and a separate preview panel help check speech against the image. Timing also depends on recognition: when Paraformer lacks usable token timestamps, the program estimates positions proportionally from text and corrects them against speech segments. Those estimates are not measured word boundaries.

Export mode changes the timing and subtitle tradeoff

Before exporting, users independently select individual clips, a compilation, or both. A compilation follows the selected order. When only a compilation is requested, intermediate pieces go into a temporary directory and are removed afterward. Precise mode re-encodes the video for closer boundary alignment. It deliberately creates neither subtitle sidecars nor burned-in captions because the maker found that the changed time base could misalign original subtitles. Fast mode copies media streams instead of re-encoding, so keyframes can affect boundaries, and optional SRT sidecars are available. The complete transcript can also be exported separately as SRT, timed text or JSON. Failed fast concatenation falls back to re-encoding, while a failed compilation does not invalidate individual clips already exported.

Public source still requires local setup

The changelog calls version 0.3.4 the first public source version and says earlier versions were built locally. The repository currently supplies no installers, portable builds or speech-model weights, so readers need dependencies and a source build. Windows is the principal validated platform; a macOS packaging option does not establish tested operation. A separate public-account promotion offers a portable package, but that distribution was not verified here. The documented design keeps original media local while sending subtitle text when a remote endpoint is selected. Local Ollama can perform the language-model step, although initial dependencies and recognition models still need downloading. API keys remain in plaintext in the user-data directory after uninstalling. This is a subtitle-driven selection tool; transitions, grading and automatic vertical reframing are outside the current release.
