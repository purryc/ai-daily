Connect text requests to an execution tool

Clover is DiffuSpace’s released text model for coding, tool use and long-context tasks. Developers pass user requests and conversation messages through its chat template, optionally enable thinking, and receive text or code for their connected tools to execute. It builds on a Qwen3.6 mixture-of-experts backbone, with 35 billion total parameters and roughly three billion active per token. Prompt and response share the context budget. The company demonstrates browser work and a single-file interactive desktop, but the model card explicitly describes a text-only model; those demonstrations do not establish native image input. The practical entry point is downloaded weights and an inference program. Online access requires an application, while a dedicated client and harness remain in development.

Resolving positions within a block

The Hugging Face implementation begins with a block of masked positions instead of fixing only the next token. Each pass fills positions whose confidence exceeds a threshold. If none qualify, it fills the most confident position to keep moving. A completed block joins the causal prefix before the next block begins. Defaults use thirty-two positions and a confidence threshold of 0.95. Added bidirectional attention lets positions within the current block inform one another while preserving the completed prefix. Developers can override generation settings. Long outputs may repeat, so defaults include repetition penalties and gradually increasing preferences to end an answer or thinking phase. These are soft controls; max_new_tokens remains the hard cap. Faster settings therefore also need completeness checks.

Available code and upstream support differ

The official Python example loads custom model code using CUDA-capable PyTorch and Transformers. BF16 weights require approximately 69 GB before inference state, so activating three billion parameters per token does not mean storing only three billion parameters. The repository also links SGLang and llama.cpp adaptations. Both upstream pull requests are currently open: developers need to check the linked implementation rather than assume the latest standard package contains support. In SGLang’s self-speculative path, one model proposes and verifies draft blocks, retaining the accepted prefix; the llama.cpp proposal likewise needs no separate draft model. Fine-tuning code is still marked as forthcoming. Numerical differences between backends can also produce different text even when decoding settings appear identical.

Generation speed is not complete task time

The company’s speed figures come from specified hardware and workloads. Its internal agent dataset reaches 680 generated tokens per second on one GB300 using BF16 at batch size one. That is a vendor observation for a particular inference setup, not the time a reader’s computer will take to finish a browser task: tool calls, page waits and recovery also consume time. Separately, the model card distinguishes selecting fewer experts within a block from reducing loaded weight size; the former can trade quality for computation without shrinking the checkpoint in memory. Integration should therefore check complete answers, tool compatibility and whole-task duration. The released preview weights are available; the decision model, multimodal expansion and dedicated client remain separate future work.
