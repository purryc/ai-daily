Starting small no longer locks in the library

A user of version 0.2.1 found that installing Essentials removed the option to install Everything, and vice versa. The workaround required quitting, moving the library away and reopening setup, leaving no usable library while its replacement downloaded. Version 0.4.0 puts switching behind the article count and Library window. The existing collection remains available until the replacement is ready. Someone who initially chooses the smaller download can therefore expand later, while somebody short of storage can move back to a smaller package. The maintainer links the change to that report; it establishes a specific workflow fix, without proving every possible interrupted-install case.

Personal documents can stay on another drive

Another issue began with a complaint about library files occupying the home directory. A second participant explained that personal documents lived on another drive and could not be copied onto the boot disk. The update separates those choices: the library can move to another folder or external drive, while Your files can point directly at an existing directory and search it without duplicating its contents. New installations use the application’s own data location; existing installations keep their location. For a collection of manuals and notes, this avoids an unnecessary second copy and separates application placement from document storage. The chosen drive still needs to be accessible when used.

A failed download should identify the component

First-run setup now combines library and model selection, suggests a model for the machine’s memory and shows download speed and remaining time for each component. Downloads can resume after quitting. A Mac report exposed a different ambiguity: Survival LLM prefers an already-running Ollama instance, whose older version may not support the requested model even when the user expects the bundled engine. The maintainer says 0.4.0 identifies the engine in use, explains the next action and wraps long errors so the message fits. That gives a stalled setup an identifiable cause instead of making the user guess whether the model, library or application is broken.

A broken window cannot update itself

A Windows user reported opening into a broken main interface without the expected setup and model selection. From the supplied screenshot, the maintainer attributed it to missing WebView2 and an older rendering engine. Version 0.4.1 installs the missing component with Microsoft’s installer. There is a practical recovery catch: the broken window cannot run the in-app update, so the maintainer directs affected users to download the new release again. The product still combines offline retrieval with generated answers and linked articles for checking. These installation and storage fixes provide no new accuracy evidence. Hackaday’s October 29 coverage is an independent discovery source, not a hands-on retest.
