Start with an element and a testable question

A developer checking whether a form works from a keyboard needs more than a screenshot. Focus may lack a visible outline, while an error message may appear only after submission. InterA11y starts with a page and an accessibility success criterion, identifies candidate elements, and breaks the criterion into questions about required evidence and decision rules. The model can collect observations for one element across several turns. Hidden elements can be excluded early, and conclusive cases such as missing alternative text use deterministic checks. The remaining semantic and behavioral cases go to the model. This changes how a tester gathers evidence and investigates suspected problems; the system is an evaluator, not an automatic page repair tool.

Capture the state that changes after interaction

The 46 tools cover programmatic inspection, rendered images, measurements, input actions and response monitoring; 24 concern interaction or monitoring. An agent can inspect a grayscale rendering to test whether color alone conveys meaning, or operate controls to obtain focus appearances and error messages. The implementation includes a Guidepup virtual screen reader, which is not equivalent to validation across all real assistive technologies. A harness manages browser resources, collected evidence and model context. Thirty-five rubric items cover ten selected success criteria, including 24 items newly developed by the authors. Tools and rubrics work together: giving an agent generic browser controls does not by itself tell it which behavior matters or what constitutes an accessibility failure.

What the comparison actually measures

The authors developed the approach on 682 curated conformance cases, then sampled elements from 54 pages across 48 websites. The final expert-annotated collection contains 197 cases: 107 positive and 90 negative. On that collection, mean recall was 79.0%, versus 44.4% for the strongest evaluated language-model baseline; precision was 93.1%, near the stronger rule-based checkers. Recall here means the share of labeled problems found in this collection, not coverage of all accessibility problems on the internet. Supplying the specialized tools to AgentLab and Browser Use also improved results. These are author-run comparisons, and the selected elements and ten targeted criteria define the scope within which the figures should be interpreted.

Return to the live workflow after screening

The evaluation uses offline copies of page code and resources. Elements requiring dynamic server content were excluded, and authenticated functionality remains future work. A passing copy therefore cannot establish whether a payment flow, account transition or live service response is accessible. The authors report 109 seconds per case on average, and interactive evidence gathering uses more tokens than static language-model checkers. These are research configuration costs, not a service price. A product team could use the approach to expand reproducible defect leads, then examine their effect on real tasks. Presenting evidence to testers and integrating it into continuous integration are directions discussed by the authors, rather than demonstrated delivery of a complete production testing platform.
