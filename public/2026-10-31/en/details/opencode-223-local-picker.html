OpenCode fixes local models hidden by a mistaken release date

The model exists behind an empty picker

An October 30 report concerns OpenCode Desktop 2.2.0 on Windows with local Ollama. The active model appeared in the composer and worked when selected through the API, including tool calls. Yet the model dialog omitted the Ollama group and its search could not find the model. The reporter checked the catalog returned by the same service, then restarted both application and service and reloaded configuration without restoring visibility. This narrows the complaint to selection: someone trying to change an already installed model had to leave the ordinary picker and set a default or use an API. It does not demonstrate a failure of Ollama inference. The distinction matters when diagnosing setup.

[S71]

An unknown date looked like an obsolete model

The patch identifies a small conversion with a large interface consequence. The server used a zero release timestamp to mean that no date was known. The client formatted it as January 1, 1970. Because the picker normally filters older releases, local or configured models disappeared; searching only the visible set could not recover them. The change keeps the date unknown and lets the existing visibility fallback handle it. Known dates, deprecated-model filtering and explicit user show/hide preferences retain their behavior. No new model or inference endpoint is involved. The correction concerns how catalog metadata is interpreted before a person can make a selection.

[S72]

The fix has a published version

The 2.2.3 release explicitly lists the unknown-date visibility fix, with an original publication timestamp of October 30 at 09:55:45 UTC. A later issue still concerns 2.2.0, and its automated response says the patch is only on the development branch and absent from 2.2.4. That statement conflicts with the published release evidence and should not be repeated as current status. Further versions had appeared by the cutoff, but older installations do not thereby become updated. Checking the desktop version is more useful than repeatedly restarting it. A reproducible failure after updating needs fresh version and catalog evidence; not every missing-provider symptom necessarily has this cause.

The workaround changes metadata, not the model

The reporter subsequently confirmed that adding releaseDate to each configured model and reloading made it appear. This supplies recent metadata to avoid the filter; it is not evidence of the model’s real publication date, and the temporary value should not become a lasting factual claim. Official documentation also supports a provider/model identifier as the default, preserving a selection route when the menu fails. The older related thread contains reproductions across versions, rather than a clean count of independent incidents. The evidence establishes a specific filtering defect, a traceable patch and one reporter-confirmed workaround. It does not establish what share of the entire user population was affected.
