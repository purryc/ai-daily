Call models from an existing agent

Google’s October 27 changelog introduces gemini-api as a beta client for the Interactions API. Existing coding agents, scripts and CI jobs can request text, images, speech, music, video or managed-agent work through shell commands. The host retains responsibility for planning, choosing inputs and using results; this client submits a particular request to the service. It is a separate product from the interactive Gemini CLI coding agent, so their capabilities and access arrangements should not be conflated. Google provides standalone binaries for macOS, Linux and Windows. A project can therefore call models without adding a language SDK dependency, although credentials and access to the remote service are still required.

Return paths and identifiers to the workflow

Media commands write files to disk and return paths or structured metadata, keeping large encoded assets out of the agent’s context. A page-building workflow can generate an image and pass its path into application code; transcription can produce subtitle or structured text files. Video generation can return an interaction identifier asynchronously and resume retrieval later. Managed research likewise exposes background execution, status retrieval and cancellation. Because invocations do not rely on a hidden local session, callers must preserve file references, previous-interaction identifiers and background-job identifiers explicitly. A process exiting is not the same as the business workflow finishing: the host must inspect status and artifacts before advancing or retrying.

Discover the schema before sending requests

The command tree and request schemas are available locally, allowing an agent to inspect usage or JSON Schema before constructing a request. Dry-run mode validates inputs, redacts credentials and shows the resolved HTTP request without making a network call. Normal execution supports JSON, compact structured output and field filtering, while exit codes distinguish authentication, validation and runtime failures. When command flags and a raw request body set the same field, the client rejects the conflict rather than silently choosing a value. These features reduce integration work; they do not decide whether a task is appropriate. The calling application still controls permissions, input scope and expenditure before submitting the request.

File size and protocol define the boundary

Current documentation caps inline files at fourteen megabytes of raw data. Larger inputs should be uploaded through the Files API and referenced afterward; those uploads expire after forty-eight hours, so their identifiers are not permanent asset URLs. The client supports ordinary HTTP, server-sent events and asynchronous polling, but not bidirectional WebSocket sessions. Live voice or video should use the Live API and SDKs. Beta minor releases can introduce breaking changes, making pinned versions and checks on stored command and output contracts useful for automation. Open-source distribution of the client also does not make model calls free: available models, quotas and charges depend on the corresponding API account.
