Inspect the source page beside the parsed document

Finding an error in a parsed PDF often means returning to the source page and locating the corresponding region. X-AnyLabeling’s October 30 integration of Unlimited-OCR-2 brings image and PDF parsing into its existing document panel. The user configures the remote server address, opens the PaddleOCR panel, selects the parsing model and starts a new parsing job with a file. Source pages remain beside structured output. Page controls and selectable blocks help inspect the matching region, after which individual blocks can be corrected, copied or exported as a document or JSON. This is a document-panel workflow, separate from prediction in the main annotation window. Official screenshots demonstrate a two-page PDF, article layout and a table; they do not measure recognition accuracy.

Cross-page tables retain their connection

The client renders PDF previews locally and sends the ordered pages together as one document request. It does not run unrelated recognition jobs for each page. Results contain content categories, coordinates, page dimensions and global block and group identifiers. Continuing text or tables across pages share a group, while document-level Markdown can merge table fragments. Unlimited-OCR-2 uses sparse-reference sliding-window attention to retain a bounded set of working references for long-document decoding. For somebody preparing reports or datasets, the integration reduces the need to guess which exported table fragment continues from the previous page. It still leaves that association open to inspection: page-local blocks remain available so reviewers can examine the pieces as well as the merged document.

Long documents need the matching inference service

The desktop interface does not automatically run the model on the user’s computer. It connects to X-AnyLabeling-Server, which can load pinned weights through Transformers or use a customized SGLang backend. Native inference requires a CUDA GPU and is bounded by context length and available memory. Longer documents can use SGLang page windows with retained context between windows; larger windows also consume more memory. The maintainers explicitly say that a stock SGLang release lacks this document-window implementation. The endpoint receives page images rather than PDF bytes. It scales the per-page output budget by page count and rejects truncated output or mismatched page counts. Opening a file successfully is therefore distinct from successfully completing the entire document.

Edited results and original output remain distinct

Ordinary block-based export retains manual corrections. The document JSON also keeps the model’s original, cross-page-merged Markdown in a separate top-level field, which is not automatically rewritten after block edits. A downstream knowledge-base integration must choose the appropriate representation or risk reintroducing text that a reviewer has already corrected. Cancellation has a separate boundary: it ends client-side waiting while inference already running on the server may continue. The guide even documents a handwritten E recognized as S in its formula example; the integration does not silently alter that prediction. The desktop project uses GPLv3, while the model has its own license. This is a practical source-review-and-correction workflow, not a promise of unattended recognition accuracy.
