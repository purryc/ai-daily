A background display with a visible preview

Mika takes a task goal and opens an app on a separate background display, where it reads, taps, types and scrolls. A small preview in the conversation shows its steps while the user keeps the main screen. Where interface text is unavailable, bundled OCR can read visible text; a configured vision model can additionally interpret screenshots. Web tasks use an embedded browser, and file work uses a local Linux sandbox with downloadable results. These are disclosed execution paths, not proof that every app works. The project remains an early public beta, primarily tested on one Android 14 phone; other manufacturers’ background policies and interface implementations remain relevant uncertainties.

[S08]

Interruptions preserve what the reader saw

Version 0.1.16 in the same update sequence improves mid-response steering. Sending another message while text streams leaves the already displayed passage above it, dimmed and labelled as interrupted, and tells Mika what the person has seen. That reduces the need to reconstruct the previous response; it does not undo external actions already taken. The release also extends non-phone tasks to Android 11 and phone control to Android 12. Background operation on Android 12 and 13 can still affect main-screen focus, so the author prefers 14 or later. Reasoning effort can be set separately for main, vision and lightweight roles on supported sign-in or Responses configurations, remaining unspecified by default.

[S06]

The computer delegates a goal to the phone

Version 0.1.14 adds a computer-started MCP connection. Over USB, a desktop AI tool submits a goal with a token, receives a task identifier, checks or waits for status changes and retrieves the result. Cancellation is a separate operation. The computer specifies the desired outcome, while the phone agent chooses between app, browser and file tools. USB listening is local to the handset and reached through port forwarding; Wi-Fi or private-network access has a separate, initially disabled switch. Phone-only steps require takeover on the handset and cannot be approved from the computer. Rebooting closes USB access and rotates its token; reconnecting the cable may also require forwarding to be restored.

[S07] [S09]

Easier updating and a specific confirmation policy

Version 0.1.18 moves update downloading into the app, shows progress and checks package size, checksum, version and signature before installation. It adds Simplified Chinese, Traditional Chinese and English choices and aligns sandbox commands with the phone’s timezone. The confirmation policy needs separate attention: default Ask mode asks before ordering or paying, but can send, submit and delete directly; Autonomous mode also skips the spending question. Computer-originated tasks have additional handset confirmation rules, so the two paths should not be conflated. Model requests still reach the configured provider; a background display does not mean offline inference. Small, inspectable tasks provide a practical way to judge the execution trace, confirmation settings and actual result.
