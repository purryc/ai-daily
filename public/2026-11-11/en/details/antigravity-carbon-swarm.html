Task ownership is visible

A developer enters /swarm with a task that can be split across files or questions. A coordinator assigns named workers, while verifiers inspect changes and tests. Briefs, questions and results appear on a shared board, reducing the need for one conversation to paraphrase every handoff. The useful target is a migration, investigation or multi-package repair with separable ownership. A small single-file edit may gain little from the coordination overhead. The feature is a preview announced alongside Gemini 4 Carbon; its demonstrations are not measurements on a reader’s repository.

Three views for steering work

The Board explains the sequence of discussion, Members shows who is active or waiting, and Graph replays mentions between agents. A terminal board provides another way to follow the work. The human can open a worker’s conversation to clarify a requirement or respond to an approval request before the whole task finishes. That makes misunderstandings easier to catch: a verifier may be testing an old requirement, two workers may own the same module, or one may be waiting on access. A busy graph is evidence of communication, however, not evidence that a patch is correct.

Workspace and model choices matter

There is a material detail in the documentation: workers share the workspace by default, and the coordinator can give concurrent editors separate working copies. The launch description emphasizes isolation, so universal automatic conflict prevention should not be assumed. Workers also inherit the conversation’s model unless a different available model is requested. Carbon access and swarm access are separate: the documentation lists Pro and Ultra for swarm, while Carbon rolls out through paid API/business access and Ultra surfaces. Active workers consume quota faster. Zero-token waiting does not make the overall task free or guarantee that parallel execution costs less. Google says Carbon usually uses more tokens than Argon for longer reasoning; this is a vendor comparison, not a measured cost guarantee.

Check the cost of coordination

An inexpensive evaluation would compare a two-module change against a single-agent run using the same acceptance criteria. Record repeated edits, human corrections, total tokens and waiting time as well as the final test result. Have the verifier inspect interface boundaries independently instead of repeating the worker’s success message. If ownership is unclear and merges dominate the work, reduce parallel scope. If the bug concerns one shared state, more agents may simply create more disagreement. This is a proposed test, not a hands-on result. The notable interaction change is that coordination becomes something the user can inspect and steer, while reliability still depends on decomposition and meaningful repository tests.

A separate preview in cloud notebooks

A separate November 10 Google Cloud preview brings Antigravity CLI to Agent Platform Workbench instances using Debian 12 or newer images. New instances enable it by default. It can work with notebooks and kernels, and %%agy converts a description into cell code. File edits and commands require approval, and instance metadata can disable the feature. This does not establish automatic upgrades for every older instance or imply that model usage is included in a virtual machine price.
