A chat request needs a phone acknowledgment

Clive turns a request such as a morning wake-up into an iPhone alarm rather than a promise in a conversation. A remote MCP connector links the assistant to the app. Pairing uses a four-word code followed by matching confirmation words and approval on the phone. The assistant can then manage the alarms it created. Inside the app, a character plays one of three instruments; a plain list is available for people who prefer it. That playful presentation is separate from scheduling reliability. When a request contains several times, the user still needs to inspect the resulting dates and time zones rather than infer success from fluent assistant text.

Queued, armed and heard are different outcomes

The help page distinguishes a queued request from an armed alarm after the device confirms scheduling. Changing the time queues it again. Armed does not mean anybody heard it. Already scheduled alarms execute through iOS, while new requests and changes need the server. Repeating schedules keep up to two weeks on the phone and need later replenishment. A fallback notification may be attempted when confirmation is missing, but is not proof of successful scheduling. This makes an unusually concrete agent boundary visible: the assistant’s intention and the device’s acceptance are separate events. A product evaluation should test interruption between them, rather than only the successful connected path. The fallback requires notification permission and an online phone, and can arrive late.

The service has platform, quota and regional limits

An iPhone running iOS 26 or later is required. The free tier allows five active alarms, counting a repeating alarm once; Pro raises the limit to 100. The US store lists $1.99 per month with automatic renewal and country-dependent pricing. The help page separately describes a default of 20 creations per assistant per 24 hours, adjustable from 1 to 50, so capacity and request rate should not be confused. Launch availability is regional: the policy explicitly excludes Japan, Mexico, the EU, EEA and UK. A regional privacy section does not prove its storefront is open. Version 1.0.1 simplifies connecting Claude, but its relative store timestamp is insufficient to assert an exact release instant.

Local speech recognition does not make the whole service local

Speech transcription stays on the phone according to the policy, but alarm text, timing, repetition and status go to the service. Clive receives tool requests rather than the whole assistant conversation; the assistant provider remains a separate data handler. Removing app data does not cancel the Apple subscription, and uninstalling alone does not immediately erase the active server record. The developer explicitly warns that setting or ringing can fail and recommends Clock backups for alarms that cannot be missed. A nonessential trial can examine permission, cancellation synchronization and returned status. Merely using AlarmKit does not establish end-to-end reliability, and this review did not run such a trial.
