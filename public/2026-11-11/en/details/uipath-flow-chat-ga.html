The conversation continues while its handling path changes

UiPath made chat agents built on the Maestro Flow canvas generally available on November 10, alongside the existing single-prompt Agent Builder route. End users still reach a Conversational Agent, allowing an organization to change the handling workflow without requiring employees to find a different chat entry point. The flow route supports conditional routing, specialist-agent handoffs, fixed messages and parallel automation. Voice agents remain preview; chat availability should not be extended to them. The change concerns composition and execution structure rather than a new model, and it does not establish an accuracy improvement for every customer deployment.

A handoff depends on an output, not just a promise

The official tutorial uses an IT helpdesk. A Conversation Trigger starts the flow, Wait for Message supplies current context, and a general agent produces a turn plus a Boolean indicating whether an account specialist is needed. A Decision node either returns to the original conversation or sends a deterministic handoff notice before entering the specialist’s own wait-and-reply loop. That fixed notice does not require generation by an LLM. The structured output’s description also informs the agent’s classification. Correct wiring establishes a route; it does not itself authorize an account reset or prove that a tool completed an operation. Those responsibilities still require configuration and checking.

Multiple waiting points can expose stale context

The tutorial warns that a flow with several Wait for Message nodes can accidentally give a later agent stale context from an earlier waiting point. It suggests maintaining a flow-level context variable, updating it after each wait, and reading that shared value downstream. This determines whether the user’s latest correction actually reaches the next decision. Parallel branches can launch an approval form while conversation continues, but parallel execution is not automatic approval or proof that every branch succeeded. The debug view should reveal the agent handling each turn, its routing output and how errors or completion return to the conversation. Users need not see the nodes; maintainers need traceability.

Deployment access and consumption are separate questions

Supported surfaces include Assistant, Teams, Slack, web embeds and SDK-based applications, but channel configuration and access identity still need their own setup. Licensing documentation separates conversational executions from the Maestro Flow that hosts them, and some tools incur additional consumption. A deterministic message therefore does not imply that the complete service is cost-free. Development and debugging can also draw from usage allowances depending on the plan. No unknown cash unit price is inferred here. An adoption check could compare an ordinary question with one requiring handoff, inspecting context continuity, human approval and recorded consumption. This research read the official tutorial without deploying or signing in to the product.
