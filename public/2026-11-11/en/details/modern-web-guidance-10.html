Start a maintenance task with a concrete old pattern

Modern Web Guidance 1.0 was announced as stable on November 10. It supplies coding agents with web-platform practices and browser-compatibility information. Its new modernization workflow starts with an existing repository or directory and looks for recognizable legacy HTML, CSS, JavaScript and dependency patterns, instead of asking a model to rewrite an application wholesale. Developers can request a plan before code changes. Guidance uses Baseline compatibility information and should be applied against the project’s actual browser targets. Firefox and Edge are joining the effort, but cross-browser participation does not make every recommendation appropriate for every customer environment or automatically certify accessibility.

Local scanning and model review have different jobs

The documented first stage uses local syntax-tree, DOM and CSS parsers, without an LLM call in the scanner itself. Findings include conditions for keeping or dropping a match. The agent then checks surrounding code: a scrollHeight read might support virtualized scrolling rather than textarea resizing, and an intentional compatibility fallback should not be removed mechanically. Deterministic rules cover only part of the guide collection, so an empty result is not proof that the rest of a codebase is sound. There is deliberately no blanket fix flag because moving behavior among JavaScript, HTML and CSS can alter interactions. The initial output should be a set of inspectable, contestable findings.

Less code is useful only if the interaction survives

Examples include replacing an imperative popover click listener with declarative controls and preventing Enter handlers from sending a message while a person is still composing Chinese or Japanese text. These are observable interaction issues rather than an abstract preference for newer syntax. After retrieving the relevant guide, the agent makes a change and reruns scanning alongside project tests. The documentation offers the skills to multiple coding agents rather than restricting them to one IDE. A team must still define editable scope, progressive-enhancement requirements and review responsibility for changes crossing application layers. Installation instructions describe the product; this research installed nothing and performed no code transformation.

Browser observation remains a separate check

Google recommends pairing guidance with Chrome DevTools for agents: one provides implementation and compatibility advice, while the other observes runtime behavior, performance and accessibility structures. A static refactor that removes a dependency can still regress on a slower device, keyboard navigation or animation preferences. A practical first use would select a small component with a clear legacy pattern, preserve before-and-after inputs and outputs, and check browser behavior before expanding the work. The public evaluation dashboard was inaccessible in this research, so no live score or cross-model improvement figure is adopted.
