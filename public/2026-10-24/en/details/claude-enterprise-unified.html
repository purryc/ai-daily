The request no longer needs a product choice

An employee might first ask which sales opportunities slipped, then request a report and five slides. Previously that could involve deciding whether to remain in chat or move into Cowork and carrying context across. The unified Enterprise experience starts with a conversation and opens a cloud session when files or code are needed, returning the resulting work to the same thread. Pro and Max began receiving this arrangement in September; the new event is Enterprise availability and its management controls. Existing projects, connectors, skills and plugins carry over. The useful interaction change is continuity for one piece of work rather than requiring employees to understand the product’s internal division of labor.

Cloud continuity has an expiry

Cloud execution means closing a laptop does not itself end a job, and the employee can continue from web or mobile. The setup guide adds an important lifecycle detail: a conversation gets an isolated virtual machine when needed, idle machines stop with encrypted disk snapshots, and the environment expires thirty days after creation. Conversation history, export and retention operate at the conversation level. Disk lifetime and chat retention are therefore different things. Local folders and applications remain optional connections governed by remote-control and device policies. Being able to supervise a task from a phone does not automatically make every file on an office computer available to that task.

Rollout depends on capabilities and roles

The announcement does not switch every organization immediately. Existing organizations start with the capability off; owners can enable it early or keep it disabled. For organizations without an explicit choice, automatic enablement from November 16 also requires Chat and cloud code execution/file creation to be enabled. Standard roles and custom roles follow different entitlement paths, so a staged rollout needs a role review. Organizations using zero data retention, the HIPAA-ready configuration or customer-managed encryption keys cannot enable this version yet and retain their existing configuration. IT therefore needs to communicate access and data boundaries, not simply announce a refreshed interface to every employee.

Usage reporting changes with the experience

Billing remains usage-based, and an extended task can consume more tokens than a short answer. Efficient mode limits this experience to Sonnet and Haiku, starting new sessions on Sonnet 5.5 at low effort; it does not change other products. Organization, group and member spending limits still matter. Reporting also gains a unified product category while historical usage keeps its earlier labels. Summing only the old Chat and Cowork fields can consequently create an apparent decline that reflects migration rather than reduced use. Administrators need to include the new category and avoid adding product-level active-user counts as if each represented different people. Simpler employee navigation creates a separate reporting handoff for the organization.
