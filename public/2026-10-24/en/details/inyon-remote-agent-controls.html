The phone connects to the existing session

A coding agent can still be running tests, editing files or waiting for approval after its developer leaves the desk. Inyon connects the existing session to an Android application or browser, retaining the agent, account and working directory on the computer. After pairing, the user can inspect chat, terminal output and diffs, answer the agent's question, and send the next instruction. An optional hub organizes multiple computers; a direct server path requires tmux and the relevant agents. The model does not need to move onto the phone. The phone supplies a remote interaction surface for work already happening elsewhere.

Stable answer controls reduce moving targets

One concrete change keeps session cards stationary as agents work. Answer controls stay in a fixed footer, while new activity waits behind an “N new” button. On a small screen with several agents, a constantly rearranging list can interrupt reading or put a different control beneath a finger. Stable positioning does not decide whether a command should be approved; it gives that decision a more consistent visual target. The release does not measure accidental taps or time saved, so the change should be understood as an interaction improvement with an explicit mechanism, not an independently demonstrated productivity result.

[S61]

Pairing includes a device identity check

Version 0.20.2 shows the hub address, name and ID after a pairing code is scanned or pasted. When the hub serves HTTPS itself, the screen also displays the certificate's SHA-256 fingerprint. Nothing is saved until the user taps Pair, and the computer prints its ID for comparison. Android tokens move to storage encrypted with a Keystore-protected key; browser tokens use IndexedDB with a non-exportable encryption key. A subsequent release makes machine-joining commands single-use. These changes concern connection and credential handling. They do not make all coding data local, because the chosen agents can still call their own model services.

Closing the window does not stop the connection

On Windows, Inyon now appears in the Start menu, Settings app list and system tray without repeatedly opening console windows for connections, updates or uninstallation. Closing its window leaves the phone link, tunnel and hub connection running in the tray. Quit Inyon stops them, with status and stop commands retained for terminal users. That distinction matters when leaving the computer: a disappeared window does not mean the remote session has ended. Versions 0.20.4 and 0.20.5 then correct installed-version reporting and updating, ensuring that the application itself restarts into the new version rather than only restarting its managed connections.

It removes a trip back to the computer

Remote desktop software can reach the same computer, but manipulating terminal windows and finding output on a phone can be cumbersome. Copying the conversation into a separate mobile assistant instead loses the working files and live terminal state. Inyon exposes the session, diff and pending question directly, making it useful for continuing an existing task during a short absence. It also supports actions such as committing and pushing, so it is not merely a read-only monitor. The MIT license does not include model services. An iOS application was not established, and recovery and permission behavior across every supported agent remain untested here.
