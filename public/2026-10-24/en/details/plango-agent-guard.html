File boundaries live where files are managed

Plango’s October 23 Product Hunt discussion describes a tangible way to set boundaries: Finder color tags can mark folders as inaccessible, read-only or requiring a question first. The user can express a rule where files are already managed instead of repeatedly explaining which private directory or credential lies outside the coding task. Tags are the interface; enforcement still depends on Plango intercepting the relevant action. Agent protection was described in an October 16 company post. The newer evidence is an October 22 explanation of MCP attack paths and the subsequent launch discussion, not a first appearance of the security product yesterday.

Rules set the floor for model judgment

The feature documentation lists commands, file reads and writes, web fetches and MCP calls as inspection targets, with a log explaining allowed and blocked actions. Protect mode blocks High and Critical ratings; Strict also blocks Medium. A small model runs on Apple Silicon after fixed rules establish severity, and can raise a rating but cannot reduce it. That ordering prevents a reassuring model interpretation from overriding a rule’s existing floor. It does not establish comprehensive detection. For a developer, an explanation tied to the actual requested operation is more useful than an undifferentiated alarm, particularly when a legitimate build stops and needs investigation.

Watching tool definitions after installation

The October 22 technical article adds change detection after installation. Plango fingerprints tool lists and marks a previously trusted server Changed when that list changes; replaced plugin files are also flagged. Inspecting names, descriptions and argument descriptions targets instructions concealed inside an apparently ordinary tool definition. Managed MCP servers can additionally use a sandbox to restrict direct access to credentials and browser data. Skill inspection examines text and hooks an agent might follow, while the secrets feature finds environment files and offers migration to Keychain. These are separate supplier-described control points, not an independently established claim that all prompt-injection paths are stopped.

Local analysis still needs permissions and network distinctions

Plango requires Apple Silicon, macOS 15 or later and at least 16 GB of memory. Its seven-day trial needs no card and does not automatically convert; the $4.99 monthly subscription covers one Mac at a time. The application itself needs relevant system permissions, and disabling them stops corresponding protection. The privacy policy separates local security analysis from account, license and update traffic. Vulnerability lookups may send package names and versions to OSV unless local mode is selected, while an optional external AI receives the context supplied to it. Consolidating inspections reduces scattered work but also concentrates trust in a resident security application. False-positive rates and sustained performance overhead remain unmeasured here. After uninstallation, migrated Keychain entries and configuration backups may still require manual removal.
