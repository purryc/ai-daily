Write the explanation before laying it out

Reading a complicated answer often means drawing its arrows yourself or copying alternatives into a comparison table. Answer me with HTML asks the existing agent to write a compact Markdown draft, then lets a local command-line renderer calculate the page layout. A network explanation can put message order, state changes and a flag table beside one another. A decision can expose comparable conditions in adjacent panels. The tool is not another question-answering model: the user’s existing agent still supplies the explanation. Giving layout to code avoids having the model invent every SVG coordinate, but a neatly drawn arrow can still express an incorrect causal claim.

A real-session draft exposed a silent formatting failure

Issue 335 records a concrete failure in the author’s own session. An agent used triple-colon blocks, a familiar convention in documentation tools, for callout and flow components. The earlier checker raised no warning, yet the renderer displayed the markers and their contents as ordinary prose. A file had been produced, but the intended diagram had disappeared. Version 0.5.9 first made this an explicit error and supplied a corrected example. That made the missing structure visible instead of silently presenting an inferior answer. This is one author-reported occurrence with a reproducible input, not a measurement of how often the problem affects other users.

An understood component no longer needs another spelling

Version 0.5.10 then accepted a triple-colon block for a recognized component as equivalent to its existing fenced-block spelling. Issue 340 explains the practical reason: the previous fix forced an agent to rewrite and render again even though the intended component was clear. That second turn translated punctuation rather than improving the answer. Unknown names and colons inside code examples remain text, while an unclosed block still produces an error. The merged change reports equivalent body HTML for the two forms and associated parser tests; those tests were not run here. The useful design choice is accommodating a recognizable intention without treating every malformed structure as valid.

Readers can return comments without handing over the decision

The generated page also provides a place to respond. Its reference describes panel comments and marked suggestions, questions or passages to keep, collected into a message the reader copies back to the agent. Choices begin unselected, and the returned message distinguishes confirmation, a changed choice and no answer. This lets a person point at the explanation that needs revision without describing its position again. The file can be read offline, but using the skill still requires an existing agent and Node environment; model charges do not disappear. The illustrated example identifies version 0.2.0 and October 2 in its footer. It demonstrates the established reading format, not this patch. For an already clear one-sentence answer, opening another page may simply add a context switch.
