Putting the terminal beside the problem

Much of a development task already lives in browser tabs: an issue, a design, API documentation and the application preview. tabsh makes the terminal another tab beside those materials, rather than reproducing every website inside a new desktop editor. For somebody relying on existing browser extensions and signed-in sessions, that arrangement may avoid reopening the same pages elsewhere. It also adds more tabs, so the shared board must help find a specific project instead of merely relocating a pile of terminals. The stable-release page is dated October 25; its Product Hunt appearance the following day does not reset the original release date.

Status comes from agent hooks

Each card belongs to a folder and can expose either a terminal or a chat interface. Agent hooks update its state when work begins, permission is requested or a task finishes; people can also change the state manually. This makes the list useful for a quick scan, but its labels depend on reported activity. Completed does not mean a change has merged or passed production checks. Keeping the folder and underlying conversation attached to the card provides a way back to the evidence. Across many projects, the most valuable information is often where a person is needed and what depends on that answer, rather than the number of agents running.

Local connection does not make the model local

The web interface communicates with a local Rust daemon over HTTP and WebSocket, using loopback listening and token pairing by default. Optional Tailscale access supports another device. Avoiding a vendor relay does not mean an attached coding agent stops using its configured model provider. A confidential project still needs to examine the actual agent and provider settings. Reconnecting after a browser tab closes is also different from keeping a process alive while the computer is powered off. Interface restoration, restored history and uninterrupted execution are distinct behaviors. The documentation should not be stretched into a guarantee for every power-loss or restart scenario.

Shared checkouts remain the developer’s responsibility

tabsh explicitly avoids worktree orchestration: agents use the selected folder and branch. This preserves a familiar file layout while leaving the developer responsible for avoiding simultaneous edits to the same code. Compared with software that automatically divides a project, it is closer to a unified session entrance: choose a provider, open files, inspect output and decide whether another session should continue. Its MIT license and public code make inspection possible but do not replace local permission controls. A small trial with non-overlapping tasks can show whether reported status tracks actual waiting. There is no reason to increase concurrency merely because the interface makes more sessions visible.
