Recognizing a model and changing it are different jobs

Knowing that a model depicts a dragon, building or bracket does not establish where it can be changed. A blind or low-vision maker may understand the overall form while remaining unaware of an unmentioned feature. Planning to add claws can reveal that the person never learned whether claws already exist. The paper studies this gap in a modeling task rather than asking only whether a caption is accurate. For an accessibility tool, a fluent description can help select an object without providing enough information to edit it. The interface needs to support locating parts, understanding relationships and checking whether a proposed modification conflicts with what is already there.

Separating description design from model errors

The blind first author and twelve sighted participants explored descriptive strategies in the pilot: whole-to-part organization, geometric terms, everyday analogies, embodied descriptions and different reference frames. Ten blind or low-vision participants then received prepared scripts checked by researchers, with some candidate wording assisted by ChatGPT. A researcher delivered the descriptions as a simulated assistant. This deliberately examines the limits of an idealized description medium rather than benchmarking an automatic AI product. Treating that condition as a model success rate would miss the contribution. Even when factual errors are controlled, understanding an account of the object and specifying a workable edit remain separate achievements.

Too much language and missing information at once

Participants interrupted long overviews, requested repetition or returned to a particular portion, yet also asked for dimensions, contours, relationships or polygon counts. Shortening a description may remove precisely the detail needed for the next edit; expanding it indefinitely adds memory demands. The paper distinguishes accuracy, completeness, expression and navigation failures. Those suggest different controls: expand a selected component, maintain understandable orientation, request another explanation of the same geometry and return to an earlier location. These are design implications rather than a finished interface delivered by the study. A single quality score for the generated paragraph would obscure which capability the maker actually lacks.

Checking understanding through a proposed change

Sighted assistance, tactile representations and accessible parametric code remain relevant alternatives, each with costs but also ways of exposing spatial relations omitted from speech. A new tool should check the user’s structural understanding separately from the modification they can specify, rather than asking only whether a description was helpful. Naming an object correctly does not establish an ability to request a change that preserves its connections. The sample and model selection are limited, and no generator is shown to describe every mesh completely. The concrete product opportunity is to reduce repeated orientation questions by showing what can be queried, where the conversation has reached and which assumptions about an edit remain unresolved.
