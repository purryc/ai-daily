Agentic Path Maps shows alternative analyses alongside the result

A valid analysis can still miss the intended question

An agent can produce executable analysis while silently choosing variables or methods that do not match the person’s intent. Agentic Path Maps makes those choices comparable through linked outcomes, explanations and code. This gives users a more precise place to disagree than a generic uncertainty warning. Someone can identify the assumption that does not fit their situation and ask for a different analysis. Task completion should therefore include understanding the premises, not only receiving an answer. The interface needs to make a consequential choice easy to locate without requiring the person to reconstruct the entire workflow from code or a long conversational history.

Connect each choice to its consequence

The result matrix aligns analysis choices with their outcomes, and selecting an item reveals details. We see its main advantage as locating differences: when two conclusions diverge, the person can examine which decision changed. A deployed product would still need to manage the number of combinations. One possible design is to begin with choices that materially change the conclusion and reveal additional detail on demand. That is a proposed strategy, not a demonstrated optimum. The display should also disclose its coverage: which paths were generated, which were checked and which remain unexplored. Otherwise, a tidy matrix may imply completeness that the system cannot support.

Less anchoring comes with more work

The study recruited 48 participants with some statistics and Python familiarity. Across two datasets, it compared one deliberately extreme result with three or nine alternatives. Alternatives reduced reliance on extremes but required more time and effort. The extra work is neither automatically waste nor automatically beneficial. Evaluation should ask whether it helps people reject unsuitable assumptions and explain their eventual choice. A person might spend longer because the display is informative, confusing or simply difficult to navigate. Distinguishing those explanations is necessary before deciding how much complexity belongs in a product’s default view or which users need an introductory explanation.

[S119]

Several paths are not a vote on truth

The experiment’s controlled set of paths does not replace checking data quality or clarifying a changing real-world goal. We would keep the question, source data and selected assumptions together, with a route back to the underlying evidence. If every analysis uses the same bad input, nine columns cannot repair the underlying problem. Likewise, the median serves as a study reference rather than a universal definition of truth. A useful trial would introduce a shared input error and see whether participants notice it despite the apparent variety of results. The work is an interface research contribution; commercial pricing, general availability and independent deployment performance are not established here.
