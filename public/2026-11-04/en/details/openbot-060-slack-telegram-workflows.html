Mentions and filters decide when work starts

Slack workflows start from a mention of the OpenBot app in a channel, with workspace, channel and text filters. A mention that does not match continues to the existing orchestrator rather than silently disappearing. That can separate a repeatable task from general conversation, for example reserving a check for messages carrying a chosen keyword. It also means similar-looking messages can follow different paths. The workflow's name should make its entry condition clear, and an evaluation should include both matching and nonmatching examples. Testing only an ideal trigger does not show what ordinary teammates will encounter when their wording varies.

Outputs make the destination explicit

A workflow can reply in the original thread, post to a channel or react to the mention. Telegram has comparable output choices, but replying or reacting needs a trigger message in that same chat. A manual run without this context fails at the output node with an explicit error. Configuring the destination as a step reduces how much the agent must infer about where an answer belongs. Generated content and delivered content should remain separate states, especially with several output branches. A successful reaction does not establish that a longer textual reply also arrived; the relevant run result still needs inspection.

Chat platforms do not behave identically

Telegram triggers apply to mentions starting eligible linked group conversations. Once a forum topic already belongs to an agent conversation, later mentions go to that agent rather than restarting a workflow. The author also records a UI limitation: linked private chats appear in the selector even though private messages do not trigger workflows. Slack lacks a From-people filter, direct-message events and direct-message actions in this change. Similar canvas nodes therefore conceal meaningful platform differences. A configuration should not be copied between services without checking those boundaries. The release's support claim does not cover every message type or every stage of an existing conversation.

Check permissions and the test's actual scope

Slack nodes reuse the existing connection and scopes and restrict creation or editing to owners and administrators; Telegram nodes also use administrator rules. The release includes server audit logs and channel-memory changes, but those do not prove end-to-end delivery for the new workflows. The Slack PR reports a development-workspace exercise covering mentions, keyword routing, thread replies, channel posts and restart persistence. The Telegram PR explicitly says no real Telegram message was sent. Desktop use and connected service environments still require suitable setup, with model and hosting costs checked separately. This research did not install the product, connect accounts or trigger a workflow.
