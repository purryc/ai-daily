Choose the listening format first

With a lecture handout ready for revision, a user can select a podcast or course format, attach the material and describe the desired result. The public composer groups language, voice, model and duration choices in one place. The new announcement presents two entry routes: direct creation in a browser and programmatic course generation through an API. SUN already had a mobile product, and Product Hunt separately lists an October 30 ChatGPT launch. The change therefore concerns how a user starts from material on a desktop, not the first existence of the whole service. For someone organizing notes before a journey, the relevant question is whether this setup yields the right listening structure with less preparation.

A conversation changes the document’s structure

The PDF entry suggests a two-host conversation, while allowing a shorter recap, deeper treatment or one narrator. Several files can feed one episode. The vendor says attached documents ground the result. That can reduce the work of preparing a spoken script, but converting tables, footnotes, formulas and qualifications into a linear recording requires choices about structure. Our editorial assessment is to compare a short familiar passage with its output before relying on a long episode, particularly for numbers, negation and causal claims. The page supplies no measured fidelity rate for document conversion, and no audio was generated or listened to in this research. A smooth conversation should not itself be taken as proof of faithful coverage.

[S26]

Publishing is a choice on each creation

The FAQ places generated work in My space and gives each creation a private or public switch. Public items may appear in the Library. Using the same account across the browser and mobile apps provides continuity, while courses and audiobooks are divided into lessons or chapters. These details matter for personal study because the useful artifact must remain findable and appropriately visible after generation. However, an unlisted private item does not imply offline processing or establish attachment-retention rules. The inspected material does not resolve those policies. The visibility control is best understood as a publishing choice on the output, without extending it into a broader claim about every stage of data handling.

[S27]

The API boundary still needs its documentation

The maker describes the API narrowly: create audio courses from a prompt and retrieve finished episodes. That does not establish that every web format has an equivalent endpoint. The developer link leads to sign-in, so request fields, completion status, rate limits and failure charging were not verified. The FAQ offers a free first creation followed by subscriptions or pay-as-you-go use, with credits related to duration. The public pricing page states that credits do not expire but did not expose a complete price table. For integration into a personal reading tool, retrieval, retries and cost accounting remain concrete implementation questions. An API link alone is insufficient to assess those parts of the workflow.
