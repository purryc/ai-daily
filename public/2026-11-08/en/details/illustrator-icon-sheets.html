List the required meanings before generating

An interface icon family has two jobs: different symbols must communicate different actions, while their visual treatment should belong together. Icon Sheets can start from a broad description or a list of required icons. The broad version lets the system choose the contents; expanding the interpreted list reveals those choices. That inspection point matters more than a large output count. Sixteen attractive icons can still omit an essential state or duplicate a meaning. A designer should first map the set to actual interface tasks, then judge its appearance. Otherwise, a convincing collection can become a pile of assets that do not fit the product’s navigation or controls.

Keep a family resemblance while changing one member

A selected icon can be edited with another prompt or explored through variations of structure, style or both. These are different design decisions. Changing an envelope into a speech bubble changes the likely interpretation; changing stroke treatment affects its relationship to the surrounding family. Artwork can also provide a style reference, but canvas artwork is a reference input rather than an object that moves into the generation panel for editing. Existing brand assets therefore still need their normal editing path. The useful distinction is between asking for a new candidate influenced by an asset and directly modifying that original asset; a similar appearance does not make those operations equivalent.

[S28]

Placement leaves editable artwork on the artboard

Placing one icon or a whole set on the artboard leaves editable vector artwork with strokes preserved. That avoids some of the splitting and tracing required when a generator returns a single raster sheet. It does not finish production cleanup. A symbol that looks balanced in a large preview can lose a thin stroke, close an internal gap or shift its apparent weight at button size. Reviewing it in the actual interface is therefore more useful than selecting only from the generation panel. Editability gives a designer a practical way to make those corrections; it should not be mistaken for evidence that the corrections have already been made.

Separate beta access from design readiness

The November 4 release is a beta capability in build 31.1.49, and the documentation limits access to the latest English beta. A stable-release date is not established. Light and dark previews help expose dependence on a background, but real states such as disabled, selected or warning still need inspection in context. Existing libraries remain useful when established symbols already cover a product’s needs. Generated families are more interesting for a particular theme or visual direction. The practical saving depends on how many candidates remain useful after refinement, rather than how many previews appear. No independent recognition study or team rework measurement was found in the source material.
