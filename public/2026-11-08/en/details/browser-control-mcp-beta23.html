Keep the sequence, not only the final frame

After an agent completes a sequence in a browser, a final screenshot often cannot explain what happened along the way. A dialog may have appeared briefly, an error may have disappeared after a retry, or a button may have been pressed twice. Beta.23 of browser-control-mcp adds tab recording on supported Chrome versions. Other tools can continue operating while recording runs; stopping returns the file path, size and duration of an AV1-encoded MP4. This is useful evidence for a reproduction, rather than forcing someone to infer every action from the final page. Producing a recording still does not establish that the underlying business task was completed correctly.

The browser version determines the capability

Recording requires Chrome 156 or newer; the Firefox path returns a capability error. The release also adds a scope parameter to call-frame evaluation on supported Chrome versions. It lets an agent inspect an outer variable hidden by a same-named inner variable. Call-stack output lists scope indices, types and names, and an invalid selection reports the available range. Older or unknown Chrome versions do not silently pretend to support it; Firefox retains only the innermost scope. These differences make environment detection part of the workflow. An agent can decide whether video, screenshots or runtime inspection are available instead of assuming that every browser exposes identical debugging controls.

Avoid silently attaching to another session

Startup behavior changes too. Previously, omitting a port could attach the tool to a Chrome already listening on 9222, causing requested headless, window or proxy settings to be ignored. The ordinary default now launches its own Chrome on a free port. Explicitly supplying a port selects attachment, while port zero is rejected. Remote-host and user-profile modes retain separate rules involving 9222, so this should not be advertised as universal session isolation. The instance list reports the actual port. Distinguishing a newly launched browser from an existing session helps explain why a supposedly identical reproduction may otherwise have inherited different cookies, tabs or settings.

Video and runtime inspection answer different questions

The tool also exposes navigation, input, network inspection, breakpoints and stepping. Video explains the visible order of events; a call stack and variable inspection help explain why state did not change. Neither replaces the other. This release additionally corrects reporting that treated already-open tabs as newly created and restores then re-minimizes a window when necessary for a screenshot. The project remains in beta, so clients need to track response shapes and supported versions. The maintainer’s comparison figures are not independent performance results, and no live recording was executed for this article. The supported contribution is the documented interface change and its stated compatibility boundaries.
