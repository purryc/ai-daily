A link carries the scene code

A 3D prototype that runs on a developer’s computer can still be awkward to show someone else. Scale, viewpoint and interaction are hard to communicate with pasted code. Three-Live 1.3.2 adds sharing to its web and XR playgrounds: a built-in scene can be addressed by preset name, while an arbitrary script is compressed into the URL fragment. The receiving client decodes that payload. A Share button presents the link and a phone-scannable QR code, removing the need to exchange a project or repeat a paste operation. The documented client-side decoding concerns this scene payload; it is not a blanket statement about the network behavior of every AI-assisted workflow.

Inspect the outputs before integrating them

The underlying project compiles Three.js scenes toward Android, Apple and browser targets. The new Native Outputs panel makes the handoff more inspectable by collecting mesh counts, GLB and USDZ byte sizes, and copyable Kotlin, Swift and HTML integration snippets. A developer can see what was generated before putting it into another application. The release also improves embedded textures and entry alignment in USDZ output. These details matter when a preview becomes an asset pipeline rather than a disposable demo. Different targets still use different rendering and runtime environments, so a successful export is not evidence of identical lighting, touch behavior, scale or performance on every device.

An agent can return an inspectable result

The CLI link command and the MCP three_live_link tool validate a scene before producing its shareable result; the MCP response can include an SVG QR code. That gives a coding agent something a person can open, rather than only a statement that generation succeeded. The project also supports deterministic headless simulation of interactions, physics and objectives, producing a filmstrip over fixed time steps. Those frames can help inspect scripted movement and state transitions. They cannot reproduce all the conditions of holding a phone in a room: camera permissions, occlusion, available space and platform support remain part of the eventual experience.

Useful for a short prototype handoff

The clearest use is a short exchange between design and engineering: change the scene, generate a link, inspect it on a phone, then examine the files and integration snippets. A persistent compilation-time badge and camera, mesh and spatial inspectors make that conversation more specific than approving a render alone. The repository’s illustration is an author-provided code and rendering showcase, not our Android or iOS test. Three-Live remains a development tool. Sending a static model can be simpler for a static task; linking a live scene becomes more useful when its behavior is changing and another person needs to inspect the latest version quickly.
