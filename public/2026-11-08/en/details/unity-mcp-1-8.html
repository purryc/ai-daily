A saved localhost address may not be active

A public issue describes a specific source of confusion: the configuration contained a localhost address and requested that the local server keep running, yet the connection still went through Cloud and timed out. Cloud mode selected that route and ignored the saved local address. Switching to Custom allowed the local service to start and initialization to succeed. The report followed an upgrade, but its author could not establish that the upgrade had changed the mode. That chronology should not become a confirmed regression claim. The useful finding is about configuration meaning: when people see an address, they reasonably expect it to describe the connection being attempted.

Explain the active route without guessing the mode

Version 1.8 adds an informational startup message describing the actual Cloud endpoint and why a saved URL is being ignored. A warning-level connection failure also points someone seeking a local server toward Custom mode. The implementation does not infer the desired mode from a localhost-looking address and silently switch it. That preserves the explicit selection. Nor does the hint declare every Cloud failure a configuration error: an expired login or an outage can produce a similar symptom. For someone operating the editor through an AI client, this explanation offers a clearer next action than a generic timeout, especially when moving among projects with different connection arrangements.

Test credentials need a separate location

A separate fix adds the UNITY_MCP_CREDENTIALS_DIR override. The maintainer found that .NET’s user-directory lookup on Windows does not necessarily follow HOME or USERPROFILE changes made for a test process. An editor running a test could therefore reach the real operating-system account’s credential store. The new value must be an absolute path and is resolved once for the current domain, moving the store lock and project-key cache together. An invalid relative path is ignored with a warning. This improves the storage boundary for tests and automation; it neither solves every credential risk nor implies that ordinary users must configure a new directory themselves.

Editor actions depend on a clear connection

The project offers scene queries and mutations, code execution, screenshots and tests, giving an agent concrete Unity objects to work with. As that action surface expands, ambiguity about the connected environment becomes more consequential. This release introduces neither a sensor nor a new generative model. It improves the mode and identity state that developers need to understand before using the existing tools. The repository image is an older connection-window reference showing the Cloud and Custom controls, not a screenshot of version 1.8 under test. Maintainer automated checks support the changes, but this article did not install Unity and independently reproduce the account or editor behavior.
