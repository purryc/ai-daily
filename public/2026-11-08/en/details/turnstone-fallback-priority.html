Choose the next model before an interruption

When an assistant reaches a provider limit midway through a task, moving elsewhere often means copying context and explaining what has already happened. Turnstone keeps the agent’s task and conversation together while allowing a different connected model to continue. The November 7 version 0.8.7 adds user control over the fallback priority of providers and models. That can reduce manual context transfer without increasing the limits of any underlying subscription. Continuity of text also does not establish continuity of interpretation. The replacement needs to distinguish completed work, unresolved decisions and actions still awaiting permission, especially when the task involves more than drafting a response.

Persistent instructions need an editing surface

The same update allows working-rule bullets to be edited directly while keeping saved instructions synchronized. For a persistent assistant, this gives the user a place to inspect what was actually retained instead of repeatedly saying that it should behave differently next time. An obsolete preference can be removed and an incorrectly learned habit corrected. Expandable table previews address another practical problem: structured results are difficult to review inside a narrow conversation column. Neither interface feature proves that a model follows every instruction. They provide more inspectable controls, which still require the user to resolve contradictory rules rather than assuming that memory automatically makes them consistent.

Storage location and inference destination differ

Turnstone describes agents, chats and memory as files stored on the Mac, but its privacy policy separately explains that a chosen cloud provider receives model requests under the user’s account. Running a local model through Ollama is a different route, not a property of every connection. Version 0.8.7 also lists a 1Password connection through its official CLI and Composio Connect through OAuth. These broaden the available connection paths without proving identical permissions for every service. The actual consent scope matters. Older policy wording and current feature demonstrations are not fully aligned, so the product should not be described as having a universal, independently verified permission boundary.

A free desktop app does not supply unlimited inference

The desktop application is advertised as free, while subscriptions and API use retain their own costs and limits. The November 6 changelog already mentions purchased OpenRouter credits, so the October 28 facts page’s claim that the product sells no credits is stale. Availability also needs care: the homepage still labels always-on Cloud as forthcoming, and the November 7 service-recovery note requires experimental Proactivity access. Those statements do not justify promising continuous execution with the Mac closed. For someone juggling several AI accounts, priorities and editable rules are useful controls. Task completion still depends on the machine, the connection and the capabilities of the model that takes over.
