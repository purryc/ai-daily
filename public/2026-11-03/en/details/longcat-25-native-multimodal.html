Put visual material into the request

Consider fixing a page from a screenshot: describing its layout, text and misplaced control can itself take time. LongCat 2.5 accepts image and text blocks in the same request. Images can be supplied as inline encoded data or public URLs; videos require URLs that the service downloads and parses. An agent host must still connect the model response to subsequent editing actions. Useful checks are concrete: were numbers, small labels and relationships read correctly, and did the resulting edit reach the intended file? Visual input removes some transcription work. It does not ensure that every detail becomes correct code, and sending an image to this API is not local-only processing.

Training addresses sequences of actions

The official English technical article is dated November 1, one day before the Chinese article, so this is a recent supplement. It describes a native-resolution encoder and residual vector quantization that turn visual signals into multiple levels of discrete tokens, alongside long-trajectory training and reinforcement learning. The intended work includes inspecting interfaces, using tools and continuing an execution sequence. Website, three-dimensional showcase and business-analysis demonstrations illustrate the vendor’s intended outputs; they were not independently reproduced here. Longer jobs also depend on tool permissions, source quality and recovery after failed actions. A model benchmark score cannot be converted directly into the probability of completing a particular customer deliverable.

Check which integration settings take effect

The OpenCode integration guide provides a LongCat provider entry and model selection after authentication. Its configuration can disable thinking, which is otherwise enabled by default. The API documentation adds a detail relevant to evaluation: temperature is fixed at 1.0 with thinking enabled and 0.7 when disabled, overriding other submitted values. An existing test harness may therefore appear to accept a setting that the backend does not use. Compatible interfaces reduce integration work but do not determine file permissions, tool approvals or acceptance tests for the team. Downloadable 2.5 weights and their applicable license were not confirmed in this research, so API availability should not be presented as verified open-source deployment.

Count caching and rework in task cost

The pricing page lists limited-time rates per million tokens of ¥2 for uncached input, ¥0.04 for cached input and ¥8 for output, with the platform and billing records taking precedence. Long tasks repeatedly carry context, so cache hits, retries and output length can materially change the bill. No completed-task cost was measured here. A small comparison should use the same screenshot and explicit acceptance conditions, recording the first artifact, correction rounds, human inspection time and bill before checking the finished files. Looking only at initial response speed or token price can miss the waiting and expense introduced by repeated corrections. Temporary discounts also should not become an assumed long-term budget.
