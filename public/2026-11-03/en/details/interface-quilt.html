Add an interaction layer without changing source code

A familiar application may lack a convenient large control or require repeated trips to another program for image editing. Interface Quilt generates an overlay and connects its controls to the existing interface through computer use. The abstract presents patches that change presentation, interaction or capabilities without source access. This targets specific friction in installed software rather than replacing the entire application. Before adopting such a layer, check whether native shortcuts, macros or plugins already solve the problem. An overlay introduces another state to maintain. Its additional flexibility should save enough repetitive work to justify that synchronization burden.

Building a patch differs from using it

Demonstrations include moving an image from a presentation into another editor and returning the result, alongside menu and control modifications. Building explores the target application; later interaction uses established bindings and recognition. Pixels still omit hidden properties, and some menus require the real pointer. A patch therefore needs more states than a successful-looking button press. It should distinguish requested, executed and independently observed completion. Otherwise a failed target action may leave the overlay displaying the state the system intended rather than the state the application actually reached. That distinction matters even for seemingly simple formatting controls.

[S87]

Feasibility demonstrations are not efficiency evidence

The paper supplies a macOS prototype and demonstrations, not a controlled user study establishing efficiency gains. Construction and testing can take tens of minutes and temporarily occupy the computer. Counting only later clicks saved would miss that preparation cost. A changed window size, toolbar layout or application version also calls for rechecking established bindings. An evaluation should include setup, recognition mistakes, recovery and maintenance alongside repeated task time. Frequency matters: a patch used many times daily may repay a substantial setup investment, while an occasional action may remain simpler through the application’s original controls.

[S87]

Start with one reversible action

A bounded trial might adjust font size or insert an image, operate both the original control and the patch, and confirm that their states agree. Then introduce occlusion and a moved toolbar. Check whether failure leaves an obvious route back to native controls, whether the patch can be disabled, and whether the user understands which layer currently owns an action. Stable application APIs may remain preferable for precise automation. Interface Quilt does not establish reliable modification of arbitrary applications or confirmed commercial availability. The appropriate deployment boundary comes from testing the particular task and its recovery path. A patch should make recovery simpler than rebuilding it from a new prompt. Keeping a recognizable route to the original application helps users continue working when recognition fails, rather than turning a small convenience into a new dependency.
