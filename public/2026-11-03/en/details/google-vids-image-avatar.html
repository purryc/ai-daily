Choose the character before writing the script

A series of training clips often needs the same presenter while the wording, background and duration change. Vids now accepts an uploaded image as the starting point for a custom avatar. The author refines the appearance, chooses a voice and saves the result in the project before generating a scripted scene. This separates choosing a character from writing each explanation. It also introduces two different review questions: whether the character looks appropriate, and whether the chosen voice suits the material. The image supplies an appearance reference; it should not be treated as proof of consent or as automatic cloning of the photographed person’s voice.

Review revisions after generation too

The help page recommends a clear, well-lit image and provides a voice preview before generation. Avatar clips are limited to sixty seconds, and the generation window should remain open. The more consequential detail appears during revision: changing the script marks the existing avatar as outdated, so the author must update that scene. A sensible review order is to approve factual wording first, generate the clip, and then check names, numbers, pauses and lip movement. When a price or date changes, inspect the rendered result rather than assuming the new script has already replaced the old performance. Captions and other on-screen text need their own consistency check.

Reuse within a project has a boundary

Saved custom avatars can be reused within a Vids project. The documented way to carry one into another file is to copy the project, which is different from an automatically synchronized organization-wide character library. For onboarding or recurring product explainers, a reviewed template could save repeated appearance setup. Copies also retain material that may no longer belong in the next video. Check old titles, scripts and brand elements before treating a duplicated project as clean. A useful small trial is two videos with the same presenter and one later correction: record which changes propagate and which must be applied manually. Shared appearance does not imply shared update behavior.

Distinguish rollout timing from account eligibility

The announcement dates Rapid Release rollout to October 30 and schedules the other release track for November 20, so this item is a seven-day review. Account eligibility needs a separate check: the announcement includes personal accounts, while the availability table carries a preset-avatar qualification for that category. Those documents do not support an unconditional promise of free custom uploads. Organization-level Vids and generative-feature access can also matter. Before building a production routine around the feature, confirm the visible controls and limits in the intended account. Compare correction effort with a recorded presenter, a fixed voiceover or an existing video template, including the cost of regenerating a scene after approval.
