Publish one catalog instead of copying skills to every client

Once a team has written a review checklist, refund procedure or release-note template as a skill, distributing a consistent version becomes a separate task. TypeScript SDK 2.4 adds a Skills extension. A server loads a folder with loadSkills and attaches the resulting catalog to its MCP server. Each directory containing SKILL.md defines a skill; surrounding directories organize its URI. SkillsClient lists names, descriptions, file paths and digests without reading the instruction files. A host can then select the relevant skill and fetch its body and references. Discovery therefore does not require loading the entire collection of instructions into the agent in advance.

A mismatched file stops the read

When reading SKILL.md, the client checks byte length and SHA-256, then compares its YAML frontmatter against the catalog entry field by field. Reference paths resolve relative to the skill folder. A path absent from the published file list is refused before a request is sent. Verification failures identify size, digest or frontmatter mismatches; a failing cached response gets one refreshed fetch before rejection. The server maintains the same consistency boundary. Its catalog stores metadata, while reads retrieve bytes from storage and require them to match the published digest. Editing a file without reloading the catalog therefore produces an error instead of silently delivering another version.

Reloads and invalid entries have explicit handling

Maintainers call reload to rescan and replace the catalog together. If the scan fails, the old catalog continues serving. Additions, removals and name or description changes can notify connected clients that resource listings changed. On the server, invalid skills are skipped with warnings by default; strict mode makes loading fail instead. On the client, invalid entries normally fail listing, while skipInvalid preserves valid entries and returns refusal details. The storage interface also separates distribution from a particular filesystem: memory files let hosts serve packaged skills even when their deployment environment has no usable filesystem, SkillFiles adapts another store, and SkillSource can produce different catalogs according to request context.

Consistency checks do not authorize execution

The extension supports protocol revisions 2025-11-25 and 2026-07-28, but attach remains experimental and may change in a minor release. Dynamic skills declare no fixed file list, so reads skip size and digest verification and return verified:false while still comparing manifest frontmatter. Client documentation leaves loading approval and server provenance with the host. Matching bytes cannot determine whether instructions are safe or grant permission to execute their actions. The repository is transitioning from MIT to Apache-2.0, with new documentation under CC-BY-4.0; adopters must respect the applicable file licenses. For teams with several clients, the concrete benefit is consistent distribution and clearer failure reporting, not automatic trust in remote instructions.
