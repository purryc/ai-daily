Give the agent a deal task and get a shareable room

A fundraising or acquisition team needs more than a place to upload PDFs. It must organize folders, decide who can see each document, distribute links and answer questions. Papermark announced Data Rooms 2.0 on October 25. Its founders describe asking an agent to prepare a buy-side acquisition room and receiving folders, permissions and a sharing link. This is coverage of the integrated 2.0 release, not the first appearance of Papermark or proof that every interface was newly introduced that day. The web product retains document management, built-in questions and answers, and page-level analytics; API, CLI and MCP let teams perform related preparation tasks from scripts or an existing assistant.

Uploading and sharing remain separate operations

The documented CLI flow begins with browser authorization, then uploads a file and creates a link. Those operations can be separated when a user needs a password, expiry or email gate. A data room groups multiple documents under one access boundary: create the room, upload and attach documents, then generate a room link. Separate links can point different contacts to the same room, with later queries filtered by link or date. This lets an agent connect organization and distribution steps, while the team still supplies appropriate documents and recipients. Page visits and reading duration are observed engagement data; they do not establish investor intent, comprehension or the probability of a deal.

Local and browser-hosted agents upload differently

Local MCP reads file paths; remote HTTP cannot access the user’s disk. The remote client must obtain an upload URL, transfer bytes, then register upload_id. A chat attachment does not complete that transfer. The package remains a 0.1.0 alpha with potentially incompatible minor updates; check the client’s file-transfer capability before connecting.

[S82]

Separate the agent’s authority from a visitor’s access

Room permissions determine whether visitors may view, download or access particular files, folders and groups. Token scopes determine what an agent can do. Document reads, room writes, link changes and analytics access are independent grants; write access does not imply read access, and missing scopes produce a 403 response. After OAuth approval or token creation, the agent acts as the user rather than a separate MCP identity. Dashboard tokens can be revoked; local logout clears local credentials, while server-side revocation requires disconnecting the integration. Branding also has explicit behavior: changing the default does not automatically move previously created rooms. Plan requirements and pricing need confirmation before adoption. The advertised sixty-second setup is a vendor claim, not a timed result from this research.
