Select this group, then continue the conversation

Flint addresses a familiar dead end in an AI report: the chart exists, but comparing another group or narrowing a date range still requires another written request. Its interaction specification accompanies data, field semantics and styling, allowing selection, brushing, zooming and linked views to be declared together. An MCP integration presents charts through compatible application cards, while developers can embed the same interaction model in dashboards. The documented examples connect country selections across two years or highlight a bubble from a table row. Selection becomes explicit context for subsequent work. The host still decides what to do with that context; a selectable chart is not itself an answer to every analytical question.

Let the compiler resolve the gesture

A user clicks a visible mark, but application logic needs a field value or data item. Flint resolves raw clicks and drags into semantic targets, then accepts update operators for emphasis, labels or viewport changes. Developers need not address SVG paths or renderer-specific mark indices directly. External controls use the same idea: a table row can dispatch a country value, which a handler converts into selection and annotation updates. Events can also flow outward to filter a table, revise text or update another chart. This removes repeated rendering glue while leaving application choices explicit: keys must correspond, selection commits need defined behavior, and the host decides what enters the next conversation turn.

Two follow-up fixes matter when the chart is reused

The maintainer dates the interaction release to October 19 and a follow-up, version 1.0.1, to October 21. One fix makes an explicitly requested interpolation mode outrank the theme for Plotly line and area charts: asking for straight segments should not silently produce a theme’s curved or stepped line. Another addresses chat-card reconstruction when VS Code drops metadata. Small charts with inline rows also carry those rows in structured content so they can render again. Rows loaded through a local file URL are excluded from this fallback, so it is not universal data recovery. Microsoft’s October 22 article explains the workflow after release and should not be counted as a separate launch.

Rendering coverage is broader than interaction coverage

Rendering coverage exceeds interaction coverage. The documentation limits presets to Vega-Lite; other backends produce a static chart with an ignored-interactions warning. Even within that backend, each chart advertises supported capabilities. An unsupported declarative entry can be dropped with a warning, while invalid code-defined interactions can prevent mounting. Definitions competing for one gesture also require conflict handling. Applications must consume those reports rather than treating a visible chart as proof that every requested action works. Persisting reader annotations and selections remains a host responsibility. Code and accompanying documentation use the MIT license. No independent runtime trial, timing comparison or user study was performed here, so claimed reliability benefits cannot be converted into an unsupported success rate.
