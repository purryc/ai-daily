Discover tools before granting access

The Agent tool picker now accepts registry-backed MCP servers. Choose existing credentials, use OAuth quick connect or create a credential, then let the setup form discover the server’s live tools. Read and write categories each receive an allow, approval-required or blocked policy, with overrides for individual tools. Connection errors offer retry or credential changes, and the same form exposes a timeout setting. A companion change saves an Assistant connector only after the user explicitly selects Add connector; abandoning the dialog no longer leaves a new connection behind. This separates selecting a service, discovering its capabilities and committing access, while leaving the user responsible for deciding which capabilities the task actually needs.

Migration preserves legacy behavior and inline limits

The new toolPermissions field replaces separate filtering and approval settings. At execution time, n8n converts category policies and tool overrides into the runtime’s filter and approval configuration. Migration covers both current Agents and their history, preserving unrelated fields and leaving malformed rows unchanged with a log entry. One default deserves attention: omitting the new field retains the previous behavior of allowing every tool without approval. The upgrade therefore does not automatically establish a deny-by-default policy. Inline Agents reject approval-based policies because those workflow executions cannot resume after human approval. Unresolved credentials prevent network requests and report the reason through the connection-failure channel; fix credentials first.

A child budget stop is no longer an empty success

A delegated run previously could cross an alert threshold or hit a cap while its parent received an ordinary completion with an empty answer. Version 2.45 forwards budget notices into child execution and treats a guardrail finish as failure, preserving the reason for the parent model and the chat interface. Notices identify the owning Agent; the interface deduplicates by owner and code, so two Agents crossing the same threshold can retain separate cards. A child’s monthly limit is distinguished from the shared session cap, including whether the interface offers an increase action. This improves propagation of configured budget controls; it does not establish that every external service charge is comprehensively metered.

Creation retries have receipts; adoption needs version checks

Non-idempotent Public API POST requests can carry Idempotency-Key. For twelve hours per user, the same key and request retrieve the first successful response without running the handler again. A changed request returns 422; an in-progress duplicate returns 409; a failed request releases the key. Without the header, another request can create another object, so clients should persist the key with the logical task. These changes shipped in the October 20 prerelease, not the latest maintenance patch. n8n offers cloud and self-hosted deployment, with published plans based on workflow executions.
