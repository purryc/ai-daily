Serving requests on a specific local machine

Gufo is a local inference engine optimized for AMD Strix Halo. Its documentation focuses on Ryzen AI MAX+ 395 systems with Radeon 8060S and provides Linux and Windows paths. A user prepares compatible model files, then starts chat or connects an application through a serving interface; weights are not included with the source. Version 0.28.1 was published on October 31 at 13:44 UTC. Its changes concern prompt processing and speculative execution for Qwen Flash-Next rather than training a new model. For someone running long contexts or several agents, the practical questions are whether the same context is processed consistently and which proposed tokens deserve the machine’s verification work.

Ending a draft when confidence falls

Speculative decoding proposes candidate tokens before the target model checks them. The change retains the existing controller, which uses acceptance history to choose a draft length and can fall back to ordinary decoding. It adds the current proposal’s probability as an immediate signal: an uncertain draft ends further drafting in that cycle. The predictor does not become the final authority; target verification remains. The pull request describes different gates for greedy and sampled paths, and jointly planned batches retain their width limits. These details locate the optimization in allocation of computation, rather than in a new writing-style control. An agent can keep its existing request interface while the engine changes how much speculative work it attempts.

A restored cache should not alter prompt processing

A separate fix addresses numerical differences introduced by splitting a prompt. The same prompt may be processed in one wide pass, or leave a small tail after restoration of a checkpoint. The maintainer identified a different mixing order on the short path that could make corresponding rows differ. The repair pins relevant accumulation order and adds route checks spanning projections, recurrent state, routed experts and matrix shapes. The user interacts with cache reuse and continuation, not internal rows, which makes consistency a necessary condition for a useful cache optimization. This repair does not establish full parity between the quantized implementation and the original unquantized model; the model documentation explicitly leaves that qualification unresolved.

Speed gains belong to measured workloads

The maintainer’s draft-gating measurements report roughly eleven percent improvement for longer responses and a four-session workload, while disclosing regressions on two of five short-reply prompts. Those numbers belong to the project’s particular quantization, greedy decoding and thinking-off configuration. They are not a claim that every request becomes eleven percent faster. Compiler, math-library or model changes also call for renewed quality checks. The documentation separates the MIT license on original engine code from adapted dependencies and the terms attached to model weights. This is an upgrade for people already serving locally on the supported hardware, who still need to compare their own response lengths, concurrency and cache-restoration patterns rather than a single maximum throughput figure.
