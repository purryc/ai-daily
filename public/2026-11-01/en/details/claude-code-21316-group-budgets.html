Add a shared constraint to team spending

The October 31 Claude Code release adds a shared monthly budget to the apps gateway while retaining each member’s own limit. Previously documented group caps are defaults assigned to individual seats: ten people with a one-hundred-dollar cap do not collectively have only one hundred dollars. The new pooled field supplies that additional shared constraint. This belongs to a gateway an organization operates itself. Developers authenticate through corporate identity, and the gateway retains upstream credentials and controls model access by group. It does not automatically give ordinary subscription users a team budget dashboard. Nor should operators confuse its configuration with the settings managed in the hosted Claude administration console. The October 29 issue already covered shared budgets in hosted Enterprise; this increment places the control in the self-hosted apps gateway.

Match subagent effort to the task

Subagents move searches, log inspection or specialist checks into their own context, then return results to the main conversation. They can have focused instructions, tools and permissions. Their model requests still consume the same usage allowance, so dividing work among more agents does not inherently reduce total cost. The release adds a default effort setting for cases without another explicit choice, avoiding automatic inheritance from the main session. Operators should check the effective configuration when a particular worker already specifies its own setting. A lighter default may be worth testing for repetitive exploration, but quality, elapsed time and request count need measurement on actual tasks. The name of a setting supplies no reliable savings percentage.

Know where policy reaches the client

The gateway can now merge all matching policies, making ordering and the effective result relevant when someone belongs to several groups. The deployment guide explains that gateway sign-in replaces Team or Enterprise sign-in. Clients receive its managed configuration rather than fetching the hosted console’s server-managed settings. Local files also have defined reach: personal settings affect that machine, while shared project configuration must be committed before it follows a colleague’s checkout or a cloud session. Organization-managed values have higher precedence. Writing a configuration file somewhere is therefore not evidence that every execution surface received it. Operators need to verify both the login path and the propagation scope before treating a policy as an operational control.

Separate the spending estimate from the bill

The gateway checks accumulated usage on requests. Its established individual limits block subsequent calls after a cap is crossed until the period resets or an administrator changes it. Documentation treats this as a control-oriented spending view rather than a perfect reproduction of the cloud provider’s invoice. Concurrent requests and price configuration also affect the result. Operators must decide how a spending-database outage behaves: continuing service and failing closed carry different operational consequences. Separately, the release announces removal of Opus 4.8 fast mode on November 30, with errors rather than automatic fallback afterward. That is a migration notice with a future deadline, not a model capability that became newly available on the release day.
