Write the sequence before running it

A coding agent searching dozens of files can spend many turns feeding raw results back into the model and waiting for its next decision. Droid 1.0 lets the model write JavaScript that combines searching, reading, filtering and checking, then prints the information needed for further reasoning. The script has no direct filesystem, network or system access; it works through available tools. The change is to the execution loop surrounding a model rather than a new foundation model. Factory’s October 29 article identifies this as its largest update and lists models that use it by default. Dependencies still require ordered execution; concurrency is useful only where calls can run independently.

Embed the same harness

The TypeScript SDK exposes the same harness to applications through a one-shot run or a conversation that preserves context. Developers supply prompts, working directories, models and tools and receive streamed activity plus a terminal result. It can start a subprocess or connect to an existing daemon. Resuming restores history and settings, but runtime objects such as permission handlers and MCP servers must be attached again. This supports review and maintenance workflows without recreating the entire agent loop. The surrounding application still decides when work begins, what failure means and how resources are closed. A final response is an execution result to inspect, not automatic proof that generated code meets its acceptance criteria.

Separate permission from completion

The headless entry point starts read-only, with higher autonomy selected when a task needs edits or development commands. Tool selection can likewise retain only inspection tools or remove command execution. Its documentation distinguishes a normally completed process from successful task output and recommends checking artifacts or running tests. Enterprise controls can constrain paths, network destinations and tools, with pre-tool hooks able to block actions or request confirmation. Packing many operations into one model request reduces requests, not the number of actions. Permissions therefore need to govern the actual tool calls. Reading the initial natural-language goal once is not equivalent to controlling everything the resulting program will do.

Read performance claims in context

Factory reports benchmark improvements in cost and task completion with matched models, but these are measurements from the vendor’s environment. Its methodology lists comparison versions, repeated trials and special treatment of some cases. The useful mechanism is fewer round trips and less irrelevant context; it does not guarantee every repository becomes faster. The following October 30 release adds an installation check that lists every Droid executable on PATH with its version, helping explain when an older binary is running. It also adds a public organization audit endpoint for enterprise owners. Adoption therefore involves checking the selected client and permitted tools as well as model capability, and understanding the state left behind when execution fails.
