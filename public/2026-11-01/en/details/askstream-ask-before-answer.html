Some missing information will never arrive on camera

A video assistant asked what a person was holding may lack a clear view, or may not know which person the user means. AskStream turns these gaps into testable interactions: receive the evolving video and query, then choose to observe, request missing information or answer. A blurred object needs clearer evidence; an obscured scene may need another viewpoint; a personal action label needs an explanation; an old preference may need confirmation. Some gaps are recognizable immediately, while others become apparent only when the relevant entity appears. This is an evaluation tool, not a newly launched home-camera assistant. Its October 30 arXiv listing is separate from the October 28 submission record.

The right question at the right moment

The main protocol offers one action opportunity per second and permits at most one question and one answer per turn. A correct question inside the permitted window triggers the missing information, after which the model must answer correctly within the answer window. Ask-F1 combines correctness and timing for both stages, with less credit for later responses inside a window. A score of 52.18 therefore does not mean that 52.18 percent of ordinary questions were answered correctly. The authors construct 1,401 questions from 438 videos across four uncertainty categories and eight subtasks. Blurring, viewpoint changes, altered queries and withheld preferences create gaps that human verification checks before and after disclosure.

Memory is part of the comparison

Offline models receive the stream through StreamHarness: it retains the latest ten frames at one frame per second, summarizes each ten-frame group, and consolidates four such summaries into a long-term block, keeping up to eight blocks. Native streaming models use their own memory mechanisms. Across turns, the main experiment retains shared video memory but discards prior questions, options and action histories. In multiple-choice evaluation, Gemini-3.8 Flash reaches 52.18 Ask-F1, while AURA leads the native streaming group at 7.22. Differences in model scale, training and interfaces prevent attributing this gap solely to streaming architecture. Open-ended responses use a model judge and should be read separately from the multiple-choice scores.

More questions do not settle interaction quality

Analysis shows that supplying the correct asking time improves results; additional question opportunities also help, but gains saturate. Real clarification can reveal another gap, whereas the main protocol deliberately simplifies interaction to one ask. Every task begins with an explicit user query, so it does not test unsolicited intervention or coordination between information seeking and physical actions. Public code and data links exist, and the repository documents API and local backend integration; no evaluation was run here. Product selection would still need evidence about interruption tolerance, understandable questions and recovery when the user’s clarification does not arrive as expected. Benchmark timing annotations alone cannot establish those interaction outcomes.
