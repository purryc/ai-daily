A task does not automatically authorize a swarm

Kimi Code 2.3.2, released October 25, changes who decides to distribute a coding task. The ordinary subagent tool’s instructions require an explicit request for delegation or parallel agents, an applicable project or skill instruction, or a mode the user has enabled. A long task, difficult question or request for thorough research does not itself qualify. Previously authorized work can be resumed without repeating the request. This makes scope a separate decision from task complexity. The distinction also limits the claim: ordinary delegation is governed here by instructions, which should not be described as the same runtime enforcement applied to the swarm tool.

The switch is checked twice

Swarm execution has a more concrete code boundary. The user can enable or disable it with /swarm on and /swarm off. Supplying /swarm with a task enables the mode and submits that task; normal completion turns it off. AgentSwarm checks the mode while resolving execution and again immediately before running. When it is off, the tool returns an error without starting subagents. The service also rejects an attempt by a tool to enable the mode. A task request and permission to fan out are therefore distinct inputs. Results retain outcomes such as not started, failed and aborted, rather than only a final narrative.

Handoffs still require work

The ordinary tool instructions also address the cost of a handoff: supply known facts, exact paths and the goal instead of making a new agent rediscover them. Resume an existing agent where possible, and avoid duplicating its searches in the parent. These requirements target context reconstruction and redundant work. Historical records of tool-triggered swarm activation are also excluded from restoring active permission. The plausible benefit is less accidental expansion and wasted coordination. Lower bills, faster completion and higher correctness do not follow automatically. This issue inspected the tagged implementation; it did not run a controlled comparison or measure usage and completion rates.

Compare delegation on the same task

A practical evaluation can choose one separable change in a test repository and compare a single-agent run with deliberately enabled swarm execution. Record handoffs, repeated reads, final defects and total usage. Also check a call after disabling the mode, a restored session and an interrupted task. If parallel work mostly adds briefing and merge conflicts, a single agent may remain preferable. This release supplies an inspectable boundary for delegation, not a recommendation to use more agents by default. The active mode should remain visible to the operator so a one-task choice is not mistaken for permanent permission. These are proposed checks, not reported test results.
