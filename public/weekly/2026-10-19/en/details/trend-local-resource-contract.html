Prepare the machine before the task

GitHub Copilot CLI’s October 7 local-model discovery already put endpoints into its picker while requiring users to supply Ollama and the model. The October 23 Instant discovery is covered in the product highlight; here the comparison concerns preparation before use. The defensible observation concerns preparation becoming part of the product entrance. It does not show a sudden increase in demand for local AI. Earlier records provide individual reference points, but no continuous completion-rate or usage series for the same population and task. Cross-week comparison is therefore still establishing its baseline.

Capacity and execution location become choices

On October 24, sideOS 0.9.8 broadened its offline-model list across memory capacities and added models able to read screenshots. capy-flash 0.7.5 introduced optional calibration of CPU execution and PCIe transfer costs on the actual machine. One helps a person select a usable local path; the other lets a developer replace assumed costs with measured ones. They have no common speed metric and cannot be combined into a single edge-efficiency improvement. The same application name can conceal very different waiting behavior across memory capacity, model size and context length. That variation belongs in the user’s configuration decision.

Preparation costs remain visible

The counterexamples are concrete. Calibration on the capy-flash author’s machine stayed within run-to-run variation, so the default remained off. An October 24 AX9 review reported memory pressure in its tested configuration; an NPU label cannot establish comfortable use of a larger model. Preparation time for retrieval needs its own measurement. Another explanation is that these products package settings previously handled by enthusiasts more clearly, without a shared underlying breakthrough. Confidence is moderate in this interface and configuration observation. Comparable evidence that total task cost is generally lower than cloud execution is absent.

Test the complete use cycle

A practical comparison starts with an approved fixed file set and the same questions. Measure the first download, indexing, cold start, repeated query and update after a file changes, then check whether results still lead to the correct passage. For desktop agents, disconnected testing must separately inspect inference, updates, telemetry and account validation; one local stage does not establish complete offline behavior. The proposition strengthens when a product makes resource shortages understandable and preserves recoverable work. It narrows if preparation consumes the benefit of reuse, or if a model switch quietly sends content elsewhere. This evaluation has not been run and assumes no savings percentage.
