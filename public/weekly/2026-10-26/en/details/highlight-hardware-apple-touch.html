One canvas, three input methods

Apple’s new preparation material raises a practical question for editor teams: can one task move between fingers, pointer and keyboard without losing its place? An illustrative review would move an object directly, refine its position with a pointer, then type an exact value. This is a proposed exercise, not a hands-on result. It would reveal whether selection and unfinished operations survive the input change. Existing pointer users also need a usable layout. The October 28 announcement establishes a developer preparation entry point. Neither its product image nor the presence of tutorials establishes a hardware sales date, and direct touch does not need to be relabeled as generative AI.

Hidden actions still need a route

The design session names hover actions and expanding controls as separate topics. Delete, more-options and local-edit buttons exposed by a pointer may need another discoverable route for a finger. An expanded slider can also obscure the thing being adjusted. A useful product review marks every hover-dependent action in a real task, then compares persistent controls, selection-triggered actions or other supported access. That does not mean making every button permanently visible. The question is whether a person can find the next action and inspect the result after moving their hand away. The appropriate choice depends on the surrounding content rather than on a single gesture demonstration.

Test cancellation and neighboring targets

Readable engineering snippets separate start, continuation, completion and cancellation. They also show touch-only panning, two-finger scrolling and simultaneous sliders. One hit-region example uses a minimum of 36 points per axis; it is not a universal rule for every Mac control. A proposed acceptance task would deliberately start between neighboring targets, interrupt a drag with a system gesture, and inspect whether the edit committed, cancelled or remained pending. Enlarging a target may prevent misses while increasing ambiguity between adjacent objects. Both outcomes matter; counting only successful drags would miss the ownership and recovery problems.

[S09]

Inventory the work before toolchain validation

The November 2 resource-page check still labels Xcode 27.3 beta as forthcoming. Preparation material therefore does not establish that every demonstrated API is usable in the current SDK. Teams can inventory hidden actions, mouse-tracking logic and costly accidental edits now, prioritizing frequent tasks and expensive mistakes. When the toolchain is available, the same task set can compare results across fingers, pointer and keyboard. If an operation repeatedly sends people back to a mouse, distinguish a genuine precision requirement from an undiscoverable control. That distinction gives the next design iteration a more useful target than a single touch-coverage score.
