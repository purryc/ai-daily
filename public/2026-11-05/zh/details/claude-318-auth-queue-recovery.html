脚本可以提前识别登录到期

通过 claude -p 运行的脚本往往只有最终文本和退出结果，登录问题可能直到下一次任务启动才暴露。2.1.318 在认证状态中加入 loginExpiresAt，在 JSON 结果中加入 credential_expires_at；TypeScript Agent SDK 同步增加后者。文本模式则在所用登录到期前十天开始向标准错误流写一行提醒。接入方可以据此把需要重新登录的任务分出来，安排人工处理，但字段只说明存储的 claude.ai 登录期限，不能延伸为所有 API key、云提供方认证或组织政策的统一有效期。

停止操作要覆盖尚未开始的消息

SDK 0.3.318 修复了换模型后暂挂消息未出现在中断响应中的情况，现在这类消息会被列出，并可用 cancel_queued 取消。对于把多个请求送进一个代理会话的产品，这能让宿主更准确地显示哪些请求被停止，避免用户以为全部取消、稍后却看到旧请求开始。它仍然不是事务回滚：已完成的命令、外部请求和文件变化需要根据各自结果处理。团队应保存提交、排队、开始和完成的关联信息，检查界面上的取消对象与返回的消息集合是否一致。

会话内扩展留下明确的启用记录

Claude Code 的 mod 是在程序内部运行的 JavaScript 或 TypeScript 事件处理器，可添加面板、改变工具调用行，或在一次工具调用前介入。用户描述需求后，Claude 能在会话中写出这样的扩展；本次版本增加了用户是否启用它的回答记录。这个记录帮助追查某个行为何时改变，却不替代审阅扩展代码。官方说明 mod 使用用户的权限，可读写文件、启动进程和发网络请求。普通 hooks、技能或 MCP 已能完成的任务，未必需要把更多逻辑放进程序内部。

恢复后的路径和结果需要核对

发布说明还修复了远程会话重启后，获准的 shell 命令误在会话起始目录执行的问题；现在若不能进入原请求目录，命令不会运行。另有修复避免 API 错误截断回复时，带 mod 钩子的无界面任务仍返回成功。对持续运行的产品，测试应包含换模型后取消、批准后重启、登录到期和损坏配置等边界，观察是否留下可解释的失败，而非只跑顺利完成的示例。本期未安装或重现这些缺陷；采用前仍需核对实际二进制、SDK 版本与组织认证方式，模型和订阅费用不由补丁说明确定。
