Recorded audio becomes attributed text through a developer component

Stable llama.cpp 0.9.0 expands the audio models available to developers building their own local transcription or spoken-output tools. Nemotron 3.5 Transcribe support accepts recorded audio with prompt context and produces text with speaker attribution across forty supported languages. Offline here means inference can run locally; it does not mean the project supplies a finished meeting application with capture, sharing, permissions and editing. Microphone handling and recording consent remain application concerns. The engineering opportunity is reducing the number of model frameworks maintained separately. End users still need controls to correct names, specialized vocabulary and a statement assigned to the wrong speaker.

Speaker state crosses windows without establishing real-time operation

The implementation processes long recordings in forty-second core windows, with four seconds of context on each side. A speaker cache and queue persist between windows so speaker numbers do not restart repeatedly. That mechanism addresses a concrete downstream problem: manually reconciling identities across a whole conversation. It does not establish live captions. The pull request explicitly excludes streaming and word timestamps from this integration. Server users must also disable reasoning because the checkpoint template otherwise can produce reasoning without transcript text; the command-line tool needs no such flag. An application should detect that configuration failure rather than interpreting an empty transcript as silence.

Preset voices reduce setup while models retain separate requirements

For spoken output, Pocket TTS gains a preset-voice path that does not require a reference recording for voice cloning. This simplifies tools that need a consistent narration voice rather than an imitation of a particular person. The release also adds Chatterbox support and lets server properties expose available voice names for selection at the speech endpoint. An application can present those choices instead of making users guess parameters. Model files, licenses and resource requirements still differ. The runtime’s open-source status does not establish unrestricted commercial rights to every weight set, nor does choosing a preset resolve every identity or permission question.

Use representative recordings to check errors and operating effort

The contributor reports validation on English reading and meeting datasets and identifies hardware including an RTX PRO 6000 Blackwell. Those measurements do not establish laptop performance or equal recognition quality across all supported languages. This issue did not run the models, and automated code review is not an independent accuracy test. A useful trial would include overlapping speakers, technical terms and long pauses, then measure correction time, cross-window speaker consistency and memory demand. Export should preserve human corrections. November 4 marks the stable release; individual changes merged on November 2–3. This is a distinct addition from previously covered Soprano support, rather than the first appearance of audio in the project.
