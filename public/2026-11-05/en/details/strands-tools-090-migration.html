An upgrade changes whether the agent starts

The separate Strands community package supplied common actions for agent applications, including web access, files, shell operations and subagents. Its November 4 version 0.9.0 replaces deprecation warnings with import errors. Maintainers say earlier versions continue working but receive no further updates. An application that automatically accepts the newest dependency can therefore fail before a user submits a task. The immediate work is to inventory imports and call sites, then choose between temporarily pinning the older package and migrating. A successful package installation is not evidence that the application still starts. This is a maintenance event for existing agents, not a new launch of every tool now included in the SDK.

Replacement involves more than a new import

The replacement map has several destinations. File operations become SDK-vended tools, some external services move to vendor-maintained MCP servers, and memory moves into MemoryManager. Automatic insertion of relevant memories into context differs from waiting for the model to invoke retrieval. The previous editor separates into read, write and edit operations; an edit identifies a path and the old and replacement text. Engineers must also review external tool names, authentication and returned structures, retaining representative old tasks for comparison. Some capabilities, including the browser wrapper, have no direct replacement. Renaming a package cannot establish that these different routes preserve the original behavior.

Exact editing and recovery are separate responsibilities

The new edit operation requires the old string to occur exactly once. That makes the intended target explicit; repeated text requires the caller to obtain more context before requesting the change. The tool documentation also says that edits use absolute paths and the process permissions. The migration guide warns that write and edit apply immediately, without the older backup files or an equivalent undo command. Teams using agents to change configuration or multiple files need their own recovery mechanism, such as version control or a snapshot, and should inspect what remains after failure. A unique match identifies a location; it does not establish that the proposed replacement is correct.

Execution isolation needs explicit wiring

The SDK sandbox delegates execution and file operations to a separate backend while the host agent continues handling model calls, hooks and state. Omitting the sandbox parameter runs command and file tools directly on the host. Built-in availability therefore does not mean isolation is enabled. A useful migration exercise uses a controlled directory to inspect a read, an edit, a failed command and recovery, comparing paths, exit results and file differences. Adoption also includes maintaining those checks, configuring execution and handling external authentication and charges. This research did not run the migration or verify provider bills. Existing applications first need to preserve their task behavior before adding more capabilities.
