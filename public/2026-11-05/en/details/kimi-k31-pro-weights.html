Weights change where inference runs; the application still supplies tools

Moonshot already introduced K3.1 Pro through its products and API in October, promising downloadable weights by November 4. The official repository now contains the model files, making deployment on a team's own infrastructure a concrete option. Text, images and conversation history enter the model; the application interprets its output as an answer or a tool request. Downloading weights does not also deliver search access, file permissions, task queues and review controls. Those remain responsibilities of the surrounding application. A team replacing a hosted endpoint should therefore check message compatibility and recovery behavior before treating the change as a routine model-name substitution.

Sparse activation does not remove the full checkpoint's storage requirement

The model card lists 2.8 trillion total parameters and 104 billion activated parameters, with text and image inputs. The file directory totals approximately 1.56 TB. Sparse activation therefore should not be confused with storing only a roughly hundred-billion-parameter checkpoint. The vLLM reference starts with eight-way tensor parallelism, using two GB300 trays or one B300 node. This is a documented infrastructure example rather than a universal minimum-hardware promise. Long prompts, concurrent conversations and caches add resource pressure beyond weight storage. A purchasing comparison needs measured task lengths, concurrency and retry costs; the absence of a weight-download fee does not establish inexpensive operation.

Long tasks need state that is not visible in the chat bubble

The official integration guide requires the complete assistant message to be returned in subsequent turns, including reasoning content and tool-call fields rather than only visible text. This affects storage, retries and migration between sessions. An intermediary that records only the chat bubble may discard information required for the next step. The documented effort settings are low, high and max. A useful comparison can run the same interrupted tasks, failed tools and multi-turn corrections against hosted and self-operated endpoints, examining completion, waiting time, final artifacts and recovery work. The advertised context capacity is a configuration boundary, not evidence that a long-running workflow will finish correctly.

Read release chronology separately from commercial conditions

The initial repository commit is dated November 2, while public-opening coverage appeared on November 5. A commit timestamp does not establish when the repository became publicly accessible, so this issue retains that uncertainty instead of converting the promised date into a verified launch clock. The custom license permits use and modification but requires a separate agreement for certain model-service businesses above its revenue threshold, with additional attribution provisions for very large commercial products. Internal use and official channels have specified exceptions. This is not an unconditional MIT release. Teams need both a review of applicable terms and workload measurements before committing to operation; no model execution or independent benchmark replication was performed here.
