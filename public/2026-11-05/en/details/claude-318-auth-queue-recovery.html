Scripts can identify an expiring sign-in

A script using claude -p may previously have surfaced a sign-in problem only when its next task started. Version 2.1.318 adds loginExpiresAt to authentication status and credential_expires_at to JSON results; the TypeScript Agent SDK adds the latter as an optional result field. Text output gets a warning on stderr starting ten days before the stored sign-in ends. An integration can use that information to separate tasks that need a person to sign in again from tasks that can continue. The date concerns the claude.ai login in use. It is not a common expiry rule for API keys, cloud-provider credentials or organization policies.

Stopping must include work that has not started

SDK 0.3.318 corrects an interruption response that omitted a message waiting behind a model change. That message is now listed and can be cancelled with cancel_queued. For a product feeding several requests into one agent session, this gives the host a better basis for showing which requests were stopped, avoiding an old request unexpectedly starting after the user believed everything was cancelled. This remains different from transaction rollback. Completed commands, external calls and file modifications need their own handling. An integrator should correlate submitted, queued, started and completed requests, then compare the cancellation shown in its interface with the returned message set.

Session extensions leave an activation record

A Claude Code mod is JavaScript or TypeScript that runs inside the program and reacts to events. It can add a pane, alter how a tool call is drawn or intervene before a call proceeds. Claude can write such an extension during a conversation; this version records the user’s answer when asked to enable it. That record can help explain when behavior changed, but it does not replace reviewing the code. The documentation says mods run with the user’s permissions, including file, process and network access. A task already served by a settings hook, skill or MCP server may not need another internal extension.

Check paths and results after resuming

Other release fixes address an approved shell command running in the session’s initial folder after a remote restart. If the requested folder cannot be entered, the command now does not run. Another corrects a headless result reporting success when an API error cut off a reply while a mod hook was active. Long-running products should exercise cancellation after model switching, restart after approval, expired sign-in and damaged configuration, rather than only successful examples. This research did not install the release or reproduce the defects. Adoption still requires checking the deployed binary, SDK version and organization authentication path; these patch notes do not establish model or subscription costs.
