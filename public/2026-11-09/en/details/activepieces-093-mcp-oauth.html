Connecting and executing are different steps

The 0.93.0 release adds MCP client OAuth2 and changes the connection surface. The concrete job is connecting an assistant to application actions, rather than producing a textual suggestion for an automation. Two directions should remain distinct: the release’s client capability and the built-in MCP server documented for external assistants to operate Activepieces. A user still has to select the right project, authorize the relevant applications and supply the trigger and action fields. Authentication can reduce manual credential handling, but it does not decide whether a particular account should send a message or change a business record. Those decisions remain part of configuring the workflow.

Find the action, then resolve its fields

The tool reference exposes flow structure, step settings and full code through separate reads. A sensible editing sequence is to inspect the existing flow, discover the needed action, resolve its fields and then apply a targeted change. Spreadsheet operations illustrate why this matters: file, sheet and column choices can depend on one another, and display names are not reliable substitutes for internal identifiers. Tool search can return no match instead of forcing a similar action. That behavior makes a capability gap visible. For someone maintaining an established automation, preserving inspectable field mappings is more valuable than receiving a fresh-looking flow that points at the wrong account.

Draft, test and publish remain separate actions

Structural validation, step testing, run inspection and publication are distinct tools in the documentation. A generated flow can therefore be checked for broken references and empty branches before it is enabled, and a run can be examined through its step outputs. This separation is useful, but a test that sends a message or updates a table may still have external effects. Calling something a test does not make it read-only. A small team could begin with a test channel and copied data, checking empty inputs and retry behavior before enabling a real trigger. We did not execute that sequence or measure error reduction against manual editing.

Read scope and cost at the point of use

The built-in MCP documentation scopes operations to the authenticated project and leaves sensitive connection setup in the interface. Tool categories can be enabled per project while discovery stays available. It also distinguishes a tool call from the flow that call starts: most MCP tools are free, direct action execution costs a credit, and triggered flows retain normal billing. The repository separately identifies an MIT community edition and commercial enterprise features. A budget therefore depends on repeated executions, model services and required enterprise controls. Our suggested acceptance check is whether one input produces exactly the intended action and whether a failure can be traced to a specific step, not just whether a flow diagram was generated.
