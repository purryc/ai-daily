Connect the computer already holding the work

A project usually already lives on a particular computer, with its repository, dependencies and unfinished files. Tether gives that machine a named place in Open WebUI rather than asking the user to upload the work again. The person connects the desktop companion and then selects the device from a browser. A phone can therefore become another entrance to the same workspace. This is useful for checking work after leaving a desk, provided the computer remains available. The interface should make the chosen machine unmistakable: changing a file in the wrong checkout is still an error even when the command itself succeeds. Local files also do not imply local model inference.

Keep permission beside the action

When the connected terminal offers coding agents, the release exposes them through the model picker and places tool approvals in chat. One conversation uses one agent, and the familiar regenerate or edit-and-resend interactions are restricted. That distinction fits an action-taking interface: rewriting the request does not undo a file mutation that already happened. Our product reading is that agent identity, target device and approval should remain visible together. A reviewer needs to distinguish a proposed action from a completed one before continuing. We did not run the supported agents here, and their appearance in one picker should not be read as identical capabilities or permission behavior.

The companion has its own adoption terms

The companion repository supplies downloads for macOS, Windows and Linux, but its licensing terms require separate attention. Personal non-commercial use is free; commercial or organizational production use requires an Open WebUI Enterprise License. Publicly visible source is therefore not a promise of unrestricted organizational deployment. The connection address and terminal setup are meaningful choices, not merely onboarding fields: they determine which service receives access to the machine. An organization should identify the owner of that endpoint and the allowed workspace before connecting employee devices. Enterprise pricing was not verified, so the personal-use offer does not establish a zero-cost team rollout.

[S08]

Check what happens after the connection returns

The same day’s 0.13.2 patch fixes chats that stalled when the service was opened through a plain HTTP LAN or Docker address, along with related editing failures. That is a reminder to evaluate the actual access path rather than stopping at a successful sign-in. A practical trial would use a non-sensitive repository, read a file, approve one controlled edit, interrupt connectivity and inspect both the file and reported result after reconnecting. This is a proposed check, not a reliability test performed for this article. For someone switching between phone and desktop, knowing which action completed is more useful than merely seeing the chat return.
