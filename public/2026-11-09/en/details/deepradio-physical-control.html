Make the requested radio behavior inspectable

DeepRadio embeds an agent workspace in GNU Radio Companion, turning a radio goal into an inspectable specification and editable flowgraph. Parameters retain their origins rather than silently becoming user choices. For a teaching trial, we would ask the operator to explain one consequential parameter before continuing. Producing connected blocks is different from understanding the conditions under which a link will work. That exercise could reveal whether the interface reduces hidden assumptions. It would also discourage a misleading acceptance rule in which any generated graph is treated as progress, regardless of the actual communication goal.

Keep each observation within its tested scope

Checks distinguish structural, signal, protocol, hardware and task outcomes, and their validity depends on the project version. The practical question is what a user can do after receiving no data. A useful interface would separate a failed test, an untested assumption and an absent external signal, instead of inviting repeated execution without a diagnosis. Our suggested assessment would deliberately introduce one fault at a time and observe whether the operator chooses an informative next measurement. Even an unsuccessful run can be useful if its unresolved questions are precise. A confident completion paragraph would not provide the same engineering guidance.

Retain a concrete boundary before transmission

RF operation is disabled by default and requires offline checks, device probing and explicit approval; stop controls and snapshots support recovery. A confirmation that merely says run would be insufficient in an adopted product. The operator needs to understand the device, configuration and physical consequence being approved. Routine reversible edits can justify less interruption, while transmission needs a clearly bounded decision. This interpretation concerns interaction design, not permission to use a frequency. The study’s controls should not be presented as a general compliance guarantee or proof that all attached hardware will behave safely under every configuration.

[S35]

Check behavior beyond the reported setup

The authors report seventy runs across seven task categories and a twenty-participant study. Code and assets are planned for release after publication. These results do not establish performance across arbitrary radios, protocols or crowded environments. A team considering the design can first examine the specification, evidence and physical-control separation without assuming a packaged product is available. For a different radio, our proposed trial would verify discovery, stopping and invalidation of outdated results before comparing repair effort on a controlled task. One successful demonstration would not settle those questions, especially when environmental conditions change between runs.
