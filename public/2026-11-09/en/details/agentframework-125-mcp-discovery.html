Discover a complete catalog before choosing tools

Before an agent can choose a tool, it often asks an MCP server what tools exist. Python 1.25.0 bounds that discovery process: default catalogs stop at one hundred pages or one thousand items, framework-owned requests have a thirty-second default timeout, and a failed refresh preserves a complete catalog snapshot. The change targets unbounded paging, waiting and partial catalog replacement rather than adding a new model capability. For a team connecting many internal systems, predictable discovery affects whether the displayed abilities can be trusted. These are version-specific defaults, not limits imposed by the MCP protocol on every service. Applications still need to decide what a stale catalog means to their users.

Give the connection lifecycle an owner

The official MCP guide distinguishes connections created by the framework from clients supplied by the caller. The framework manages its own connection lifecycle, while the application remains responsible for a supplied client. The inputs include an endpoint, authentication and tool configuration; only then can the model receive tools and their results. Injecting an external client does not automatically apply every framework default. Our interface implication is that connection failure should be distinguishable from an inadequate model answer. Otherwise people may keep rewriting a question when the actual problem is an expired token or an unresponsive service. Choosing a local process versus a remote URL also changes where task data travels.

A shared workflow is not a shared user

The release also restricts live workflow executors and sessions to one authorization scope, rejecting cross-scope reuse before a model call. Its migration guidance recommends factories that create fresh workflow, executor and session objects for each invocation; sharing a builder can still share its executors. The underlying concern is mixing two users’ active execution identities. The stated guard does not cover every state loaded from shared storage or automatically audit custom tools. For an enterprise assistant, the visible user, project and approval history should agree with the backend session. A new chat window alone is not evidence that those identities have been isolated correctly.

Validate boundaries as well as startup

Python 3.11 becomes the minimum, so applications on 3.10 must address their runtime before adopting the release. The framework offers orchestration, checkpoints and human intervention, but those primitives do not decide a product’s business authorization and recovery rules. A bounded upgrade trial could use an oversized catalog, a server that fails midway through refresh and requests from two distinct users. Inspect the rejection, retained catalog and session identity rather than checking startup alone. That trial was not run here. Teams should also inspect monitoring filters that depend on older span names, because a telemetry naming change can make activity disappear from a dashboard without changing the real workload.
