One interface for lasting workspaces and disposable tasks

Running several agents on one development machine can entangle dependencies, directories and credentials. Paddock gives each agent a Linux work box with an XFCE desktop, SSH and Docker inside the box through Sysbox. The owner can retain it as a continuing workspace or delete it after a single task. The changelog dates the initial single-VPS release to October 25, followed by a rename in version 0.2; the October 27 Product Hunt appearance is a discovery milestone. This is intended for people willing to manage a host. It brings several environment controls together, but does not promise to operate the underlying server on the user’s behalf.

Environment controls sit beside agent controls

The web interface, CLI and HTTP API expose creation, stopping, resuming, forking and deletion. A box can start with a repository or archive, while agent tasks have separate prompts, steering, interruption and event streams. Detached commands provide logs, input and termination controls. This helps distinguish an environment that is still running from a task that is actually progressing. Outbound networking can be open, denied or restricted by domain and address allowlists, with changes applied to a running box. Choosing that policy still requires knowing which model, repository and dependency services the task needs. An overly narrow rule can break the task; an indiscriminate one weakens the intended separation.

Returning to a snapshot starts processes afresh

Rollback can sound as if an agent will resume thinking at the exact earlier moment. The maker instead describes filesystem restoration: files, installed packages, configuration and deletions return, while processes and RAM do not. The box boots again, with temporary directories, package caches and in-box Docker data outside the same capture scope. A snapshot before restoration can undo the rollback itself. Credentials are kept in an excluded runtime path, and the maker explicitly says they are not yet automatically reinjected on restoration. Restoring files may therefore require renewed authentication and service startup. It also cannot reverse an email or API write already performed outside the box, a separate boundary the operator must track.

Free code still needs a maintained host

The project is MIT-licensed and expects an Ubuntu or Debian VPS with root access, a DNS name and the required web ports. Its installation configures Docker, Sysbox, restic and Traefik, while the owner supplies enough compute and storage for the boxes. This can suit developers who repeatedly fork experiments and want a stable environment under their control. It is not automatically cheaper overall than a hosted sandbox. Snapshot retention, host updates, exhausted resources and recovery drills remain operational work. Public code and the maker’s explanations make the control boundaries inspectable, but they do not constitute an independent isolation audit. A useful cost comparison includes maintenance time alongside the server bill.
