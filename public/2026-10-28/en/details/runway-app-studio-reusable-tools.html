Giving the recipe its own controls

A colleague wanting a set of product visuals may otherwise need to ask which model to choose, which references to attach and which prompt to copy. App Studio packages those choices into an application. A creator describes the tool or starts from an existing Agent session or Workflow, retaining its prompt, model sequence and brand settings. The resulting interface exposes the inputs another person actually needs and produces images, video or audio. This can reduce dependence on the person who originally discovered the recipe. It also makes that person responsible for maintaining the recipe when models, brand material or input assumptions change; a working first example is not evidence of universal suitability.

Editing a tool before sharing it

The builder offers conversation beside a live preview. Selecting an element or marking a location supplies a more precise target than describing an ambiguous button. The code is visible, and a published app can be downloaded as source. Replacing the model behind a generation step triggers a rebuild rather than merely changing a label. The review should therefore cover output behavior as well as whether the interface opens: the same input may yield different text, people or brand colors after a model change. Changes remain in the preview until published, giving the author a place to try them before the shared application changes for colleagues.

A link still has an audience

An unpublished preview is private to its author. The publishing panel supports the author, the workspace or specific people, and audience changes take effect immediately. Public access is unresolved in the documentation: the product page and announcement describe links for Runway account holders, while the sharing guide lists a public-link option in one instruction but elsewhere restricts access to workspace members. External customer access should be checked in the actual account before it is promised. The guide also documents no deletion or unpublishing option; choosing Only you stops colleagues opening the app. Narrowing an audience is useful, but it is a different operation from removing the hosted application.

A reusable interface still consumes credits

App Studio was announced for paid plans on October 26 without a separate add-on, but building, running and hosting draw on existing credits. The public-sharing description assigns visitors their own generation costs; the author still pays for building, personal use and hosting. A narrow recurring job, such as producing controlled background variants of a product image, provides a more understandable starting point than an application attempting every production stage. The October 27 changelog also lists Ads, but its original announcement is September 30. That adjacent workflow connects advertising accounts, generates approved variants and reads performance back; the later changelog date does not establish a second launch or new capabilities.
