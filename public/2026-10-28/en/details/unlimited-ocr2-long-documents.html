Keep the document and its page order

Before a scanned manual can enter a knowledge base, somebody has to recover its text without losing the relationship between paragraphs, tables and pages. Unlimited OCR 2 offers a multi-page interface: the caller supplies page images in order and receives a continuous result with corresponding page markers. A downstream search or review tool can use that structure to return to the source page rather than presenting an untraceable wall of text. The caller still owns input ordering. Missing scans, duplicated images or a filename sort error can create an apparently complete result with the wrong content. Counting and ordering pages therefore remain useful checks before inference starts.

Bound the working references and preserve the handoff

The main change is Sparse Reference Sliding Window Attention, or SR-SWA. The official description limits text–visual interaction to a fixed-size working reference set, with 512 tokens given as an example. The serving configuration also uses page windows and reuses the preceding cache tail. These address working computation and continuity across processing segments; they do not make an entire book instantaneous. More pages still mean more input encoding, output and storage. For a document application, progress is better communicated through completed pages or stages than through the phrase single request. A bounded working set is a resource strategy, not a promise that total latency stays unchanged as the input grows.

An open interface still has deployment requirements

The repository and model card identify MIT licensing. They provide a Transformers path and a customized SGLang route recommended for serving. The native example was tested with Python and an NVIDIA A800 with 80 GB of memory, and loading requires the model’s custom code. This is not a promise of browser-only execution or compatibility with any consumer GPU. The service example includes page-output caps, window sizes and memory settings, making resource management part of integration. A practical deployment should pin its model and runtime and examine representative documents before replacing an existing OCR workflow. Downloadable weights provide access to a component; they do not remove the work of operating it reliably.

Check correctness across page boundaries

Baidu also publishes MarathonDocBench, whose dataset page exposes 100 document identifiers and more than 18,000 page records. That gives evaluators a concrete long-document sample to inspect, but an author benchmark is not accuracy evidence for a particular organization’s files. A table joined to the wrong row or two paragraphs incorrectly merged can travel further into search than an obvious garbled character. Review should retain source-page links and inspect meaningful boundaries and omissions, rather than comparing text volume alone. The repository announces version two on October 27, while the model history already shows October 26 uploads. This is therefore a recent supplement. The first generation’s June release is separate, and unlimited in the name does not imply error-free recognition.
