Find reviews relevant to the installation decision

A bot can be useful and highly rated while members have different questions: what happens to anonymous submissions, which data are retained, and who can see them. BotLens organizes this material separately. An administrator can query a bot name for permission metadata, privacy themes and review examples, or submit a bot manifest for a comparison. Ordinary members need not read an entire marketplace’s feedback to locate relevant discussion. The useful output is evidence for follow-up, not a safety badge. Praise for a privacy feature and a complaint can both count as privacy-related discussion, so the topic indicator must be read alongside the direction of the review.

Models prepare the evidence before the query

The study uses a local Llama model to create labels and trains a DeBERTa classifier to identify relevant reviews. Researchers manually review the entire classifier-positive set before adding topic and affective-expression labels. Six MCP tools expose individual bot signals, thematic breakdowns, sample reviews, comparisons and server-manifest reports. Labels and aggregates are precomputed, so a query largely performs indexed retrieval rather than fresh inference over the corpus. This places expensive work in data preparation, but also creates an update obligation. If a bot changes its permissions, version or policies, old reviews and metadata do not automatically describe its behavior today. Fast retrieval and fresh evidence are separate requirements.

The percentage describes discussion, not vulnerabilities

The processed corpus contains 183,142 reviews of 23,102 bots, spanning January 2021 through February 2026. The pipeline retains 8,832 security- or privacy-related reviews, a yield of 4.82%. That figure is neither a victimization rate nor a vulnerability rate, and it is not an October snapshot. Manual validation checks relevance rather than whether an allegation is true. The negative set was not comprehensively reviewed by people, so completeness is also unknown. The classifier’s evaluation contains only sixteen positive examples, making a strong-looking F1 score an imprecise estimate of broader performance. These denominators are necessary to understand what the tool can actually help an administrator decide.

Comparison still needs current permission evidence

BotLens remains a proof of concept; the paper does not show that administrators using it make better installation decisions. In practice, themes can identify behaviors needing explanation before someone checks current permissions, developer documentation and the context of individual reviews. A low discussion rate may reflect sparse feedback or missed classification, while a high rate may include praise for protective features. The tool reduces the work of finding related material across reviews, not the responsibility to assess truth, age and scope. Members who never participated in the installation decision still need understandable access disclosures and ways to respond. A review-query service does not itself provide those controls.
