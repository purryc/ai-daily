Preparing the route before arrival

Many generated-scene demonstrations prepare a location before anybody enters it. WorldStream schedules construction while the person moves. Position, velocity and camera direction identify the tiles likely to be needed next. Semantic planning reaches farther ahead than geometric construction, so the runtime can prepare a region without immediately loading every object. A turn changes priorities while completed plans remain reusable. Regional planning sets settlement intensity, transport and ecological structure; tile planning specializes these choices using slope, water and accepted neighboring connections. Deterministic local code then places roads, buildings, vegetation and characters. The model supplies an executable scene specification rather than generating every displayed frame.

Where an edit survives

If a person changes a forest and then walks far enough for it to leave rendering memory, a screenshot cannot restore the edit. Each tile retains its accepted plan, boundary commitments, random seeds, object state, edits and revision. Unmodified trees can be reconstructed from parameters, while an individually edited tree receives an explicit record. Background jobs carry the revision they started from; an outdated result is discarded instead of overwriting a newer edit. Revisiting therefore depends on the same world record, with compatible generator and asset versions. It is not a promise that an arbitrary replacement asset pack will reproduce the location unchanged.

Connecting a sentence to existing objects

Language interaction reads nearby entities, points of interest and the currently supported capabilities. A location query reads spatial relationships; directing an actor changes state before navigation and animation controllers execute it. Editing the present region and specifying a future region use different scopes. Asking for a village ahead should not immediately replace the forest under the player. In 80 bilingual requests against fixed world facts, the authors recovered the intended operation or appropriate non-execution 76 times. Remaining mistakes concentrated on scope. This experiment did not separately establish a complete edit, leave, unload and revisit cycle, nor does it allow arbitrary requests for capabilities the runtime has not implemented.

The budgets behind a continuous world

The paper uses a Three.js-based WebGL runtime. Its prefetch experiment replays 100 routes and measures backend tile readiness, excluding installation in the browser. Planning ablations contain one complete run per variant, so they do not estimate model-sampling variance. For an editing tool, retaining addressable objects could reduce the work of finding a location again after regeneration. Rapid turns, successive edits and asset upgrades would still need recovery checks. The current prototype has a bounded generation vocabulary, local controllers and curated geographic rules. Longer exploration also accumulates records. Managing that storage and deciding how distant characters continue to act remain system problems rather than solved consequences of rendering a larger map.
