A shared system prompt no longer hides the full conversation

After restarting a local model server, a developer wants to continue editing code without waiting for the entire conversation to be processed again. capy-flash previously stopped looking once memory contained a matching system prompt, even if disk held a much longer conversation. Version 0.7.4 compares those matches. Disk wins when its additional coverage exceeds one sixteenth of its own prefix length. That threshold avoids loading a disk snapshot for a trivial gain. The change repairs reuse of existing state; it does not add unlimited context or recover messages that were never retained. Its benefit is most relevant when several conversations share the same initial instructions.

Single-GPU restoration and server entry points receive fixes

A separate single-GPU bug allocated a read buffer without the required alignment for recurrent state, causing restoration to fail and forcing a fresh prefill. The maintainer reports the same 27B conversation dropping from 15.18 to 0.60 seconds on one GPU, and a 31k-token case dropping from 7.63 to 0.46 seconds on two RTX 5070 Ti cards. These are next-turn recovery timings on the author’s setup, not average response speeds for arbitrary requests. CPU lists also accept ranges, invalid affinity choices fail at startup, and a second server is refused on an occupied port instead of unexpectedly sharing incoming connections.

Calibration decides which missed experts move to the GPU

Flash-Next keeps some experts in host memory and normally computes a cache miss on the CPU. Version 0.7.5 optionally calibrates CPU work and PCIe transfer cost to decide whether sending some missed experts to the GPU is worthwhile. On the author’s Ryzen 9900X and dual 5070 Ti setup, differences remained within roughly two to three percent run-to-run variation, so the default stays off. Changed scheduling can also change the order of floating-point sums. Ten of eleven calibrated test answers were identical, with different wording in the remaining summary. Applications requiring repeatable output should distinguish similar meaning from identical tokens.

[S62]

Compatible APIs reduce client changes, with hardware constraints

OpenAI- and Anthropic-compatible endpoints let Claude Code, Codex CLI or OpenCode use the server by changing connection settings rather than rebuilding a chat interface. The 27B and Flash-Next profiles have different requirements: Flash-Next needs substantial host RAM for experts, while the single-card 27B uses three-bit quantization with a quality tradeoff. File and environment-variable key inputs avoid exposing the key in the command line, but files and service access still need appropriate protection. Published packages primarily target Linux and the specified GPU architecture; the native Windows port is community work. Existing suitable machines can exercise restoration without implying that buying new hardware is justified. Cold startup still has to load the model from disk.
