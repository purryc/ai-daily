Starting with choices rather than a style name

A creator searching a large LoRA collection often chooses a few names from tags, changes their strengths and waits for another image. HimmBO begins with choices among images already in a gallery. The person marks preferred examples, and the system converts marked versus unmarked images into pairwise feedback. No absolute aesthetic score is required, and screening does not generate another batch every round. The paper uses style adapters sharing a base model and standardized subjects to make appearance easier to compare. Precomputation moves work before the interaction; it does not eliminate the cost of preparing and storing a gallery when a platform lacks one.

Sharing feedback between similar styles

Images are encoded into style features and combined with adapter coefficients to estimate preferences. A choice can therefore inform visually similar candidates that have not yet been shown. Screening uses level-set estimation to keep several promising regions rather than treating an early favorite as the only possible answer. A spacing rule also discourages near-identical candidates from occupying the same batch. Eight adapters remain for coefficient refinement. This ordering has a practical cost: refinement can adjust only the surviving components. If screening misses an adapter needed for the desired look, further coefficient tuning cannot bring it back without revisiting the selection stage.

[S87]

Returning a reusable mixture

During refinement, each round generates eight mixtures and also displays the previous best. The person ranks preferred results. The implementation uses Python, BoTorch and GPyTorch; SDEdit generates images from a shared anchor to keep content comparatively stable. The result contains adapter identities and coefficients as well as an image. A preferred completed mixture can subsequently join the gallery. That makes reuse possible: a creator could apply the same mixture to another subject rather than merely save one output. However, matching a style on the test subject does not establish stable behavior on every new subject. Actual adoption also requires checking adapter licenses and base-model compatibility.

[S87]

What the timing comparison includes

The main evaluation uses simulated users whose choices follow DreamSim similarity to 24 hidden target images, with five random seeds per target. Library size ranges from 40 to 1,080 adapters. The default session has twelve screening rounds without new generation and eight refinement rounds totaling 64 generated images. The paper reports roughly fifteen minutes on one GPU versus thirty-seven for the comparison configuration. This is not average production time for working creators and excludes initial gallery preparation. A small preliminary human test is mentioned, but larger studies are still needed for noisy or changing preferences. Evaluation uses linear merging only, and the library manifest, curation pipeline and test inputs are described as forthcoming.
