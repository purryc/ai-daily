Speech goes in; the board shows the words

The project is useful to makers who want an English voice interface on a small device without first operating a cloud service. A user prepares the development board, display and storage card, opens live transcription and starts the microphone. Recognized words appear on the display while the person speaks. Version 1.0 is the October 25 firmware release; the earlier October 9 model artifact is a component, not the same release event. This delivers an installable path from recorded speech to visible text. It does not supply a general conversational assistant that can ask clarifying questions, infer an arbitrary intention or handle every language.

The memory arrangement is part of the product

The disclosed hardware uses an ES8311 microphone and the P4X’s two RISC-V cores. The design compresses Kroko into a mixture of two-bit and four-bit weights and uses PIE vector instructions, without a separate neural accelerator. The model still exceeds onboard flash capacity. Firmware is flashed separately; weights remain on microSD and load into 32 MB PSRAM at startup. The browser installer cannot copy that card file for the user, and the ESP32 family name alone does not establish compatibility. These details determine which board to buy and how to diagnose an empty display after startup. Convenient flashing therefore removes a toolchain setup step while leaving specific physical preparation to the maker.

Six demos separate recognition from action

A second page offers vacuum, home, car, factory, kitchen and presenter demonstrations, all operating devices simulated on the screen. Recognized verbs, targets, quantities and exclusions trigger rules; the interface exposes the words responsible for an action. There is no language model improvising a plan. Editable phrase files accommodate domain names and spoken variants. This suits a prototype with an explicit action vocabulary. Connecting an actual appliance still requires an interface, state confirmation and handling of unintended commands. A correct on-screen response cannot establish that external equipment received anything, and accurate transcription alone does not make a physical action appropriate in its surroundings.

Keeping up with audio is not instantaneous response

The author reports processing chunks faster than their audio duration, but the recognizer still accumulates speech and resolves word boundaries before committing an answer. Its demonstration accuracy comes largely from synthesized speech, with phrase lists selected using those clips. That is not evidence about a noisy kitchen, distant speakers, accents or overlapping voices. A device interface should make listening, tentative text and completed action distinguishable; one accuracy percentage does not help a user recover from the wrong command. Code and weights also have different licenses. There is no verified finished-device price, battery duration or independent replication here. Its concrete use today is an inspectable offline prototype on specified hardware, with editable vocabulary and visible failures.
