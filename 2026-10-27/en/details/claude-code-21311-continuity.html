Long tasks carry instructions as well as code

A coding task can include reading files, discussing an approach, running tests and revising the result several times. As the conversation grows, Claude Code compresses earlier material and continues from a summary. Version 2.1.311 addresses a standard-context overflow error and project instructions becoming stale after that handoff. When someone has just edited CLAUDE.md or MEMORY.md, subsequent work should use the current instructions. Restoring an older copy can produce runnable code that nevertheless violates the latest agreement. This is a continuity repair for an existing coding workflow. It should be evaluated against the decisions retained during a long task, rather than the amount of code the agent can generate.

Separate the summary from the files read again

The context documentation distinguishes several kinds of material. Earlier conversation becomes a structured summary; project instructions, applicable rules and automatic memory are loaded from disk; some recently accessed files are read again. A summary is therefore neither a workspace backup nor a promise to preserve every sentence verbatim. Developers can keep durable constraints in explicit project files, retain current acceptance criteria in the task, and inspect context usage with /context. This makes failures easier to locate: a file may be outdated, a requirement absent from the summary, or a correct instruction misinterpreted during execution. A fluent continuation alone cannot distinguish those cases or establish that the task remains on track.

[S61]

Read the conversation state and command state separately

A second confusing state occurs when the visible turn has returned or a wait expires while a command is still running. The interaction guide provides task inspection and interruption controls. Before starting the same build, test or data operation again, a developer should check the existing task and decide whether to wait, stop it or resume. Silence in the chat is not evidence that execution stopped. Likewise, restoring a conversation does not undo file changes or external effects that already occurred. Recovery still requires checking the diff, version control and any affected system. Session continuity and transaction rollback solve different problems, even when both are presented in the same terminal workflow.

A background task needs an accurate status

A timeout message can easily lead a developer to send the same command again. This release changes that message to include output produced so far and state that the command remains active in the background. When a background session’s process exits, its message also stops promising a restart that will not occur and explains how to resume. These details affect the next action: inspect the existing task or launch another copy. A long conversation can also move between cloud and local execution. A transferred compacted session now warns that it starts from the latest compaction rather than carrying every earlier message locally. The official older terminal image illustrates the interaction only; no independent completion-rate or time-saving result is available.
