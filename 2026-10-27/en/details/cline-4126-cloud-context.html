Cline v4.1.26 · Product update · Official release notes

Cline separates cloud model settings and keeps replies with the right task

Keep a model choice for each execution location

A model chosen inside the editor may not be the right choice for a cloud repository task: available providers, costs and configuration can differ. Cline v4.1.26 separates Local and Cloud API settings and stores their selections independently. A startup or resume card identifies the repository, branch and preparation steps. After entering a request, the developer can check where it is going instead of guessing whether a quiet conversation is waiting or already changing files. The increment concerns settings and task state. Yesterday’s desktop diff and terminal panels are a separate release story, and are not counted again as features introduced here.

Keep each message attached to its intended task

The release also repairs a case where a message sent after cancellation or switching tasks could answer an older pending question. This matters because the same short response, such as “go ahead,” can mean very different actions in two tasks. The interface should make the current task, repository and outstanding question apparent, while retiring questions belonging to a cancelled task. Users should not need to repeat an entire project brief to establish which conversation they mean. After reconnecting or switching, reading the most recent question remains a sensible check. The presence of a familiar input box does not by itself establish that its context is the one the person intended.

[S64]

A cloud workspace is not a complete copy of local setup

The cloud-agent documentation describes a separate repository workspace and branch for each task, with pause and resume support; work does not go directly into the default branch. This separation helps parallel work, but the current documentation also says rules, skills, MCP and connectors are not loaded into cloud sessions. Familiar local behavior therefore needs to be checked individually. There is a documentation mismatch as well: the cloud guide discusses Plan/Act and approval controls, whereas the 4.1.26 release says the corresponding toggle and automatic-approval bar are hidden for cloud sessions. An older tutorial cannot establish that every local control appears unchanged in the cloud. The actual account interface and documented support boundary need to agree.

Keep chat input separate from command execution

Local editor work has its own interruption risk: a user can be typing a message when the agent starts a command. Previously, keyboard focus could move into the terminal and subsequent text would land in the wrong place. This version keeps chat focus stable. Choosing an answer to a model question now lets execution continue, while empty answers are rejected. A run_commands call containing no commands returns an error instead of an apparently successful empty result. These changes make it easier to distinguish what the user answered from what the agent actually did. The maximum model-request retries also falls from five to three, changing the wait during failures. Account and model charges retain their own conditions, and the resulting repository changes still need review.
