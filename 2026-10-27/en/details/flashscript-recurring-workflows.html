Keeping the procedure that already worked

A weekly workbook update may already have required corrections to sheet selection, column names or unnecessary charts. Saving those corrections as a natural-language skill still asks an agent to reinterpret the procedure on the next run. FlashScript supplies authoring guidance for a coding agent to turn a successful trajectory and request template into a Python program. Retrieval, merging, calculation and writes become fixed steps; cities, dates and thresholds become inputs. The reviewed procedure acquires a reusable artifact instead of remaining only in conversation history. This fits work with a recurring structure, but it does not mean an arbitrary one-off request can be saved as reliable automation without further design.

Giving model judgment a defined place

Model calls return declared types such as a string, Boolean or option. The surrounding program controls when each call happens, its inputs and how the answer is used. An input call might map an informal city name to a sheet; a computation call might retain a semantic judgment; an output call explains changes already calculated by code. The guidance also uses guarded caches, explicit rules and grouping of independent questions. This separates program testing from judgment testing. A correctly typed answer is not necessarily a correct judgment, however. A cache or rule that encodes a mistaken assumption can make an error reproducible rather than remove it.

Consistent analytics within a specific benchmark

The evaluation used twelve WorkBench analytics templates, totaling 120 tasks, with ordinary and skill-guided agents as comparisons. Runs used Claude Haiku 4.5 and repeated each task three times. The authors report correct, identical tool sequences for the programs, averaging 321 input tokens versus roughly 23,000 for the skill-guided agent, and about 1.5 versus 4.4 seconds. They also tested 108 unseen instances of the same templates. This is not an enterprise-wide reliability rate. Every computation-layer decision in these experiments could be replaced with a rule, the combined subtasks were independent, and the study did not follow users maintaining production workflows over time.

A reusable template matters more than one successful trace

Programs produced from a trace alone were more specific to its original instance and performed worse on unseen and composite tasks than versions given a template. A deployable version therefore needs explicit variables, conditions that invalidate cached decisions and examples covering changed data, phrased requests and environments. Teams already using scripts should compare maintenance effort with their current scripts. Teams relying on agents should compare review and retry work. Fewer model calls remove one cost, while preparing the initial template and repairing it later remain real work. The useful artifact is a procedure whose assumptions can be inspected and changed, rather than a replay button that hides them.
