Understanding which approvals disappear

Coding agents often begin by reading files, running commands and fetching reference material. Requiring a response at every step can turn approval into a mechanical habit. Copilot’s newly generally available assisted mode screens some requests with a model so uncertain actions return to the person. Its input is a specific permission request in task context, and its output is an execution decision rather than another coding suggestion. That can reduce repeated interruptions, but the person still needs to understand what proceeded automatically. Counting fewer prompts would miss whether review quality deteriorated or an unintended operation was permitted. The release does not provide an independent error rate for those decisions.

Rules come before model review

Existing permission rules are evaluated before model review. An already allowed action may not be reviewed again, and a prohibition does not disappear when assisted mode is selected. The CLI provides a way to choose the mode, inspect it or return to manual handling. Administrators separately control assisted review and unrestricted bypass. For a team, the visible session state matters as much as the configuration file: a new default should not lead people to assume every existing conversation changed with it. A deployment guide alone cannot establish that all machines have the same active policy. Clear feedback when a setting is unavailable or prohibited remains part of the user experience.

What happens when nobody is there

In an interactive session, a request that cannot pass automatically can be put to the user. An unattended or autopilot run denies requests that still need human approval. Consequently, the same job can end differently depending on whether a person is present. Someone maintaining automation needs to distinguish a permission stop from a failure to understand the task. The run record should identify completed steps and the action that did not execute, so resuming work does not repeat an external side effect. Assisted review also does not cover every tool call or sandbox-bypass request. Automatic approval of one test command is no promise about subsequent file, network or deployment operations.

[S58]

Useful defaults do not mean zero prompts

Teams with granular rules should evaluate assisted mode inside those boundaries rather than removing restrictions and asking a model to reconstruct them. A modest trial can retain familiar read-only operations and inspect what happens when work needs a new path or a write. Ambiguous requests should return to a person in an understandable form. Cost includes later investigation and recovery as well as time spent answering prompts. The documentation acknowledges that a model can approve an unsafe action; this is not an absolute guarantee. If automatic decisions take longer to investigate than manual ones took to answer, fewer clicks may not produce a net saving.
