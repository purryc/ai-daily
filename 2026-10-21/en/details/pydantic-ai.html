Task and evidence

A voice agent has two distinct positions in a conversation: how far generation has progressed and how far audio playback has reached. When a listener interrupts an explanation, the model may already have produced the entire paragraph. Retaining that full transcript can make the next turn assume the listener heard material that never left the speaker. The 2.59.0 release and its associated implementation treat this as revisable conversational state rather than forcing an application to erase the entire turn. A maintainer probe involving roughly twenty-six seconds of retained unheard text illustrates one observed case, not a population failure rate or an independent reproduction. The product benefit is a defensible answer to where the conversation actually stopped, supporting interruption and continuation without inventing shared knowledge.

Control and recovery

Small API distinctions determine whether that recovery works. The OutputItemCut discussion distinguishes an empty heard_transcript from None: the empty string means nothing was heard, while None leaves the existing transcript unchanged. The original text remains available through provider_details.original_transcript, and a late correction can be associated with its response identifier. Such a correction can still matter after generation finishes if playback is ongoing. Updated all_messages and new_messages reads reflect revisions, but copies obtained earlier do not change retroactively. If an application uses an old copy for its logs, next prompt or business logic, it must handle that synchronization explicitly. Otherwise, the SDK may represent the interruption correctly while the surrounding product continues to rely on a false assertion about what was communicated.

Control and recovery

Useful evaluation interrupts speech at its beginning, midway through a sentence and after generation has completed but before playback finishes. The next turn should use only audible information, while the audit trail still explains the revision. Clearing a whole turn is a manual alternative, but it discards information that was successfully conveyed.

Control and recovery

The release’s separate Daytona integration addresses another persistent state: lazy workspace creation and reattachment through history. Applications explicitly manage that lifecycle; workspaces are not automatically deleted. Missing credentials, missing workspaces and unavailable services need identifiable recovery paths rather than an unnoticed switch to a blank environment. The integration is asyncio-only, and permissive SDK licensing does not eliminate external-service costs. Both changes should be judged by whether interruption recovery returns to an explainable real state. If the next voice turn still cites unheard speech, or workspace reattachment silently loses task artifacts, the intended adoption benefit has not been demonstrated.
