Workflow and handoffs

The central approval problem in a terminal agent is not the number of confirmation dialogs. It is whether a person understands the action being authorized and what happens when authorization is withheld. Stable 1.0.101 describes bringing operations such as creating and entering a directory into path approval, requiring explicit approval of extension capabilities, and improving approval explanations and diagnostics. In the previous workflow, an ambiguous pause could be mistaken for a model limitation and bypassed by granting broader permission. Clearer scope and reasons can support a narrower grant. Dynamic subagents and structured output on supported models add orchestration capability, but their product value depends on equally intelligible approval boundaries; more delegated work otherwise creates more actions that are difficult to account for.

Mechanism and limits

Unattended operation makes the failure semantics particularly consequential. The release says an MCP connection with an expired token and no OAuth handler is skipped instead of hanging, while renewable grants follow the appropriate connection path. That means the process can advance and expose unavailable capability; it does not mean an authentication failure has been repaired. A task that depends on the skipped tool may still lack essential information or an execution step. Teams should connect the skip reason to the affected work and a recovery choice: authenticate again, perform the action manually, or narrow the task. Treating the remaining output as an unqualified success would conceal the very condition this change makes manageable. A useful acceptance case therefore includes an expired credential, an unavailable interactive handler and a task whose result cannot legitimately be complete without that tool.

Acceptance and alternatives

Against manual shell commands, Git operations and service consoles, the CLI should reduce coordination while preserving an explanation of each grant and each omitted step. The available evidence does not rank it against other coding agents. Adoption also depends on platform support, Copilot entitlement and organizational policy; a public issue repository establishes neither open-source licensing nor free access. The falsifiable product judgment is that legitimate tasks become less frequently blocked without reducing users’ understanding of the scope they authorized. Faster skipping of necessary tools, or more frequent requests for broad permission, would not satisfy that judgment even if the session appears smoother.
