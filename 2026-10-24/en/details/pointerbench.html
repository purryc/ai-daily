A correct plan can still miss its target

An instruction to widen a spreadsheet column is easy to understand, yet the action can fail because the pointer lands a few pixels away from its divider. Selecting a cell, grabbing a boundary and placing a caret between two characters are different targeting problems. PointerBench isolates them by supplying a screenshot and an already specified instruction, then asking for a point or bounding box. It does not continue into a menu or change a document. That separation helps an agent developer investigate whether a failure came from localization or from the surrounding plan and execution machinery. To the end user, however, a correctly described coordinate matters only if the intended edit subsequently happens.

Three families of fine movements

The dataset contains three equally sized suites: Sheets, Text and Pro. The distinction is useful for interpreting behavior rather than treating every visible control as the same kind of target. A grid calls for structural reasoning; text editing can require a position between glyphs; an unfamiliar professional interface adds the problem of interpreting an icon. Pro uses generated interfaces, so its application coverage must not be described as completed work in a hundred running commercial programs. The fixed image size also leaves a practical gap. Changing display scale or enlarging a window changes target geometry, and success on this controlled set does not establish that an agent will remain accurate on a user’s own desktop.

Read the coordinate contract first

The repository makes the output contract explicit through JSON examples and local scoring scripts. A predicted point must lie within the target, while a predicted box must cover the intended region without including too much surrounding material. Malformed answers fail. This matters when integrating a model that normally emits a different coordinate range or only produces points. A wrapper can be responsible for an apparently poor result, and a point-only model does not automatically gain text-selection ability because it located the word. The paper discusses coordinate compliance, while its tables and the current repository leaderboard also contain different values. They should remain separate snapshots rather than becoming one composite ranking with unspecified prompts or parsers.

Make the targeting failure inspectable

The public code is MIT licensed and the screenshots and annotations are CC BY 4.0; model endpoints and compute remain the implementer’s responsibility. A practical use is a more informative failure view in an agent development tool: wrong text, incorrect coordinate conversion and an oversized selection should be different categories. A fourth category, an action that never changed application state, requires evidence this static benchmark cannot provide. Continuous dragging, relocating after scrolling and recovering from a mistaken edit also sit outside its scope. Those distinctions help a team decide whether to improve its model adapter, its visual targeting or the application interaction itself. They are more actionable than treating one aggregate score as a promise that a long desktop task will finish correctly.
