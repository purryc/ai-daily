Decide visibility while creating the task

Paperclip puts goals, tasks and the agents doing the work in one workspace, allowing a small team to organize development, research and operations together. With private tasks, the creator selects Private from the composer's plus menu and chooses the people and agents involved. A removable lock chip makes that choice visible; projects can maintain their own membership lists as well. A hiring discussion or customer document no longer has to appear in the company-wide task list simply because the same agent team is being used. The software is MIT licensed, while the hosted offering is presented through a waitlist.

Share one step without opening the whole task chain

Task hierarchies make sharing easy to misunderstand. Giving a colleague one child task does not necessarily mean that the colleague should see its parent or neighboring tasks. The implementation supports sharing that child independently, while the interface distinguishes ownership, project membership, direct grants and inherited access. An inherited private state is locked with an explanation of why it cannot be removed at that location. Conversely, making a parent public does not automatically publish its existing private children. The person coordinating the work can inspect these reasons rather than remembering an invisible set of rules for the whole task tree.

An agent's access follows the responsible person

The implementation extends checks beyond the task list to search, activity, run transcripts, logs, documents, attachments, work products, plugins and native MCP. That addresses the obvious gap in merely hiding a row while leaving its contents readable through another endpoint. Agent access is intersected with the current responsible user's permissions, so reusing an agent does not automatically carry over another person's private work. Two limits remain significant: withdrawing a direct grant can leave another valid ownership or project grant in place, and withdrawing access cannot automatically remove information already received in an agent's context or memory.

[S69]

Emergency access is explicit

Owners and administrators do not silently receive every private document because of their higher role. Emergency access requires an explicit breakGlass request, producing an audit record and warning. Privacy here does not mean hiding every sign that work exists, however. Dashboard totals can include private work, and company run lists can retain locked rows showing the agent, status, timing or usage cost without exposing the restricted content. Teams that need even a task's existence to be concealed should account for that distinction. The release and implementation describe these controls; they do not constitute an independent audit of every deployed integration.

[S69]

The upgrade also changes role and budget defaults

Two other changes affect administrators immediately. The Operator preset expands from one permission to fourteen, adding missing preset permissions for existing Operators while preserving custom scopes. An old understanding of that role name is therefore insufficient during an upgrade. The cost ledger also distinguishes reported, estimated and unpriced usage. Unpriced no longer means zero cost: the default policy blocks it from passing budget checks until an administrator supplies an audited pricing adjustment or changes the policy. Local installations still need to configure their model subscriptions and API costs. Private tasks organize information access; role and ledger settings determine permitted work and how spending becomes visible.
