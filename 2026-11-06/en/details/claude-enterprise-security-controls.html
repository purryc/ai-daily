Find the setting that needs changing

A security administrator can inspect chat, Cowork and Claude Code configuration without opening each setting separately. The new security center puts current values, recommendations and links to change them together, refreshing automatic checks when the page loads. Some entries still depend on an owner’s attestation. This can reduce screenshot collection and repeated requests to identify a setting’s owner, but a passed-control count describes those checks rather than an external audit. Centralized management adds a separate parent-level identity console in beta. Its setup requires the relevant organizations’ approvals and cannot be undone, so responsibility should be agreed before consolidating management.

A policy service decides before execution

The hook forwards user-visible transcript text, tool calls and results, and extracted attachment text to the organization’s HTTPS security service. That service returns allow or deny. Raw image and file bytes are excluded, and the verdict cannot rewrite or redact a prompt. Material that exists only in an image can therefore escape this inspection. The check runs before inference; enabled tool validation adds a decision before execution. Supported Enterprise conversation surfaces share the configuration, while Platform API organizations, Bedrock and Google Cloud are outside this path. Voice and some built-in tools have additional coverage limits. A single enabled indicator should not imply universal inspection.

Observe first, then choose outage behavior

Configuration separates off, shadow and enforcing states. Allowing the feature only unlocks setup; it does not start inspection. Shadow mode keeps requests moving even when the service denies them. The first saved configuration uses a five-second timeout and allows a request if the service fails; administrators can instead block on failure. Requests outside the rollout sample still bypass inspection. A pilot should therefore include disconnections, slow verdicts and mistaken denials, checking what employees see and how work resumes. The connection test measures one round trip, not production performance. Waiting time, false blocks and missed inspection are separate operating costs to examine.

[S68]

Recovery matters after a denial

A denied passage can be resent with the conversation, so adding a new message that says to ignore it may leave the request blocked. The documentation describes editing the original message, removing attachments, rewinding or starting a new task, depending on the surface. Administrators must also distinguish ending sign-in sessions from revoking execution capability: the new sign-out API leaves API keys, running cloud sessions and scheduled routines intact. An acceptance exercise can use allowed, prohibited and ambiguous cases, recording wrong verdicts, repeated blocks and recovery time. Logs should identify the relevant request.
