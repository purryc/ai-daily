Keep the earlier task discoverable

Changing a model provider can make a missing chat look like lost work. The recovery change keeps earlier conversations discoverable across providers. If the new provider cannot resume a session, the interface opens its history read-only and offers recovery choices. Continuing prepares an editable prompt rather than silently submitting the old conversation. That gives the developer a place to remove stale assumptions or explain the current code before sending anything. The distinction matters when a task has already changed files: reading an earlier record and resuming its execution are different states. A useful recovery screen should make that difference apparent before the next instruction leaves the composer.

Check images before submitting

Image thumbnails address a smaller but frequent input error: similarly named screenshots can be confused until the model answers. The implementation previews local references in order and retains a fallback when the terminal or available space cannot support images. File replacement and deletion also matter; a stale preview can misrepresent what is being submitted. This is not evidence of better model vision. It gives the person an earlier opportunity to correct the request before paid inference or code changes begin. A practical comparison would include similarly named files and rotated screenshots, then check that the visible preview still corresponds to the attachment actually submitted.

Parallel tasks still need explicit closure

The release makes the agent center usable without a daemon and surfaces unread results. Patch details can also be expanded during approval. These entry points reduce hunting for outputs, but they do not perform acceptance on the developer’s behalf. A result waiting to be read differs from a task that has not finished, and both differ from a change that has been reviewed and accepted. Bringing several tasks into one place makes those distinctions more consequential. A team can check whether people select and review the intended patch, rather than treating the presence of an agent center as evidence that parallel work is now reliable.

[S71]

Include failures in a migration trial

Before adopting the update, retain completed and interrupted sessions and exercise recovery under different provider settings. Inspect drafts, read-only history and the continuation composer. Look for stale conclusions presented as current facts, unexpected submission after cancellation, and previews that no longer match their files. These are proposed checks, not tests performed here. Model usage costs were not measured. The practical benefit would be less reconstruction work and fewer mistaken requests while preserving deliberate control over submission. If the developer still has to reconstruct every step from memory, an additional recovery button has not solved the underlying handoff problem.
