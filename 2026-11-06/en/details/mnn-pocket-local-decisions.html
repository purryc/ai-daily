Choose the task before the artifact

A mobile app may need a field extracted from a short message or a request assigned to a workflow, without needing an extended cloud conversation. MNN-Pocket supplies a local language-model component for such jobs. The developer provides the task and text, then chooses generated output or a constrained decision interface. It is not a finished consumer assistant with every business integration, and no new sensor is involved. Its main card specifically discourages demanding mathematics and long coding tasks. That scope helps define a useful trial: a small local task should retain a clear correction path instead of being enlarged simply because the model can run offline.

A download size is not a memory budget

The MNN build uses quantization-aware training and a four-bit-weight, sixteen-bit-activation deployment path. It also needs a runtime compatible with its export. The advertised 173 MB describes the deployment files, not peak memory for every possible input. MNN documentation distinguishes exporting a model from running it, with runtime settings controlling the backend and threads. The potential saving is avoiding network turnaround for small requests. The integration work shifts toward downloads, updates, device compatibility and recovery from loading failures. Local inference alone does not establish that the surrounding app has no telemetry or other network calls; that boundary remains an application design and verification question.

A decision need not become a paragraph

The Dec variant accepts a state, questions and candidate descriptions. A separate adapter and pointer head return selections with candidate probabilities. The documentation illustrates routing a request between returns and billing; this is an interface example, not a measured customer-support result. Dec is a different artifact from the 173 MB generation package. Its interface rejects invalid requests instead of silently repairing them. A returned probability is also not automatically calibrated for the app’s own cases. Compared with generating an explanation and parsing an answer afterward, this path can simplify output handling. The product still needs sensible candidates, confirmation rules and a way to recover from misclassification.

Compare quality and waiting on the same device

GGUF is another deployment option, but developers need to select the file explicitly: its documentation warns that automatic selection may choose a larger Q8 artifact instead of the intended four-bit QAT build. A comparison should record the exact file, backend, input length and device conditions. Decode throughput measured on one tablet is not an interaction-latency promise for every phone. A practical pilot can run the same short cases through existing rules, a cloud model and the local version, tracking errors, correction effort and first-load cost. This is a proposed test, not one performed here. Downloads and corrections may consume the time saved by avoiding a remote request.
