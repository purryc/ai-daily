Route work to the device that owns it

NexusDock gathers several AgentDock devices into one console and exposes one address to an MCP-compatible client. File operations, commands, Git and browser work still execute through AgentDock on the chosen device; copying a server’s information into a chat is not the same as performing the task there. The maker’s October 31 V2EX post introduces this combination to the community. Existing site and documentation evidence predates that appearance, so it should not be described as a first launch. For someone switching between a local computer, remote host and container, the benefit is less repeated client setup. With only one device, the documentation says the central layer is usually unnecessary.

Pairing a device and authorizing a client are separate steps

Setup begins with a one-time pairing code generated in the console, then entered through the desktop interface or a command-line pairing action. Linux hosts and servers have their own documented path. Paired devices connect outward, without requiring a public inbound port for every machine, and pairing preserves their existing local MCP endpoints and authentication. Authorizing the AI client is a separate step: OAuth-capable clients complete browser authorization, while fixed-token clients use a dedicated MCP access token. That token is distinct from the console administrator password. One entry point reduces address management, but makes target selection and access control more consequential. A successful connection still needs to reach the intended machine.

Separate remembered knowledge, reusable procedures and progress

Recall is intended for project decisions, preferences and confirmed lessons that are useful in later work. An embedding provider can add semantic retrieval. Workflow stores reusable procedures, such as checks before a release, but the documentation explicitly describes an adaptable process template rather than an automatically executing script. A current task separately records its goal, completion conditions, progress and verification evidence. That state belongs to the AgentDock instance handling it; connecting NexusDock does not automatically transfer an interrupted task to another computer. The distinction is easy to miss behind shared-memory language: remembering an earlier decision is different from preserving a running process, its files and outstanding actions on a new host.

The convenient entry point still has operating costs

The maker and website describe a free entry tier for one device, with additional devices and higher memory or workflow limits handled by other plans. That does not establish free use of every connected model. The device runtime is Apache2.0 open source, and self-hosting documentation covers Docker, persistent volumes and HTTPS access. Basic device management, keyword search and workflow operations do not require an extra model provider; semantic retrieval needs an embedding configuration. The original discussion shows two reply positions without readable long-term usage evidence. A maker screenshot illustrates an assistant listing several devices, but cannot validate the reader’s own network, authenticated browser sessions or reliability across machines.
