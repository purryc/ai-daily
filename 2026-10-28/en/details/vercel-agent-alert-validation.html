Investigation enters the delivery path

When an error spike appears, an on-call engineer first asks whether it comes from health checks, persists over time or affects a real customer action. Vercel places that initial investigation before a selected notification destination. Agent examines logs and metrics and forwards only the incidents it considers Critical. Monitor-specific context can help it interpret the business impact. The appeal is fewer interruptions that end with no action, but the design also puts a classification step inside the delivery path. An incorrect decision could delay or suppress an important page. The vendor’s examples explain intended behavior; they are not a measured incident dataset demonstrating how often the classification is right.

A choice attached to the destination

The administrator opens a monitor’s notification settings, links the paging webhook and chooses Critical Only for that destination. A CLI flag provides the same configuration path. Critical is defined through Agent’s impact assessment, rather than simply being another numeric threshold above High. The documentation also describes testing delivery after connecting incident.io and then configuring its routing. That separation is useful: a team can inspect which endpoint receives which monitor, rather than relying on a vague account-wide automation switch. The existing incident system still owns the response workflow. This feature does not by itself roll back a deployment, repair the service or decide that an incident has been resolved.

Lower session consumption, unchanged rates

A separate October 27 update changes how the same product carries context through conversations, including long Slack threads. Incremental handling, reusable prompt context and revised workflow guidance are intended to consume fewer tokens. Vercel reports a 67% average reduction for dashboard and Slack sessions, with no action required. The rates themselves have not changed: paid sessions combine provider inference charges with an Agent fee of $0.25 per million tokens. This is a consumption claim rather than a universal discount on every investigation. A long conversation may benefit from less repeated context, but the announcement provides no task-by-task distribution from which to predict an individual team’s monthly bill.

Delivery delay belongs in the cost calculation

Validation requires an eligible paid plan with Observability Plus, which includes ten Agent investigations per billing cycle. Extra investigations and scanned data for custom monitors create distinct costs. The documented custom-monitor scan rate is $0.0035 per GB. More consequentially, the documentation warns that classification can delay notification compared with the original severity setting. A team evaluating this feature needs the filtered incidents and delivery times, not only the count of pages avoided. A rare but consequential failure can outweigh several harmless interruptions. Keeping a direct view of the alert record helps an operator investigate that tradeoff; no independent measurement of missed incidents or end-to-end delay was established here.
