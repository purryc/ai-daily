Giving “that button” a concrete target

When fixing a page with a coding agent, the developer can already see the problem but must translate its location into a prompt: which card, at which width, and in which component. PulseDev lets the person activate Inspect, click an element, Shift-click several targets or drag a region, then describe the change beside the page. The context includes selectors, markup, styles and page information. A Vite plugin adds source mapping where supported; a script tag supplies the annotation surface more broadly. Better targeting reduces explanation, but it does not guarantee a unique source component in every framework. Repeated components and responsive styles still require reviewing the scope of the proposed edit.

The increment is setup and diagnostic context

The substantive change is version 0.8.4 on October 26. The desktop application now contains the local server, with each project started and stopped from its sidebar instead of a separate terminal process. Tasks also carry a selected-element screenshot, recent console errors and failed network requests, helping distinguish a styling complaint from failed data loading. Codex, Gemini and OpenCode can request permission through the widget before file edits or commands. Version 0.8.5 the following day adds offline release notes to Settings. The October 27 Product Hunt appearance is a discovery event, not evidence that all these capabilities first shipped that day. The official changelog supplies dates without a timezone.

Review beside the page still means reviewing code

The application launches an already installed and authenticated Claude Code, Codex, Gemini CLI or OpenCode. A task board separates queued, running, review and completed work, while logs show reads, edits and commands. A person can stop a run, add instructions and inspect the diff. The vendor describes review mode as approval before writing and rejection as rollback, with optional auto-apply. Its demonstration also uses live-editing language, so the exact boundary between staging and real file writes deserves verification before relying on a no-side-effects claim. Projects have separate local server ports, and an editor can read or close annotations through MCP. Design feedback and acceptance of the resulting code remain distinct decisions.

Local routing and model service are separate

The free tier supports one project; additional projects require Pro, separately from the selected agent's usage limits and provider charges. The application requires macOS 13 or newer, and the maker corrected obsolete download copy to state that current builds are signed and notarized. Its privacy policy says PulseDev itself does not receive source code or prompts, but the coding agent may send prompts and files to its own provider. Annotations, screenshots and project records remain in a local folder that uninstalling does not erase. Servers accept local connections by default; phone testing requires enabling network access. This is a development-machine review aid, not a guarantee that project data never leaves the device.
