Showing what this computer can actually load

Pumpkin adds a setup and management interface around llama.cpp. On first use it identifies the GPU, video memory and RAM, asks where files should live, and offers chat, coding, research or agent-oriented starting choices. Model files are labeled according to whether they fit the GPU, need RAM offloading, run slowly on the CPU or are too large. Existing downloads from tools such as LM Studio and Ollama can be reused in place. Clicking Install produces a model, preset and chat entry point. This removes several choices about backends, quantization files and launch flags. Fitting into memory still does not establish that a model can reliably perform a particular tool-based task.

Keeping a route back after an engine update

The new Model server control in 0.9.0 brings dependency maintenance into the application. Users can turn updates off, request notifications or allow automatic updates, choosing a release that is at least a day old or the newest build. On first execution, Pumpkin checks whether the engine still responds as its chat interface expects. If that check fails, it restores the previous build and skips the incompatible one. User-supplied engines are not replaced, and a manual rollback remains available. An unsupported build on an older system can pause newer-build attempts for thirty days. This is a compatibility check between the application and engine, not certification of model accuracy, every tool or long-running reliability.

Changing a model also changes its supporting files

A vision model may need a matching mmproj projector in addition to its weights. The new preset interface shows folders, warns about mismatches and switches the projector when the selected model changes. This addresses a familiar failure in which all the files appear downloaded but images still cannot be processed. Speculative decoding also becomes a prominent preset toggle; the Reports speed test compares enabled and disabled runs on the user's machine. It should not be assumed to accelerate every model. The adjacent 0.8.8 release fixes image-engine selection on older Macs by trying builds compatible with their operating system. These are changes to software compatibility and configuration, with no new sensor involved.

Local chat and external actions have different boundaries

Pumpkin also offers document retrieval, phone access and a coding agent, but these existing features should not all be counted as additions in 0.9.0. Project editing asks before file changes or commands by default. Documentation says external MCP servers run as the user, outside the Docker isolation used for ordinary sandboxed command tools. Phones can reach the computer through a home network or Tailscale; home-network traffic is unencrypted. Network exposure therefore depends on enabled features rather than the local-model label alone. Platform support still carries beta and hardware-testing limitations. The application suits people willing to enable capabilities selectively and retain a recovery route: easier installation does not remove hardware differences or responsibility for connected services.
